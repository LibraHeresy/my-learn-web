# 学习页面步骤"目的"与"预期结果"说明 — 需求评估与方案设计

## 需求来源

用户反馈：在学习页面中，课程和项目的步骤指引过于简单（"动手试试"只有操作指令），用户不知道：
1. **这一步有什么作用**（为什么要做这个？）
2. **完成后应该看到什么结果**（我做得对不对？）

特别地，课程中的"动手试试"（`type: "task"`）章节通常包含 **3-9 个子步骤**（如"1. 修改标题、2. 替换图片、3. 添加列表"），每个子步骤也缺乏说明。

---

## 评估：是否需要做

**结论：需要做。**

当前教学流程的信息结构是：
- `explain` → 概念讲解（是什么）
- `example` → 示例演示（长什么样）
- `task` → 操作指令（做什么）

缺失的环节：
- **为什么做**（purpose）→ 用户不理解操作背后的教学意图
- **做成什么样**（expectedResult）→ 用户无法自我验证是否做对了

这就像教人弹扬琴只告诉"按这个弦、敲那个键"，但不说是为了弹什么曲子、好听的声音应该是什么样。**这是一个真实的教学体验缺陷。**

---

## 评估：是否值得做

**结论：值得做。**

| 维度 | 分析 |
|---|---|
| **教育价值** | 高。填补"知道做什么"和"理解为什么做"之间的鸿沟，是脚手架式教学的核心改进 |
| **实现成本** | 适中。约 4 个文件改动（类型定义 + 2 个 UI 组件 + 数据示例），无架构级变更 |
| **向后兼容** | 完全兼容。所有新增字段为可选，已有课程无需修改即可正常运行 |
| **可增量推进** | 高。先为核心课程添加数据，后续逐步补全，不阻塞上线 |
| **用户感知** | 强。子步骤卡片 + 颜色区分的信息框，视觉上显著改善任务区的信息密度 |

## 现有架构分析

### 课程（Lesson）结构

```
Lesson
├── sections: LessonSection[]
│   ├── type: 'explain' | 'task' | 'hint' | 'example'
│   ├── title?: string
│   └── content: string          ← 目前唯一的内容载体
└── starterCode: {html, css, js}  ← 整个课程共用一份
```

- `sections` 在一个页面内**全部展开**，用户滚动阅读
- `task` 章节的 `content` 中通常用 `1. 2. 3.` 编号列表组织多个子步骤
- 子步骤格式不统一：有的用编号、有的用粗体标题、有的用纯段落

### 项目（Project）结构

```
Project
└── steps: ProjectStep[]
    ├── title: string
    ├── content: string   ← 概念讲解
    ├── task: string       ← 操作指令（始终展示在"你的任务"框中）
    ├── hint?: string      ← 可选提示（可折叠）
    └── starterCode?       ← 每个步骤可独立设置
```

- 一次展示一个步骤，通过 prev/next 按钮和步骤圆点导航
- 已有"你的任务"高亮框，但缺乏目的和预期结果说明

### 两种模式的问题差异

| | 课程（Lesson） | 项目（Project） |
|---|---|---|
| **问题严重程度** | 高。任务章节有多个子步骤，且一次性全部展示，用户容易迷失 | 中。已有步骤导航和任务框，但缺乏目的和结果说明 |
| **改造重点** | 需要子步骤级别的数据结构 + UI | 步骤级别新增字段即可 |
| **数据迁移量** | 大（~80 节课的 task 章节） | 小（5 个项目，每个 4-7 步） |

## 方案设计

### 核心思路

让每个**子步骤**都有自己的"目的"和"预期结果"。

### 类型定义

```typescript
// 新增：课程子步骤
export interface LessonSubStep {
  content: string          // 这一步做什么（markdown）
  purpose?: string         // 这一步的目的
  expectedResult?: string  // 完成后应该看到的效果
}

// 修改：课程章节
export interface LessonSection {
  type: 'explain' | 'task' | 'hint' | 'example'
  title?: string
  content: string
  subSteps?: LessonSubStep[]  // 新增
}

// 修改：项目步骤
export interface ProjectStep {
  title: string
  content: string
  task: string
  hint?: string
  starterCode?: { html: string; css: string; js: string }
  purpose?: string         // 新增
  expectedResult?: string  // 新增
}
```

```
└─────────────────────────────────────────────┘
```

### 配色方案

| 信息类型 | 底色 | 左边框 | 语义 |
|---|---|---|---|
| 你的任务（已有） | 暖金色 | `--color-gold` | 行动 |
| **这一步的目的** | `#F4F8FC` 淡蓝灰 | `#8BA4B8` 钢蓝 | 思考/意图 |
| **完成后你应该看到** | `#F4F8F0` 淡鼠尾草绿 | `#8BA87D` 鼠尾草绿 | 成功/结果 |
| 提示（已有） | 淡紫 | `--color-primary-light` | 辅助 |

三者视觉区分明确，不会与现有的 task/hint/example 样式混淆。

### 改动文件清单

| 文件 | 改动内容 | 改动量 |
|---|---|---|
| `src/types/index.ts` | 新增 `LessonSubStep`，`LessonSection` 和 `ProjectStep` 各加字段 | ~10 行 |
| `src/components/LessonContent.vue` | 子步骤卡片列表渲染 + CSS | ~60 行 |
| `src/views/ProjectPlayer.vue` | purpose/expectedResult 卡片 + CSS | ~40 行 |
| `src/configs/lessons.ts` | 示例课程数据充实（首批 3-5 节） | ~150 行 |
| `src/configs/projects.ts` | 示例项目数据充实（首批 1 个） | ~20 行 |

### 渲染逻辑（LessonContent.vue 关键判断）

```
if section.subSteps 存在:
  → 渲染 section.content 作为总览说明
  → 遍历 subSteps，每个渲染为一张卡片（编号 + 内容 + 可选目的 + 可选结果）
else:
  → 保持原有 section-content 渲染方式（向后兼容）
```

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 卡片太多导致页面过长 | 子步骤卡片设计紧凑，purpose/expectedResult 用小字号，建议 2-3 句话 |
| 数据迁移工作量大（~80 节课） | 可增量推进，不阻塞上线；旧课程保持原有体验 |
| 子步骤内容与 section.content 重复 | 有 subSteps 时，section.content 仅作为简短总览（1-2 句），详细指引在 subSteps 中 |
| 与现有 hint 系统语义重叠 | hint = "怎么做"（可折叠，低可见性），purpose = "为什么做"，expectedResult = "做成什么样"，三者角色明确分离 |
