## 一、高优先级：学习断点（直接影响"看懂/学会"）

### 1. 沙箱无控制台输出——JS 课程"盲写"（最痛点）
`workflow-console-intro`、`workflow-console-log` 等 sandbox 课程以 `console.log` 为核心教学，但 `LivePreview` 只捕获运行错误（`code-error` 消息），iframe 内的 console 输出学员完全看不到——教"看输出"的课看不到输出。

**方案**：在 errorGuard 脚本中 hook `console.log/warn/error`，通过 postMessage 桥接回主应用，在预览面板增加"控制台"选项卡。工作量小（复用现有 error 桥基建），收益极大。

### 2. 任务目标无自动验收
task 步骤的 `expected` 是文字描述（"预览区标题会变成你写的文字"），学员自行比对。缺乏"做对了"的即时确认，容易半途放弃或误判完成。

**方案**：为 sandbox 课程逐步引入**任务自动检查**——构建期在预览脚本注入轻量断言（检查元素存在、文本变化、样式值、console 输出），达成后显示 ✓ 并提示下一步。建议分两档起步：① 元素存在/文本匹配（覆盖 HTML/CSS 大部分课程）；② 输出值/行为检查（覆盖 JS 课程）。可在 `meta.yaml` 按步骤声明断言，保持内容与代码分离。

### 3. 课程与测验零联动
18 个 gem（766 题）与 112 门课之间没有任何显式映射。学员不知道"学完这章该做哪套题"，测验页也不知道"这套题对应哪些课"。

**方案**（任选或组合）：
- recap 块后追加"去测验：<gem 名称>"引导（构建期按 chapter→gem 映射自动生成）
- 测验页 gem 卡片显示"关联课程"列表
- 课程"标记完成"时提示"建议完成 XX 测验巩固"

## 二、中优先级：理解效率（降低认知成本）

### 4. 核心概念缺可视化
全部内容为文字+代码。**盒模型、flex 主轴/交叉轴、grid 网格线、事件循环时序、Promise 链、调用栈**等空间/时序概念，一张 SVG 示意图的传达效率远超十段文字，尤其对零基础学员。

**方案**：为 10-15 个核心概念课（css-box-model、css-flexbox、css-grid、css-position、async-event-loop、async-promise、js-functions 作用域等）配轻量内联 SVG 示意图（无外部图片资源，构建零成本）。

### 5. 内容密度极不均衡
平均 6551 字，但 `js-conditions` 达 20416 字（3 倍+）。超长课容易造成认知过载与中途放弃（课程完成数据可验证）。

**方案**：
- `js-conditions` 拆分为"条件判断基础"+"逻辑运算与嵌套分支"两课（约 10k/10k 字）
- 其他 >12k 字的课（css-layout-capstone、css-position、css-responsive、js-es6-syntax）在开头加"本节地图"（学什么、多少步、约多久）

### 6. 前置知识无自测与跳过
`prerequisite` 块静态列出"你需要知道这些词"，已会者无法跳过，不会者无法自测。

**方案**：prerequisite 中的术语直接复用术语注入（点击看 tooltip）；块首加"我已会，收起"折叠；进阶课可加"3 题前置自测"链接。

### 7. 缺少"预测输出"型即时小测
所有 task 都是"改代码看效果"型，缺少训练**心智模型**的"先猜输出再验证"练习——这是程序员最核心的阅读代码能力。

**方案**：在事件循环、异步、作用域、闭包等课程正文嵌入 1-2 个"预测输出"折叠块（`:::predict` 新 block：给代码，学员先想，点开看答案与解析）。构建管线已有 block 注册机制，扩展成本低。

## 四、结构性建议（后续大迭代）

1. **章节小结页**：每章末尾加"本章小结 + 测验入口 + 下一步"聚合页（当前章节是纯课程列表）
2. **学习数据反馈**：完成度/正确率趋势可视化，基于错题池给出"建议复习"清单
3. **local 课程引导**：53 门 local 模式课程无内置练习，可提供更明确的"开始清单"（要装什么、做完什么算完成）
4. **移动端学习模式**：代码编辑在手机体验差，可提供"阅读模式 + 代码高亮无编辑"的降级体验
