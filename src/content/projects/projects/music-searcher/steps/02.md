# 步骤 2：理解 API —— 你的数据从哪来

## 本步骤目标

理解 iTunes Search API 的工作方式——它接受什么参数、返回什么数据、你如何拿到这些数据。**在写任何代码之前，先用浏览器测试 API。**

## 为什么这一步很重要

在真实工作中，你拿到一个第三方 API 后，第一件事不是写代码，而是**读懂它的文档、在浏览器里试几次、搞清楚返回数据的结构**。如果跳过这一步直接写代码，你会反复遇到"为什么取不到这个字段""为什么报错"的问题，而且每次都要回去查——效率极低。10 分钟的 API 调研，能省下 2 小时的调试时间。

## iTunes Search API 介绍

Apple 提供了一个完全免费、无需注册、无需 API Key 的搜索接口。它原本是为 iTunes Store 设计的，但返回的数据对音乐搜索场景完全够用。

### 基础 URL

```
https://itunes.apple.com/search
```

### 核心参数

| 参数 | 含义 | 示例值 | 是否必须 |
|------|------|--------|----------|
| `term` | 搜索关键词（支持中文、英文、日文等） | `贝多芬`、`mozart` | 是 |
| `limit` | 返回结果的最大数量（默认 50，最大 200） | `10`、`50` | 否 |
| `country` | 国家/地区代码，影响搜索结果的语言和地区偏好 | `cn`（中国）、`us`（美国）、`jp`（日本） | 否 |
| `media` | 媒体类型 | `music`、`podcast`、`movie` | 否 |
| `entity` | 实体类型（更细的分类） | `song`、`album`、`musicArtist` | 否 |

## 动手实验：在浏览器中测试 API

**打开你的浏览器，复制下面的 URL 到地址栏，按回车：**

```
https://itunes.apple.com/search?term=贝多芬&limit=5&country=cn
```

你会看到一大段 JSON 文本。这就是 API 返回的原始数据。如果你看到的是乱码或者空白页，检查一下 URL 是否完全正确。

### 你看到的 JSON 结构（简化版）

```json
{
  "resultCount": 5,
  "results": [
    {
      "wrapperType": "track",
      "kind": "song",
      "trackId": 123456789,
      "artistName": "Ludwig van Beethoven",
      "trackName": "Symphony No. 5 in C Minor",
      "collectionName": "Beethoven: The Complete Symphonies",
      "artworkUrl60": "https://is1-ssl.mzstatic.com/image/thumb/...jpg/60x60bb.jpg",
      "artworkUrl100": "https://is1-ssl.mzstatic.com/image/thumb/...jpg/100x100bb.jpg",
      "previewUrl": "https://audio-ssl.itunes.apple.com/...m4a",
      "primaryGenreName": "Classical",
      "trackTimeMillis": 420000,
      "country": "CHN",
      "releaseDate": "2000-01-01T08:00:00Z"
    }
  ]
}
```

### 逐个理解关键字段

**外层结构：**

```
resultCount: 5    --> 本次搜索返回了多少条结果
results: [...]    --> 结果数组，每个元素是一首歌（或一个专辑、一位艺术家）
```

**内层结构（results 数组中的每个元素）——我们项目中会用到的字段：**

| 字段 | 含义 | 示例 | 我们在界面上怎么用 |
|------|------|------|-------------------|
| `trackName` | 歌曲名 | "月光奏鸣曲" | 显示为歌曲标题 |
| `artistName` | 艺术家/歌手名 | "Beethoven" | 显示为歌手名 |
| `artworkUrl100` | 100x100 封面图 URL | `https://...jpg` | 显示为歌曲封面 `<img>` |
| `previewUrl` | 30 秒试听音频 URL | `https://...m4a` | 可选：让用户点击试听 |
| `collectionName` | 专辑名 | "Beethoven: Complete..." | 显示为专辑名 |
| `primaryGenreName` | 音乐类型 | "Classical" | 显示为分类标签 |

## 自己动手实验（在写代码之前）

在浏览器地址栏依次测试以下 URL，观察返回数据的变化：

**实验 1：修改搜索词**
```
https://itunes.apple.com/search?term=mozart&limit=5&country=cn
```
观察：`results` 数组里的 `artistName` 和 `trackName` 有什么变化？

**实验 2：修改返回数量**
```
https://itunes.apple.com/search?term=周杰伦&limit=20&country=cn
```
观察：`resultCount` 变成了多少？`results` 数组有几个元素？

**实验 3：修改国家代码**
```
https://itunes.apple.com/search?term=beethoven&limit=5&country=us
https://itunes.apple.com/search?term=beethoven&limit=5&country=jp
```
观察：两个 URL 返回的结果有什么不同？`artistName` 的语言变化了吗？

**实验 4：搜索不存在的词**
```
https://itunes.apple.com/search?term=xysdfjkshdfkj&limit=5&country=cn
```
观察：`resultCount` 是多少？`results` 数组是空数组 `[]` 还是 `null`？

**实验 5：在浏览器控制台用 fetch 测试**

打开任意网页的开发者工具（F12），在 Console 标签中输入：

```js
// 在浏览器控制台直接运行这段代码
fetch('https://itunes.apple.com/search?term=周杰伦&limit=3&country=cn')
  .then(response => response.json())  // 把响应体解析为 JSON 对象
  .then(data => {
    console.log('总共', data.resultCount, '条结果')  // 打印结果数量
    console.log('第一首歌:', data.results[0].trackName)  // 打印第一首歌名
    console.log('歌手:', data.results[0].artistName)  // 打印第一首歌手
    console.log('封面:', data.results[0].artworkUrl100)  // 打印第一首封面 URL
  })
  .catch(error => console.error('请求失败:', error))  // 捕获网络错误
```

运行这段代码后，你应该能在控制台看到具体的数据。这就是你接下来要在项目里做的事情——只不过不是打印到控制台，而是渲染到页面上。

## 你需要带走的关键理解

1. **API 就是一个 URL** —— 你在地址栏输入一个特定格式的 URL，它返回 JSON 数据，而不是网页。
2. **查询参数控制结果** —— `term` 决定搜什么，`limit` 决定返回多少条，`country` 决定地区偏好。修改这些参数就能拿到不同的数据。
3. **返回结构是固定的** —— 永远是 `{ resultCount: n, results: [...] }` 这个形状。你可以放心地用 `data.results[0].trackName` 取数据。
4. **`results` 空数组不等于 `null`** —— 搜不到东西时，`results` 是 `[]`（空数组），而不是 `null` 或 `undefined`。这一点在第 5 步处理"无结果"状态时会用到。

## 常见错误和解决方法

| 错误现象 | 可能原因 | 解决方法 |
|----------|---------|----------|
| 浏览器显示空白页或 JSON 报错 | URL 拼写错误，或者 `?` 和 `&` 的位置不对 | 直接复制上面的 URL，逐个字符对比 |
| 中文关键词在 URL 中变成乱码 | URL 需要编码，中文不能直接放 URL 中 | 在 JS 代码中用 `encodeURIComponent()` 编码；在浏览器地址栏直接输入中文有时也能工作（浏览器会自动编码），但 JS 代码中必须手动编码 |
| 返回的数据中有些歌没有封面图 | `artworkUrl100` 可能为空字符串 `""` | 在渲染时检查：`if (track.artworkUrl100) { ... } else { 显示占位图 }` |
| `fetch` 报跨域错误（CORS） | iTunes API 是支持 CORS 的，不应该出现跨域问题 | 检查是否在 file:// 协议下打开（应该用本地服务器，如 Live Server） |
| 请求成功但返回空结果 | 搜索词在 iTunes 库中没有匹配 | 换一个更常见的关键词试试，比如 "love"、"周杰伦"、"Beethoven" |

## 本步骤完成标准

- 在浏览器地址栏成功访问 iTunes Search API 并看到 JSON 数据
- 修改 `term`、`limit`、`country` 参数，观察返回数据的变化
- 在浏览器控制台用 `fetch` 成功获取并打印数据

- 知道搜索不存在的词时，`results` 是空数组 `[]`，不是 `null`
