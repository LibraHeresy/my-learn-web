# 步骤 3：基础搜索 —— 从输入框到结果展示的通路

## 本步骤目标

搭建从"用户输入关键词 + 点击按钮"到"调用 API 获取数据并渲染到页面"的完整通路。**这是整个项目最核心的骨架。**

## 为什么这一步很重要

任何一个功能都可以拆成三步：**接收输入 -> 处理数据 -> 输出结果**。这一步覆盖了全部三步。在真实工作中，你拿到一个新功能需求时，也应该先用最朴素的方式（比如按钮点击触发）把整条链路跑通，再逐步加优化（防抖、状态管理、错误处理）。先跑通，再跑好。

### 第 2 步：写 JS 核心逻辑

创建 `app.js`（放在 `index.html` 同级目录）：

```js
// ============================================================
// 第 3 步：基础搜索 —— 核心 JS 逻辑
// ============================================================

// --- 1. 获取 DOM 元素 ---
// 把这些常用的 DOM 元素缓存到变量里，避免每次都 document.getElementById
const searchInput = document.getElementById('searchInput')  // 输入框
const searchBtn = document.getElementById('searchBtn')        // 搜索按钮
const resultsDiv = document.getElementById('results')         // 结果容器

// --- 2. 封装 API 请求函数 ---
// 这个函数负责：接收关键词 -> 构建 URL -> 发送请求 -> 返回数据
// 它是"数据获取层"，和页面渲染逻辑完全分离
async function searchMusic(term) {
  // 2a. 构建请求 URL
  // encodeURIComponent 把中文编码成 %E8%B4%9D... 格式，否则 URL 无效
  const url = `https://itunes.apple.com/search?term=${encodeURIComponent(term)}&limit=20&country=cn`

  // 2b. 发送请求
  // fetch 返回一个 Response 对象，它的 body 还在网络传输中
  const response = await fetch(url)

  // 2c. 检查 HTTP 状态
  // response.ok 为 true 表示状态码在 200-299 之间
  // 如果 !ok，抛出错误让调用方 catch 处理
  if (!response.ok) {
    throw new Error(`搜索失败：HTTP ${response.status}`)
  }

  // 2d. 解析 JSON
  // response.json() 返回一个 Promise，需要 await
  const data = await response.json()

  // 2e. 只返回 results 数组，这是调用方真正需要的数据
  return data.results  // 可能是空数组 []（如果没搜到结果）
}

// --- 3. 渲染函数：把数据变成页面上的 HTML ---
// 这个函数只负责"把数据画到页面上"
function renderResults(results) {
  // 3a. 先清空旧内容
  resultsDiv.innerHTML = ''

  // 3b. 遍历每一条结果，拼成 HTML 字符串
  // map() 遍历数组，返回一个新数组，用 join('') 合并成字符串
  const html = results.map(track => {
    // track 是 API 返回的每首歌的数据对象
    return `
      <div class="result-item">
        <img
          src="${track.artworkUrl100}"
          alt="${track.trackName} 封面"
        />
        <div class="info">
          <div class="track-name">${track.trackName}</div>
          <div class="artist-name">${track.artistName}</div>
        </div>
      </div>
    `
  }).join('')  // join('') 把数组元素合并成一个字符串，不加分隔符

  // 3c. 一次性插入 DOM（比逐条 appendChild 性能更好）
  resultsDiv.innerHTML = html
}

// --- 4. 搜索处理函数（按钮点击时调用）---
async function handleSearch() {
  // 4a. 获取用户输入的值，去掉首尾空格
  const keyword = searchInput.value.trim()

  // 4b. 如果输入为空，直接返回，不发请求
  if (!keyword) {
    resultsDiv.innerHTML = '<p style="color:#999; text-align:center;">请输入关键词后再搜索</p>'
    return  // 提前退出，不继续往下执行
  }

  // 4c. 显示"搜索中"提示
  resultsDiv.innerHTML = '<p style="text-align:center; color:#999;">搜索中...</p>'

  try {
    // 4d. 调用 API 搜索函数
    const results = await searchMusic(keyword)

    // 4e. API 返回后，渲染结果
    renderResults(results)
  } catch (error) {
    // 4f. 如果请求失败（网络中断、API 挂了等），显示错误信息
    console.error('搜索出错:', error)  // 控制台输出详细信息，方便调试
    resultsDiv.innerHTML = '<p style="text-align:center; color:red;">搜索失败，请检查网络后重试</p>'
  }
}

// --- 5. 绑定事件 ---
// 方式一：点击按钮触发搜索
searchBtn.addEventListener('click', handleSearch)

// 方式二：按回车键也能触发搜索（提升用户体验）
searchInput.addEventListener('keydown', (e) => {
  if (e.key === 'Enter') {  // e.key 是按键名称
    handleSearch()
  }
})
```

## 代码执行流程回顾

```
用户输入"贝多芬" --> 点击[搜索]
  --> handleSearch() 被调用
    --> 检查关键词是否为空（不为空，继续）
    --> 显示"搜索中..."
    --> 调用 searchMusic("贝多芬")
      --> 构建 URL: https://itunes.apple.com/search?term=%E8%B4%9D%E5%A4%9A%E8%8A%AC&limit=20&country=cn
      --> await fetch(url)  -- 等待网络响应
      --> 检查 response.ok 是否为 true
      --> await response.json()  -- 等待 JSON 解析完成
      --> 返回 data.results（20 首歌的数组）
    --> renderResults(results)
      --> results.map() 把每首歌变成一段 HTML
      --> resultsDiv.innerHTML = 合并后的 HTML 字符串
```

## 常见错误及解决方法

### 错误 1：点击搜索没反应，控制台报 `Uncaught ReferenceError: searchInput is not defined`

**原因**：`<script src="app.js">` 写在了 `<head>` 中，或者放在了 `<body>` 顶部，此时 DOM 还没加载完。

**解决**：确保 `<script src="app.js">` 写在 `<body>` 标签的最底部（`</body>` 之前）。

### 错误 2：点击搜索后显示"搜索失败，请检查网络"

**原因**：可能是用 `file://` 协议打开的 HTML 文件，fetch 跨域被限制；也可能是网络真的断了。

**解决**：
- 使用 VS Code 的 Live Server 插件（右键 HTML -> Open with Live Server）
- 或者用 `npx serve .` 启动本地静态服务器
- 打开浏览器开发者工具（F12）-> Network 标签，查看请求的具体状态码

### 错误 3：结果渲染出来了，但封面图不显示

**原因**：有些歌曲的 `artworkUrl100` 是空字符串 `""`。

**解决**：在渲染时增加判断——如果 `artworkUrl100` 为空，用一个默认占位图：
```js
src="${track.artworkUrl100 || 'https://via.placeholder.com/60'}"
```

### 错误 4：输入中文搜索后 URL 变成乱码

**原因**：忘记用 `encodeURIComponent()` 编码中文关键词。

**解决**：检查 `searchMusic` 函数中 URL 构建部分，确保是：
```js
`.../search?term=${encodeURIComponent(term)}&limit=...`
```
而不是：
```js
`.../search?term=${term}&limit=...`  // 错误！中文没有编码
```

### 错误 5：搜索了"贝多芬"，再搜"莫扎特"，结果显示的还是贝多芬的数据

**原因**：`searchMusic` 函数没有加 `await`，或者 `renderResults` 被调用了两次（旧请求还没回来，新请求先回来了，但旧请求后回来覆盖了新结果——这是"竞态条件"问题）。

**解决**：第 5 步会专门解决这个问题。目前先确保搜索不同关键词时，每次都等上一次搜索完成再搜下一个。

### 错误 6：用 `for` 循环逐条 `appendChild`，页面卡顿

**原因**：频繁操作 DOM 性能差。

**解决**：本示例已经用了最优做法——先用 `map().join()` 拼成完整 HTML 字符串，再一次性 `innerHTML`。你的代码也应该这样做。
