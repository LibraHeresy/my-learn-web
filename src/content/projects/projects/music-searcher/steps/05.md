# 步骤 5：完整状态管理 —— 覆盖用户遇到的每一种情况

## 本步骤目标

为搜索功能添加五种状态的完整 UI 反馈（空闲 / 加载中 / 成功 / 空结果 / 错误），并解决**竞态条件**问题——旧请求不会覆盖新请求的结果。

## 为什么这一步很重要

这一步是"业余代码"和"专业代码"的分水岭。业余代码只考虑了"一切正常"的情况（Happy Path），一旦网络波动、API 抽风、用户搜了个不存在的词——页面就僵住了，用户困惑、烦躁、离开。专业代码会为每种可能的情况提供明确的 UI 反馈。在面试和工作中，"你是怎么处理边界的"是一个高频问题——这一步就是在训练这个思维。

## 五种状态定义

在动手写代码之前，先在大脑中建立清晰的模型：

```
            用户输入关键词
                  |
          +-------v--------+
          |   LOADING       |  正在请求 API，显示加载动画
          |   "搜索中..."    |
          +-------+---------+
                  |
        API 返回结果后
                  |
     +------------+-------------+
     |            |             |
     v            v             v
  SUCCESS       EMPTY          ERROR
 "展示结果"   "无匹配结果"   "网络错误/API故障"
 (results     (results        (fetch 抛出异常
  长度 > 0)    长度 === 0)     或 response 非 200)
                |
                v
         用户打开页面
                |
         +------v------+
         |   IDLE       |  还没开始搜索
         | "输入关键词"  |
         +--------------+
```

## 动手改造代码

### 第 1 步：定义状态常量

在 `app.js` 的顶部（DOM 元素获取之后）添加状态定义：

```js
// ============================================================
// 状态管理
// ============================================================

// 用对象定义五种状态常量，避免代码中到处写魔法字符串
// 好处：拼写错误会被 IDE 检查出来（写 Status.LOADING 不会拼错，写 "lodding" 会）
const Status = {
  IDLE: 'idle',           // 空闲（页面刚打开，还没搜）
  LOADING: 'loading',     // 加载中（请求已发送，等待响应）
  SUCCESS: 'success',     // 成功（拿到了结果且数量 > 0）
  EMPTY: 'empty',         // 空结果（请求成功但 results 是 []）
  ERROR: 'error'          // 出错（网络故障 / API 返回非 200）
}

// 当前状态变量，初始为 IDLE
let currentStatus = Status.IDLE
```

### 第 2 步：实现状态驱动的渲染函数

用 `switch` 根据当前状态决定渲染什么内容。这个函数替代了原来零散的 `resultsDiv.innerHTML = '...'` 写法：

```js
/**
 * 根据 currentStatus 渲染对应的 UI
 * "单一出口"原则：所有状态变化都走这个函数
 * 这样你永远不会忘记处理某个状态
 */
function renderByStatus(data = null) {
  // data 参数只在 SUCCESS 状态下有值（results 数组）
  // 其他状态下 data 为 null

  switch (currentStatus) {
    case Status.IDLE:
      // 空闲状态：引导用户开始操作
      resultsDiv.innerHTML = `
        <div style="text-align:center; padding:60px 20px; color:#aaa;">
          <div style="font-size:48px; margin-bottom:16px;">&#9835;</div>
          <p>输入关键词，开始搜索音乐</p>
        </div>
      `
      break

    case Status.LOADING:
      // 加载状态：告诉用户"正在工作中"
      resultsDiv.innerHTML = `
        <div style="text-align:center; padding:40px 20px; color:#999;">
          <div class="spinner"></div>
          <p>搜索中...</p>
        </div>
      `
      break

    case Status.SUCCESS:
      // 成功状态：渲染搜索结果列表
      resultsDiv.innerHTML = data.map(track => `
        <div class="result-item">
          <img
            src="${track.artworkUrl100 || ''}"
            alt="${track.trackName} 封面"
            onerror="this.src='data:image/svg+xml,...'"  /* 图片加载失败时显示占位图 */
          />
          <div class="info">
            <div class="track-name">${track.trackName}</div>
            <div class="artist-name">${track.artistName}</div>
          </div>
        </div>
      `).join('')
      break

    case Status.EMPTY:
      // 空结果状态：API 响应了，但没有匹配项
      resultsDiv.innerHTML = `
        <div style="text-align:center; padding:40px 20px; color:#999;">
          <p style="font-size:18px; margin-bottom:8px;">&#128533;</p>
          <p>没有找到相关音乐</p>
          <p style="font-size:14px; color:#bbb;">换个关键词试试？</p>
        </div>
      `
      break

    case Status.ERROR:
      // 错误状态：网络故障或 API 挂了
      resultsDiv.innerHTML = `
        <div style="text-align:center; padding:40px 20px; color:#e74c3c;">
          <p style="font-size:18px; margin-bottom:8px;">&#9888;</p>
          <p>搜索失败</p>
          <p style="font-size:14px;">请检查网络连接后重试</p>
          <button
            onclick="retrySearch()"
            style="margin-top:12px; padding:8px 20px; background:#e74c3c; color:white; border:none; border-radius:4px; cursor:pointer;"
          >
            重试
          </button>
        </div>
      `
      break

    default:
      // 防御性编程：万一出现未知状态，也不至于页面空白
      console.warn('未知状态:', currentStatus)
      resultsDiv.innerHTML = '<p style="text-align:center;">未知状态，请刷新页面</p>'
  }
}
```

### 第 4 步：改造搜索函数，驱动状态切换

```js
// ============================================================
// 改造后的搜索函数——通过状态驱动 UI
// ============================================================

// 新增：请求计数器，用于解决竞态条件
let requestId = 0

async function doSearch(term) {
  // 0. 处理空输入 -> 回到 IDLE 状态
  if (!term.trim()) {
    currentStatus = Status.IDLE     // 切换状态
    renderByStatus()                // 根据新状态渲染 UI
    return
  }

  // 1. 进入 LOADING 状态
  currentStatus = Status.LOADING
  renderByStatus()

  // 2. 记录当前请求的"版本号"
  // 每次调用 doSearch 时 requestId 自增，这个闭包变量保存当前请求是第几个
  const currentRequestId = ++requestId

  try {
    // 3. 发送请求
    const results = await searchMusic(term)

    // 4. ★★★ 竞态条件检查：★★★
    // 如果在这段 await 期间，用户又输入了新的关键词，
    // 那么 requestId 已经自增了，currentRequestId !== requestId。
    //
    // 举例：
    //   用户输入"贝" -> requestId 变成 1，currentRequestId = 1，发请求
    //   用户输入"贝多芬" -> requestId 变成 2，currentRequestId = 2，又发请求
    //   请求 2 先回来（"贝多芬" 的结果），渲染。
    //   请求 1 后回来（"贝"的结果），此时 currentRequestId(1) !== requestId(2)，
    //   所以跳过渲染——旧数据不会覆盖新数据！
    if (currentRequestId !== requestId) {
      console.log(`请求 #${currentRequestId} 被丢弃，当前请求是 #${requestId}`)
      return  // 旧请求，直接丢弃
    }

    // 5. 根据结果数量决定状态
    if (results.length > 0) {
      currentStatus = Status.SUCCESS  // 有结果
      renderByStatus(results)         // 传入数据用于渲染
    } else {
      currentStatus = Status.EMPTY    // 无结果
      renderByStatus()
    }
  } catch (error) {
    // 6. 错误处理也需要检查竞态条件
    if (currentRequestId !== requestId) {
      return  // 旧请求的错误也不应该展示
    }

    console.error('搜索出错:', error)
    currentStatus = Status.ERROR
    renderByStatus()
  }
}
```

### 第 5 步：错误状态下支持重试

```js
// 保存最近一次搜索的关键词，用于"重试"按钮
let lastKeyword = ''

// 修改 doSearch，开头保存关键词
async function doSearch(term) {
  lastKeyword = term  // 记录最后搜索的关键词
  // ... 其余代码不变 ...
}

// 重试函数：被 error 状态下的"重试"按钮调用
// 注意：必须挂到 window 上，因为 onclick 属性在全局作用域查找函数
window.retrySearch = function () {
  if (lastKeyword) {
    doSearch(lastKeyword)  // 用上次的关键词重新搜索
  }
}
```

### 第 6 步：初始化页面为 IDLE 状态

在 `app.js` 最底部添加初始化调用：

```js
// ============================================================
currentStatus = Status.IDLE
renderByStatus()
```

## 竞态条件详解（面试高频问题）

**什么是竞态条件（Race Condition）？**

在异步编程中，如果你连续发了两个请求，你不知道哪个先回来。如果旧请求后回来，就会覆盖新请求的数据——用户搜的是"周杰伦"，看到的却是"贝多芬"的结果。

**场景重现：**

```
时间线：
  0ms:  用户输入"贝"        -> 发请求 A，需要 500ms 才返回
  100ms: 用户输入"贝多芬"    -> 发请求 B，需要 200ms 就返回了
  300ms: 请求 B 回来了      -> 页面显示"贝多芬"的结果（正确）
  500ms: 请求 A 回来了      -> 页面被覆盖成"贝"的结果（错误！）
```

**我们的解决方案：请求计数器**

每次调用 `doSearch` 时，全局的 `requestId` 自增一次，同时把当前的 `requestId` 值存到局部变量 `currentRequestId` 中。请求回来后，检查 `currentRequestId` 是否还等于最新的 `requestId`——不相等说明有更新的请求发出去了，当前这个"旧结果"应该丢弃。

## 你应该看到的效果

1. **空闲状态**：刚打开页面，看到引导提示"输入关键词，开始搜索音乐"
2. **加载状态**：输入"周杰伦"，看到旋转加载动画和"搜索中..."
3. **成功状态**：API 返回后，看到 20 条带封面的歌曲列表
4. **空结果状态**：搜索"xysdfjkshdfkj"，看到"没有找到相关音乐"
5. **错误状态**：在 DevTools Network 面板切换到 Offline 模式，再搜索，看到"搜索失败"和重试按钮
6. **竞态条件**：快速连续输入不同关键词，最终结果始终对应最后输入的关键词，不会出现"旧结果覆盖新结果"

## 常见错误及解决方法

### 错误 1：竞态条件检查写错位置

**错误代码**：
```js
const results = await searchMusic(term)
// 没有检查 currentRequestId，直接渲染
// 问题：旧请求回来后会覆盖新结果
renderByStatus(results)
```

**正确代码**：
```js
const results = await searchMusic(term)
// ★ 必须在这里检查！await 之后、渲染之前 ★
if (currentRequestId !== requestId) {
  return  // 丢弃旧请求的结果
}
// 确认是最新请求后才渲染
if (results.length > 0) {
  currentStatus = Status.SUCCESS
  renderByStatus(results)
} else {
  currentStatus = Status.EMPTY
  renderByStatus()
}
```

### 错误 2：catch 块中没有检查竞态条件

如果旧请求的异常在 catch 中被渲染成错误状态，用户会看到"搜索失败"，而实际上最新请求可能已经成功了。

**正确做法**：catch 块中也要检查 `currentRequestId !== requestId`，旧请求的错误应该静默忽略。

### 错误 3：Status 对象写成字符串

```js
// 容易拼错，且 IDE 不会提示
currentStatus = 'laoding'  // 拼错了！应该是 'loading'
```

```js
// 使用常量，拼写错误会被 IDE 发现
currentStatus = Status.LOADING  // IDE 会检查 Status 对象上有没有这个属性
```

### 错误 4：renderByStatus 调用忘记传参数

```js
// 错误：SUCCESS 状态需要 data 参数，但忘记传了
currentStatus = Status.SUCCESS
renderByStatus()  // data 是 undefined，渲染不出结果
```

```js
// 正确：SUCCESS 状态必须传入 results 数组
currentStatus = Status.SUCCESS
renderByStatus(results)
```
