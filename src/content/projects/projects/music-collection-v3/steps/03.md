# 第 3 步：推送到 GitHub —— 让代码有个"网上的家"

## 你要做什么

在 GitHub 上创建一个公开仓库，把本地的 Git 仓库推送到 GitHub，再写一份 README.md 描述你的项目。

## 为什么这一步重要

GitHub 不只是代码备份——它是你的技术名片。以后无论是找工作、做作品集、还是和其他开发者协作，GitHub 都是核心工具。一个干净、有 README 的仓库比一百行简历更有说服力。

## 动手操作

### 第一步：在 GitHub 上创建仓库

1. 打开浏览器，访问 [github.com](https://github.com)，登录你的账号（如果没有账号，现在注册一个，免费，只需要邮箱）
2. 登录后，点击页面右上角的 **"+"** 号 → 选择 **"New repository"**（新建仓库）
3. 填写仓库信息：
   - **Repository name**（仓库名）：`music-collection`（全小写，单词之间用连字符 `-` 分隔，这是 GitHub 上的命名惯例）
   - **Description**（描述）：`🎵 我的音乐收藏应用 —— 从原生 JS 到 Vue 组件化的学习项目`
   - **Public / Private**：选择 **Public**（公开）——这样别人才能通过 GitHub Pages 访问你的项目。隐私注意：如果你想保留代码私密也可以选 Private，但后续 GitHub Pages 部署会有限制
   - **不要勾选** "Add a README file"——因为我们的项目本地已经有文件了，勾选会导致 GitHub 上也有内容，推送时产生冲突
   - **不要勾选** "Add .gitignore"——我们本地已经创建了 `.gitignore`
   - **不要勾选** "Choose a license"——暂时不需要
4. 点击绿色的 **"Create repository"** 按钮

### 第二步：关联远程仓库并推送

仓库创建后，GitHub 会跳转到一个页面，显示一段命令。你会看到类似这样的提示：

```
Quick setup — if you've done this kind of thing before
https://github.com/你的用户名/music-collection.git
```

**往下翻一点**，找到标题为 **"…or push an existing repository from the command line"** 的代码块，复制那三行命令。这三行命令的作用是：

回到你的终端（VS Code 内置终端），粘贴并运行这三行命令。**注意把 你的用户名 替换成你真实的 GitHub 用户名**：

```bash
# 告诉 Git 远程仓库的地址，"origin" 是这个地址的别名
git remote add origin https://github.com/你的用户名/music-collection.git

# 确保本地分支名是 "main"（GitHub 默认主分支名）
git branch -M main

# 把本地的 commit 推送到 GitHub，"-u" 设置上游分支（以后只需 git push 即可）
git push -u origin main
```

### 逐行解释（理解你在做什么）：

**git remote add origin <URL>**：
- `remote` = 远程仓库，即 GitHub 上的那个
- `add` = 添加一个远程仓库的地址
- `origin` = 给这个地址起的名字（约定俗成叫 origin，表示"源头"）。你也可以叫别的名字，但所有人都用 `origin`，所以你也用
- `<URL>` = GitHub 仓库的 HTTPS 地址

**git branch -M main**：
- `branch` = 分支操作
- `-M` = 强制重命名（move/rename）
- `main` = 把当前分支重命名为 `main`（GitHub 上默认主分支叫 `main`，老项目可能叫 `master`）

**git push -u origin main**：
- `push` = 推送，把本地的 commit "发送"到远程仓库
- `-u` = `--set-upstream` 的缩写，设置 `origin/main` 为本地 `main` 分支的"上游"。设置后，以后只需 `git push` 即可（不需要每次写 `origin main`）
- `origin` = 推送到哪个远程仓库
- `main` = 推送哪个分支

### 可能遇到的问题：登录验证

如果是第一次推送，GitHub 会要求验证你的身份。根据你的情况，可能出现：

**情况 A：弹出浏览器登录窗口**
- 点击"授权"或"Sign in"即可，这是最简单的方式

**情况 B：终端提示输入用户名和密码**
- 用户名：你的 GitHub 用户名
- 密码：**注意——不是你的 GitHub 登录密码！** 需要先去 GitHub 创建一个 Personal Access Token（个人访问令牌）。步骤：GitHub 网站 → 右上角头像 → Settings → 左侧最下 Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic) → 勾选 `repo` 权限 → 生成 → 复制那段 token → 在终端密码提示处粘贴（粘贴时终端不显示任何字符，这是正常的，防止别人偷看，直接粘贴后按回车）

**情况 C：终端没有任何提示，直接报错 "Permission denied"**
- 说明 SSH 密钥未配置。对于新手，最简单的解决方案是使用 HTTPS + Token（情况 B 的做法）

### 第三步：验证推送成功

推送完成后：
1. 终端输出应该包含类似 `To https://github.com/你的用户名/music-collection.git` 和 `* [new branch] main -> main`
2. 刷新 GitHub 仓库页面——你的代码文件出现在上面了！
3. 你会看到 `src/` 文件夹、`index.html`、`package.json`、`vite.config.js` 都在上面
4. 注意：`node_modules/` 和 `dist/` **不在**——这说明 `.gitignore` 生效了

### 第四步：写 README.md

README 是仓库的门面。当别人访问你的 GitHub 仓库时，README 的内容会自动渲染显示在文件列表下方。

在项目根目录（`package.json` 同级）新建 `README.md`：

```markdown
# 🎵 我的音乐收藏

一个基于 Vue 3 + Vite 构建的音乐收藏管理应用。

## 功能

- 📋 展示音乐收藏卡片列表（封面、曲名、作曲家、时期）
- 🔍 按时期筛选（巴洛克、古典主义、浪漫主义等）
- ➕ 添加新曲目（表单输入，支持自定义封面图）
- ❤️ 收藏/取消收藏曲目
- 🗑️ 删除曲目（带确认弹窗）
- 💾 自动保存到浏览器本地存储（刷新不丢失）
- ✨ 添加/删除动画过渡效果
- 📱 响应式布局（手机/平板/桌面均可使用）

## 技术栈

- **Vue 3**（Composition API + `<script setup>`）
- **Vite** 构建工具
- 纯 CSS（Grid + Flexbox 布局）

## 项目版本

| 版本 | 说明 |
|------|------|
| v1 | 纯手工版 —— HTML + CSS + 原生 JavaScript，手动操作 DOM |
| v2 | Vue 重构版 —— 组件化 + 响应式数据 + 声明式渲染 |
| v3 | 工程化版 —— Git 版本管理 + GitHub Pages 部署 + CI/CD 自动化 |

## 如何运行

```bash
# 1. 克隆项目
git clone https://github.com/你的用户名/music-collection.git

# 2. 进入项目目录
cd music-collection

# 3. 安装依赖
npm install

# 4. 启动开发服务器
npm run dev

# 5. 浏览器打开 http://localhost:5173
```

## 在线预览

👉 [https://你的用户名.github.io/music-collection/](https://你的用户名.github.io/music-collection/)
```

**注意**：先把在线预览链接留着（第四步才部署），等部署完成后你再把链接补上。

### 第五步：提交并推送 README

```bash
git add README.md
git commit -m "添加 README：项目说明、功能列表、技术栈、运行方法"
git push
```

现在刷新 GitHub 仓库页面，README 的内容应该渲染在文件列表下方，像一个精美的项目首页。

## 预期结果

- 浏览器访问 `https://github.com/你的用户名/music-collection`，看到你的完整项目代码
- README 在仓库页面下方渲染显示
- 仓库是 Public（公开）的

## 常见错误

- **错误**：创建 GitHub 仓库时勾选了 "Add a README file"。**后果**：GitHub 上有一个 README，你本地也有一个——两个不相关的提交历史，`git push` 会报错 `failed to push some refs`。**解决**：先用 `git pull origin main --allow-unrelated-histories` 拉取 GitHub 上的内容并合并，然后再 `git push`。更好的做法是创建仓库时不勾选任何初始化选项。
- **错误**：`git remote add origin` 的 URL 写错了（比如用户名拼错、仓库名拼错）。**后果**：`git push` 时报错 `remote: Repository not found`。**解决**：检查 URL，在 GitHub 仓库页面点绿色的 "Code" 按钮复制正确的 URL。如果已经 add 错了，用 `git remote remove origin` 删除，再重新 `git remote add origin <正确URL>`。
- **错误**：推送时提示 `Support for password authentication was removed`。**说明**：GitHub 从 2021 年起不再支持直接用账号密码做 Git 操作认证。**解决**：必须用 Personal Access Token（见前面"情况 B"的说明）。
- **错误**：README.md 文件名写成 `readme.md` 或 `Readme.md`。**后果**：GitHub 要求文件名精确是 `README.md`（全大写），否则不会自动渲染。**Windows 不区分大小写**，但 GitHub 的 Linux 服务器区分大小写——在 Windows 上看起来正常的文件，推上去后 GitHub 可能识别不了。**解决**：确件名是 `README.md`，大写 README。
