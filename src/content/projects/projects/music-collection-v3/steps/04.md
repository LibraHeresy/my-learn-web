# 第 4 步：构建生产版本 —— npm run build

## 你要做什么

运行 `npm run build` 命令，理解构建过程做了什么，查看 `dist/` 文件夹的内容。这是部署前的必要步骤。

## 为什么这一步重要

你一直在用 `npm run dev` 启动的开发服务器写代码——它有热更新（改代码保存后页面自动刷新）、源码映射（浏览器报错时显示源文件位置而非压缩后的位置）、未压缩的代码。这些便利是以性能为代价的。给用户访问的必须是**构建后的优化版本**——速度快、体积小、不包含开发工具。这一步让你理解"开发"和"生产"的区别。

## 动手操作

### 1. 运行构建命令

在项目根目录的终端中执行：

```bash
npm run build
```

**不要**在开发服务器运行的同时执行——先按 `Ctrl+C` 停止 `npm run dev`。

构建过程大约 3-10 秒，终端会输出类似这样的信息：

```
vite v5.x.x building for production...
✓ 34 modules transformed.
dist/index.html                   0.45 kB │ gzip: 0.30 kB
dist/assets/index-abc123.css      2.10 kB │ gzip: 0.95 kB
dist/assets/index-abc123.js      52.34 kB │ gzip: 19.82 kB
✓ built in 2.45s
```

### 2. 理解构建输出

**building for production...** —— Vite 明确告诉你：这是在构建**生产版本**，不是开发版本。

**文件大小的含义**：
- 第一个数字（`2.10 kB`）是文件的实际大小
- 第二个数字（`gzip: 0.95 kB`）是经过 gzip 压缩后、网络传输时的大小。浏览器和服务器之间的传输通常是压缩的，所以 gzip 大小更接近用户实际下载的量

**文件名中的哈希值 abc123**（你的会不同）：Vite 根据文件内容生成的一串随机字符。文件内容变了，哈希值就变。这个机制叫"缓存破坏"（cache busting）——当你更新部署后，文件名变了，浏览器就知道该下载新版本而不是使用缓存。如果文件名永远不变，浏览器可能一直显示旧的缓存版本，用户看不到你的更新。

**✓ built in 2.45s**——只用了 2.45 秒。Vite 的构建速度非常快，这就是它相比旧工具（如 Webpack）的优势。

### 3. 查看 dist/ 文件夹

构建完成后，项目根目录会多一个 `dist/` 文件夹（dist = distributable，可分发）。

```bash
# 列出 dist/ 目录结构
ls dist/
```

你会看到类似这样的结构：

```
dist/
├── index.html
├── assets/
│   ├── index-abc123.css
│   └── index-abc123.js
└── favicon.ico
```

**对比一下开发版本和生产版本**：

| 维度 | 开发版本（src/） | 生产版本（dist/） |
|------|-----------------|------------------|
| 文件数量 | 多个 .vue、.js、.css 文件 | 合并后的 2-3 个文件 |
| JS 大小 | 未压缩，含注释和变量名 | 压缩（minify），变量名缩短，注释删除 |
| CSS 大小 | 完整写法，含注释 | 压缩，空格和注释删除 |
| 源码映射 | 包含（方便调试） | 默认不包含 |
| HMR 热更新 | 支持 | 不支持（最终产品不需要） |
| 加载方式 | Vite 开发服务器动态处理 | 纯静态文件，直接由浏览器加载 |

### 4. 预览构建结果

在正式部署之前，你可以在本地预览构建结果，确保它和开发版本一样正常工作：

```bash
# 用 Vite 内置的预览服务器
npx vite preview
```

终端会输出类似 `Local: http://localhost:4173/`。在浏览器打开这个地址，你应该看到和开发模式一样的音乐收藏应用——但注意，这里的文件是 `dist/` 中的压缩版本，不是 `src/` 中的源码。

**这是一个关键验证步骤**：如果预览时页面白屏或功能异常，说明构建过程有问题。必须在部署之前修好。

测试要点：
- 卡片列表显示正常
- 筛选功能正常
- 添加/删除/收藏功能正常
- 刷新后数据不丢失（localStorage 和构建无关，不受影响）

全部确认无误后，按 `Ctrl+C` 停止预览服务器。

### 5. 将 dist/ 加入 .gitignore（检查）

确认你的 `.gitignore` 中有 `dist/` 这一行（第 2 步时已经加了）。运行 `git status` 确认 `dist/` 没有出现在未追踪文件列表中。如果出现了，说明 `.gitignore` 配置有问题。

**为什么 dist/ 不需要提交**：
- dist/ 是"构建产物"——它完全由源码生成。只要源码在，任何时候都可以重新 `npm run build` 生成完全相同的 dist/
- 提交 dist/ 会让仓库体积膨胀，commit 历史被无意义的构建产物淹没
- Git 应该管理"源头"（源码），而不是"计算结果"（构建产物）

## 预期结果

- `npm run build` 执行成功，`dist/` 文件夹生成
- `npx vite preview` 预览时页面功能正常
- 理解了"开发"和"生产"版本的区别

## 常见错误

- **错误**：在 `npm run dev` 运行的同时执行 `npm run build`。**后果**：可能端口冲突或文件锁冲突，构建失败。**解决**：先 `Ctrl+C` 停止 dev 服务器再 build。
- **错误**：构建成功但 `npx vite preview` 时图片不显示。**原因**：如果图片使用了相对路径且没有放在 `public/` 或 `src/assets/` 中，构建时可能不会正确处理。**解决**：图片放在 `src/assets/` 中并用 `import` 导入，或放在 `public/` 中用绝对路径引用。
- **错误**：构建输出显示文件很大（JS 文件超过 500KB）。**原因**：可能引入了较大的第三方库，或者误把大文件（如高清图片）用 `import` 导入了 JS bundle 中。对于本项目，JS 文件应该小于 100KB（因为只有 Vue 本身和自己的少量代码）。
- **错误**：以为 `dist/` 文件夹可以像 `src/` 一样直接修改。**后果**：修改 `dist/` 中的文件后，下次 `npm run build` 会覆盖这些修改——所有改动丢失。**解决**：永远只修改 `src/` 中的源码，`dist/` 是通过构建自动生成的，不要手动改它。
