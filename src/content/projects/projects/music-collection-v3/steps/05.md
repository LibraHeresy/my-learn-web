开发时我们用的是 Vite 的开发服务器（`npm run dev`），它有热更新和源码映射，很方便——但这些便利是以文件体积和性能为代价的。
现在要构建给用户访问的"生产版本"：
```bash
npm run build
```运行后，项目根目录会多出一个 `dist/` 文件夹：
```dist/
├── index.html        # 入口页面（压缩后）
├── assets/
│   ├── index-abc123.js   # 打包后的 JS（变量名缩短、空格删除）
│   └── index-def456.css  # 打包后的 CSS（选择器简化、注释移除）
└── favicon.ico
```对比一下：
| | 开发版本（dev） | 生产版本（dist） |
|---|---|---|
| 文件大小 | 几百 KB（未压缩） | 几十 KB（压缩后） |
| 加载速度 | 慢（多文件请求） | 快（合并后少量文件） |
| 错误提示 | 详细的源码位置 | 压缩后的位置（难读） |
| 热更新 | ✅ 有 | ❌ 无（已经是最终品） |
**类比：**
- 开发版本 = 排练时的笔记，潦草但你能看懂
- 生产版本 = 正式演出的节目单，印刷精美，观众能看懂
你可以用 `npx serve dist` 临时预览构建结果——这是你"上线前最后的彩排"。
