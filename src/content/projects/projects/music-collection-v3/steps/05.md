# 第 5 步：部署到 GitHub Pages —— 项目上线

## 你要做什么

把 `dist/` 构建产物部署到 GitHub Pages，获得一个任何人都能访问的公开网址。

## 为什么这一步重要

这是整个 v3 项目的核心交付——前面的 Git、GitHub、构建，都是为了这一步做准备。部署完成后，你的音乐收藏应用就有了一个固定的线上地址，可以发给任何人查看。这是从"在本地写代码"到"把产品交付给用户"的关键一步。

## 动手操作

### 1. 配置 Vite 的 base 路径

GitHub Pages 部署在 `https://你的用户名.github.io/仓库名/` 这样一个子路径下，而不是网站根目录。所以需要告诉 Vite：构建时所有资源路径前面加上 `/仓库名/`。

打开项目根目录的 `vite.config.js`：

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  base: '/music-collection/'   // ← 添加这一行。仓库名是什么这里就填什么
})
```

**base: '/music-collection/' 的作用**：
- 构建后的 `index.html` 中，所有资源引用路径会变成 `/music-collection/assets/index-xxx.js` 而不是 `/assets/index-xxx.js`
- 如果忘了配，部署后浏览器会尝试从 `https://你的用户名.github.io/assets/xxx.js` 加载资源，但实际资源在 `https://你的用户名.github.io/music-collection/assets/xxx.js`——路径不对，页面白屏

**注意**：末尾的 `/` 不能省。`/music-collection` 和 `/music-collection/` 在一些场景下行为不同，始终加斜杠。

### 2. 安装 gh-pages 工具

`gh-pages` 是一个 npm 包，它能帮你把 `dist/` 文件夹的内容推送到 GitHub 仓库的 `gh-pages` 分支——GitHub Pages 会自动从这个分支读取内容并部署。

```bash
npm install -D gh-pages
```

**-D 是什么意思**：这是 `--save-dev` 的缩写，表示把 `gh-pages` 安装为"开发依赖"——只在开发/部署时用到，不影响用户使用的实际代码。在 `package.json` 中，它会出现在 `devDependencies` 而不是 `dependencies` 中。这是一个好习惯：明确区分"开发时用的工具"和"运行时需要的库"。

### 3. 添加部署脚本

打开 `package.json`，找到 `"scripts"` 部分，添加 `deploy` 脚本：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "deploy": "gh-pages -d dist"
  }
}
```

**"deploy": "gh-pages -d dist" 的意思**：
- `gh-pages`：运行刚才安装的 gh-pages 工具
- `-d dist`：指定要部署的文件夹是 `dist/`（`-d` = directory）
- 这条命令会：把 `dist/` 的内容提交到 `gh-pages` 分支 → 推送到 GitHub → GitHub Pages 自动部署

### 4. 构建并部署

```bash
# 先构建
npm run build

# 再部署
npm run deploy
```

第一次部署时，`gh-pages` 会：
1. 在本地创建一个 `gh-pages` 分支
2. 把 `dist/` 的内容作为这个分支的唯一内容提交
3. 把 `gh-pages` 分支推送到 GitHub
4. 终端输出 `Published` 表示成功

### 5. 在 GitHub 上启用 Pages

部署命令执行完成后，还需要在 GitHub 仓库设置中手动启用 Pages：

1. 打开 GitHub 仓库页面
2. 点击顶部的 **Settings**（设置）标签
3. 左侧菜单找到 **Pages**（在 "Code and automation" 分类下）
4. 在 "Branch" 下拉菜单中：
   - 选择 `gh-pages`
   - 目录选择 `/ (root)`
   - 点击 **Save**
5. 页面会自动刷新，稍等片刻（通常 1-3 分钟），页面上方会出现一行蓝色提示：
   > Your site is live at `https://你的用户名.github.io/music-collection/`

### 6. 访问你的线上应用

点击那个链接或者在新标签页中输入 `https://你的用户名.github.io/music-collection/`。

你应该看到——和本地运行完全一样的音乐收藏应用！添加、删除、筛选、收藏全部正常（localStorage 是浏览器级别的，不依赖服务器，所以功能完全可用）。

**祝贺！** 你的项目从本地代码变成了一个公开网站。任何人只要有这个链接，就能看到你的作品。

### 7. 更新 README 中的链接

现在回到 `README.md`，把之前预留的在线预览链接补上：

```markdown
## 在线预览

👉 [https://你的用户名.github.io/music-collection/](https://你的用户名.github.io/music-collection/)
```

提交并推送：

```bash
git add README.md
git commit -m "更新 README：补充在线预览链接"
git push
```

### 8. 理解部署架构

此时你的 GitHub 仓库有两个分支：

| 分支 | 内容 | 用途 |
|------|------|------|
| `main` | 项目源码（`src/`、`package.json`、`vite.config.js` 等） | 给别人看你的源代码、自己继续开发改代码 |
| `gh-pages` | 构建产物（`dist/` 的内容） | GitHub Pages 读取这个分支来部署网站 |

**每次修改代码后，全部更新线上版本只需两步**：

```bash
# 1. 提交代码改动
git add .
git commit -m "描述你的改动"
git push

# 2. 重新构建并部署
npm run build
npm run deploy
```

## 预期结果

- 访问 `https://你的用户名.github.io/music-collection/`，看到完整的音乐收藏应用
- 所有功能（列表、筛选、添加、删除、收藏、持久化）都正常工作
- GitHub 仓库 Settings → Pages 显示 "Your site is live"

## 常见错误

- **错误**：忘记在 `vite.config.js` 中配置 `base`。**后果**：部署后页面白屏。按 F12 打开控制台，会看到一堆 404 错误——浏览器尝试从 `https://xxx.github.io/assets/xxx.js` 加载资源但找不到（实际在 `/music-collection/assets/xxx.js`）。**解决**：加上 `base: '/music-collection/'` 后重新 `npm run build && npm run deploy`。
- **错误**：`vite.config.js` 中 `base` 路径写成了 `/music-collection`（没有末尾斜杠）。**后果**：某些资源路径拼接可能出错（如 `/music-collectionassets/xxx.js`）。**解决**：始终在 base 路径末尾加 `/`。
- **错误**：`npm run deploy` 报错 `Permission denied`。**原因**：gh-pages 工具推送时需要 GitHub 认证。**解决**：确认你之前用 `git push` 时已经配置了认证（Token 或 SSH），gh-pages 使用的是同一个认证方式。
- **错误**：部署成功后访问网址显示 404。**可能原因 1**：GitHub Pages 还没部署完成——等 2-3 分钟再试。**可能原因 2**：仓库是 Private 的——免费账号的 Private 仓库不能使用 GitHub Pages。**解决**：在 Settings → General → Danger Zone 最底部，把仓库改为 Public。
- **错误**：线上页面能打开但样式不对或图片裂了。**可能原因**：资源路径写成了绝对路径（如 `/assets/cover.jpg` 而不是相对 Base 的路径）。**解决**：在 Vue 中使用资源时，用 `new URL('./assets/xxx', import.meta.url)` 或把文件放在 `public/` 中再用绝对路径（如 `/cover.jpg`）。
