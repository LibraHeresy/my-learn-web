# 第 2 步：Git 初始化与第一次提交

## 你要做什么

在你的 v2 项目文件夹中初始化 Git 仓库，创建 `.gitignore` 文件排除不需要追踪的文件，完成第一次 commit（提交）。

## 为什么这一步重要

Git 是所有后续操作的基础。没有 Git 仓库，代码推不到 GitHub，自动化部署也无从谈起。`.gitignore` 尤其重要——如果不配置，你可能把几万行的 `node_modules` 也提交到仓库里，仓库会变得巨大且无法维护。

## 动手操作

### 关于终端的重要说明

如果你之前没怎么用过终端（也叫"命令行"或"控制台"），下面是一些基本规则：

- **cd 命令**：Change Directory，切换目录。`cd music-collection-vue` 表示进入 `music-collection-vue` 文件夹
- **ls 命令**（Windows 上用 `dir`）：列出当前目录中的所有文件和文件夹
- **pwd 命令**（Windows 上用 `cd` 不带参数）：显示当前所在目录的完整路径
- **按上下箭头键**：浏览之前输入过的命令，不用重新打

以下所有命令中，以 `#` 开头的是注释（说明这一行是干什么的），你不需要输入 `#` 和后面的文字。

### 1. 确认你在正确的目录中

打开终端，首先确认当前在 v2 项目的根目录下：

```bash
# 查看当前目录
pwd
```

输出应该包含 `.../music-collection-vue` 或你给项目起的名字。

**如果不在正确目录**：用 `cd` 切换到项目目录：

```bash
# 替换为你的项目实际路径
cd D:\MyWorkspace\...\music-collection-vue
```

小技巧：在 VS Code 中打开你的 v2 项目文件夹，然后按 `` Ctrl+` `` 打开终端——VS Code 会自动把终端定位到项目根目录。

### 2. 确认项目可以正常运行（安全检查）

在初始化 Git 之前，确认 `npm run dev` 可以正常启动，项目没有问题。

```bash
npm run dev
```

浏览器打开 `http://localhost:5173/`，确认页面正常显示。确认后按 `Ctrl+C` 停止开发服务器。

### 3. 初始化 Git 仓库

```bash
# 初始化 Git 仓库（只执行一次）
git init
```

运行后终端会输出类似 `Initialized empty Git repository in .../music-collection-vue/.git/`。

**git init 做了什么**：在你的项目文件夹中创建了一个隐藏文件夹 `.git/`。这个文件夹包含 Git 的所有内部数据——所有 commit 记录、分支信息、配置等。**永远不要手动修改 .git/ 文件夹中的内容。**

你可以验证一下：

```bash
# 查看包含隐藏文件的目录列表
ls -a
```

你会看到项目文件夹中多了一个 `.git` 目录（注意前面有个点，代表隐藏目录）。

### 4. 查看当前状态

```bash
# 查看 Git 仓库的当前状态
git status
```

你会看到类似这样的输出：

```
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .vscode/
        index.html
        package-lock.json
        package.json
        public/
        src/
        vite.config.js
```

**"Untracked"（未追踪）** 的意思是：这些文件在项目文件夹中，但 Git 还没有开始管理它们。它们是"新来的"——Git 看到了它们，但还不知道要不要管。

### 5. 创建 .gitignore 文件 —— 重要！

在提交之前，必须告诉 Git **哪些文件不需要管理**。在项目根目录（`package.json` 同级）新建一个文件，名为 `.gitignore`（注意文件名以点开头，没有后缀）。

**操作**：在 VS Code 左侧文件列表的空白处右键 → "新建文件" → 输入 `.gitignore`。

文件内容如下：

```gitignore
# 依赖目录 —— 别人可以通过 npm install 重新下载，不需要提交
node_modules/

# 构建产物 —— 每次构建都会重新生成，不需要提交
dist/

# 本地环境变量文件 —— 可能包含敏感信息（API 密钥等）
.env.local
.env.*.local

# IDE 和编辑器配置 —— 每个人的编辑器设置不同
.vscode/
.idea/

# 操作系统生成的文件
.DS_Store
Thumbs.db
```

**逐行解释为什么不需要提交这些文件：**

| 被排除的文件 | 为什么不需要提交 | 如果提交了会怎样 |
|------------|----------------|----------------|
| `node_modules/` | 这个文件夹有几万个文件、几百 MB。别人克隆你的项目后运行 `npm install` 就能下载完全相同的依赖 | 仓库变得巨大（几百 MB），GitHub 会拒绝推送。每次 `npm install` 后 `git status` 都会显示一堆改动 |
| `dist/` | 每次 `npm run build` 都会重新生成。提交构建产物就像提交"计算结果"——源码才是源头 | 每次构建后都要 commit 新的 dist，commit 历史被无意义的构建产物淹没 |
| `.env.local` | 可能包含 API 密钥、访问令牌等敏感信息 | 密钥泄露到公开仓库——任何人都能看到，可能导致安全问题和费用损失 |
| `.vscode/` `.idea/` | 别人的编辑器配置可能和你的不同（缩进、换行符、插件等） | 团队协作时会产生无意义的配置冲突 |
| `.DS_Store` `Thumbs.db` | 操作系统自动生成的元数据文件，对你的项目没有任何用处 | 污染仓库，没有任何价值 |

保存文件后，再运行一次 `git status`：

```bash
git status
```

你应该注意到 `node_modules/` 和 `.vscode/` 从 "Untracked files" 列表中**消失了**——`.gitignore` 生效了，Git 现在忽略这些文件夹。

### 6. 第一次提交（First Commit）

提交分两步：先"暂存"（告诉 Git 要把哪些文件的改动放进这次 commit），再"提交"（拍快照）。

```bash
# 第一步：暂存所有文件（把当前目录下所有内容加入暂存区）
git add .

# 查看状态，确认暂存了哪些文件
git status
```

现在 `git status` 会显示这些文件变成绿色，状态是 "Changes to be committed"——它们已经被暂存，等待提交。

```bash
# 第二步：提交（拍快照 + 写备注）
git commit -m "初始化：Vue 3 + Vite 音乐收藏项目，包含列表、筛选、添加、收藏、删除功能"
```

每次 git 操作后的输出都是英文的，如果你不习惯，可以只看关键部分：看到类似 `[main (root-commit) a1b2c3d] 初始化...` 这样的输出就说明成功了。

**-m 参数**：后面的引号里的文字是 commit message（提交消息），用来描述这次提交做了什么。写清楚 commit message 是一个重要习惯——未来的你（或者别人）看到历史记录时，能一眼就知道每步做了什么。

**好的 commit message vs 坏的 commit message：**
- 好："添加筛选功能：按时期过滤音乐卡片"
- 坏："改了点东西"
- 好："修复删除后索引错乱的问题"
- 坏："bug fix"

### 7. 查看提交历史

```bash
# 查看提交记录
git log --oneline
```

输出类似：

```
a1b2c3d 初始化：Vue 3 + Vite 音乐收藏项目，包含列表、筛选、添加、收藏、删除功能
```

- `a1b2c3d` 是这个 commit 的哈希值（"身份证号"），每个人的不一样
- `--oneline` 让每条记录只显示一行（不用的话会显示作者、日期等更详细的信息）

**重要理解**：此时，你的项目已经被"存档"了。以后不管你怎么改代码，你都可以用 Git 回到这个状态。这是一种安全感——你可以大胆地改，因为你知道随时可以"读档"。

## 预期结果

- 运行 `git status` 显示 "nothing to commit, working tree clean"（工作区干净，没有未提交的改动）
- 运行 `git log --oneline` 显示一条 commit 记录
- 项目根目录有 `.gitignore` 文件，里面排除了 `node_modules/`、`dist/`、`.env.local` 等

## 常见错误

- **错误**：忘了先创建 `.gitignore`，直接 `git add .` 把所有文件都暂存了，包括 `node_modules/`。**后果**：`node_modules/` 里的几万个文件被加入暂存区，`git commit` 会非常慢甚至卡住，仓库大小暴增。**解决**：如果还没 commit，用 `git rm -r --cached node_modules` 从暂存区移除，然后创建 `.gitignore` 再重新 `git add .`。如果已经 commit 了，需要修改 `.gitignore` 后做一次新 commit 来移除。
- **错误**：把路径中的斜杠方向写反了。在 Windows 中，文件路径用的反斜杠 `\`，但在终端和 `.gitignore` 中，**始终用正斜杠 /**。`node_modules/` 是正确的，`node_modules\` 是错误的。
- **错误**：`git init` 在错误的目录中执行（比如在桌面或用户文件夹）。**后果**：Git 把整个桌面或用户文件夹当作"项目"来追踪，`git status` 会列出成千上万个文件。**解决**：确认当前目录下有 `package.json` 再执行 `git init`。如果已经错了，删掉那个目录下的 `.git` 文件夹即可撤销。
- **错误**：`git commit` 时忘了加 `-m` 和消息。**后果**：Git 会打开一个终端文本编辑器（通常是 Vim），对新手来说很难操作——不知道怎么输入文字、不知道怎么退出。**解决**：如果你不小心进入了 Vim：按 `i` 键进入编辑模式，输入消息，按 `Esc` 键退出编辑模式，输入 `:wq` 然后按回车（write + quit，保存并退出）。更好的办法是养成习惯，**始终用 git commit -m "消息"**。
- **错误**：commit message 用中文但在某些终端显示乱码。**后果**：不影响功能，只是看起来别扭。**解决**：如果担心编码问题，可以用英文 message；或者先用中文，以后有需要再改（不影响 Git 的功能）。
