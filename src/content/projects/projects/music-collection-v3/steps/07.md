# 第 7 步：环境变量 —— 区分开发和生产

## 你要做什么

学习使用 `.env` 文件管理配置信息（如 API 地址、应用标题等），理解 `VITE_` 前缀的含义，区分开发环境和生产环境的配置。

## 为什么这一步重要

你的应用在不同的"环境"中运行时，某些配置应该是不同的。比如：
- 开发时你可能用一个测试用的 API 地址
- 部署后应该用真实的 API 地址
- 某些功能只在开发时开启（如调试面板），上线后关闭

环境变量就是用来管理这些"因环境而异的配置"的。虽然本项目目前没有 API 调用，但理解这个机制是使用任何现代前端框架的基本功。

## 动手操作

### 1. 理解环境变量的概念

环境变量是一组"键=值"的配置。它们在应用启动时被读取，然后在代码的任何地方都可以使用。

**生活中类比的例子**：
- 你在家穿的拖鞋（开发环境）
- 你在公司穿的皮鞋（生产环境）
- 你不需要在代码中写"如果在家穿拖鞋，如果在公司穿皮鞋"——你只需要一个变量叫"鞋子的类型"，在不同环境下设置不同的值

### 2. 创建环境变量文件

在项目根目录（`package.json` 同级）创建两个文件：

**`.env`**（通用配置，所有环境都生效）：

```env
# 应用标题
VITE_APP_TITLE=我的音乐收藏

# 默认时期（用于新添加曲目时的下拉默认值）
VITE_DEFAULT_PERIOD=古典主义
```

**`.env.development`**（开发环境专用，`npm run dev` 时生效）：

```env
# 开发环境标题（可以加个标记区分）
VITE_APP_TITLE=我的音乐收藏 [DEV]

# 开发环境启用调试日志
VITE_ENABLE_DEBUG=true
```

**`.env.production`**（生产环境专用，`npm run build` 时生效）：

```env
# 生产环境标题（正式名称）
VITE_APP_TITLE=🎵 我的音乐收藏

# 生产环境关闭调试日志
VITE_ENABLE_DEBUG=false
```

### 3. VITE_ 前缀规则

**重要**：Vite 只会暴露以 `VITE_` 开头的环境变量给你的应用代码。这是出于安全考虑——防止不小心把敏感的环境变量（如密钥）暴露到前端代码中。

- `VITE_APP_TITLE` → 可以在代码中通过 `import.meta.env.VITE_APP_TITLE` 访问
- `APP_TITLE`（没有 VITE_ 前缀）→ **无法访问**，Vite 会忽略它
- `VITE_SECRET_KEY` → 可以访问——但这很危险！**任何以 `VITE_` 开头的变量都会被打包进最终 JS 文件中，用户可以看到**。所以千万不要在前端环境变量中放真正的密钥、密码、Token

### 4. 在代码中使用环境变量

打开 `src/App.vue`，把硬编码的标题替换为环境变量。

修改 `<script setup>`，在顶部添加环境变量的读取：

```vue
<script setup>
import { ref, computed, watch } from 'vue'
import MusicCard from './components/MusicCard.vue'
import FilterBar from './components/FilterBar.vue'
import AddForm from './components/AddForm.vue'

// 读取环境变量
const appTitle = import.meta.env.VITE_APP_TITLE || '我的音乐收藏'
const enableDebug = import.meta.env.VITE_ENABLE_DEBUG === 'true'

// 调试日志（仅在开发环境打印）
if (enableDebug) {
  console.log('🐛 调试模式已开启')
  console.log('应用标题:', appTitle)
}
</script>
```

然后把 `<template>` 中的标题改成使用变量：

```vue
<template>
  <div class="app">
    <h1>{{ appTitle }}</h1>
    <!-- 其余代码不变 -->
  </div>
</template>
```

### 通俗理解 `import.meta.env`

- `import.meta` 是 Vite 提供的一个特殊对象
- `import.meta.env` 包含了所有以 `VITE_` 开头的环境变量
- `import.meta.env.VITE_APP_TITLE` 取出 `VITE_APP_TITLE` 的值

**注意**：环境变量的值永远是**字符串**。所以 `VITE_ENABLE_DEBUG=true` 中的 `true` 实际上是字符串 `"true"`，不是布尔值。需要用 `=== 'true'` 来判断，不能直接用 `if (import.meta.env.VITE_ENABLE_DEBUG)`。

### 5. 测试环境变量切换效果

**开发环境测试**：

```bash
npm run dev
```

浏览器打开 `http://localhost:5173/`——标题应该显示"我的音乐收藏 [DEV]"，并且浏览器控制台（F12）能看到调试日志。

**生产环境测试**：

```bash
npm run build
npx vite preview
```

浏览器打开 `http://localhost:4173/`——标题应该显示"🎵 我的音乐收藏"（没有 [DEV] 后缀），并且控制台**没有**调试日志。

### 6. 确保 .env 文件不提交到 Git

`.env` 文件可能包含敏感信息或本地专用的配置——不应该提交到 Git。检查 `.gitignore` 中是否包含了以下行：

```gitignore
# 环境变量文件
.env.local
.env.*.local
```

注意：`.env` 和 `.env.development`、`.env.production` 这类不包含 `.local` 的文件，**通常会提交到 Git**（因为它们包含的是公共的、非敏感的配置）。只有 `.env.local`（本地覆盖）才不应该提交，因为它可能包含你个人的 API 密钥或其他敏感信息。

对于本项目，你可以选择：
- **推荐**：把 `.env`、`.env.development`、`.env.production` 提交到 Git（让其他人克隆项目后也能正常运行）
- 如果你在 `.env.local` 中放了个人配置（如 API 密钥），确保它在 `.gitignore` 中

### 7. 提交并推送

```bash
git add .env .env.development .env.production src/App.vue
git commit -m "添加环境变量支持：区分开发和生产环境标题"
git push
```

如果配置了 GitHub Actions，push 后自动部署的版本会使用 `.env.production` 中的配置。

## 预期结果

- 开发模式（`npm run dev`）下标题显示 "[DEV]" 后缀，控制台有调试日志
- 生产模式（`npm run build` + preview）下标题无后缀，控制台无调试日志
- 理解了 VITE_ 前缀的意义和环境变量的使用场景

## 常见错误

- **错误**：环境变量没有 `VITE_` 前缀。**后果**：`import.meta.env.XXX` 的值为 `undefined`，代码中读不到这个值。**解决**：所有需要在代码中访问的环境变量必须以 `VITE_` 开头。
- **错误**：在 `.env` 中放入了敏感信息（API 密钥、Token 等），且以 `VITE_` 开头。**后果**：这些值会被打包进 `dist/` 的 JS 文件中，任何人查看网页源码都能看到你的密钥——这是严重的安全事故。**解决**：需要保密的配置绝不能出现在前端环境变量中，应该放在后端服务中。前端环境变量只放公开的、非敏感的配置。
- **错误**：修改 `.env` 文件后没重启开发服务器。**后果**：开发服务器仍然使用旧的环境变量值。**解决**：每次修改 `.env` 文件后，需要 `Ctrl+C` 停止开发服务器，然后重新 `npm run dev`。环境变量只在服务器启动时读取一次。
- **错误**：用布尔值判断环境变量时没转字符串（`if (import.meta.env.VITE_FLAG)` 而不是 `if (import.meta.env.VITE_FLAG === 'true')`）。**后果**：环境变量值是字符串 `"false"`，非空字符串在 JavaScript 中是 truthy——所以 `if ("false")` 结果是 `true`，和预期相反。**解决**：环境变量的比较始终用字符串：`=== 'true'`、`=== 'production'` 等。
