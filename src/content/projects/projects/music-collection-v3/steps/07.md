现在每次修改代码后，都要手动运行 `npm run build && npm run deploy`。能不能让这个过程自动化？
这就是 CI/CD（持续集成/持续部署）——每次 `git push`，GitHub 自动帮你构建和部署。
创建一个 `.github/workflows/deploy.yml` 文件：
```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
# 授予 GITHUB_TOKEN 写入 Pages 的权限
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 18
      - name: Install dependencies
        run: npm ci
      - name: Build
        run: npm run build
      - name: Setup Pages
        uses: actions/configure-pages@v4
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./dist
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```逐行解释：
- `permissions` — 给 workflow 授权：读源码、写 Pages、获取临时身份令牌
- `on.push.branches: [main]` — 当 main 分支有新 push 时触发
- `environment` — 关联 GitHub Pages 环境，部署后可拿到最终 URL
- `actions/checkout@v4` — 把代码下载到虚拟机
- `actions/setup-node@v4` — 安装 Node.js
- `npm ci` — 安装依赖（比 `npm install` 更快，适合 CI 环境）
- `actions/configure-pages@v4` — 自动配置 Pages 设置
- `actions/upload-pages-artifact@v3` — 把 `dist/` 打包上传为部署工件
- `actions/deploy-pages@v4` — 将工件部署到 GitHub Pages
> 💡 这里用的是 GitHub 官方 action，无需依赖第三方。
创建这个文件后，提交并推送：
```bash
git add .github/
git commit -m "添加 GitHub Actions 自动部署"
git push
```然后打开 GitHub 仓库的 Settings → Pages，把 Source 改为 "GitHub Actions"。
从此以后，你只需要 `git push`，GitHub 会自动：构建 → 部署 → 上线。这就是真正的工程化开发流程！
