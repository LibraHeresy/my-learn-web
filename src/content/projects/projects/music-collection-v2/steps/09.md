# 第 9 步：打磨体验 —— 过渡动画、空状态、细节优化

## 你要做什么

给项目加上过渡动画、空列表提示、加载状态展示等细节，让应用从"能用"升级到"好用"。

## 为什么这一步重要

功能做好只是及格线，用户体验决定了别人愿不愿意用你的应用。这一节你学的不是 Vue 的核心 API，而是**实际项目中提升完成度的具体技巧**：过渡动画、空状态、边界情况处理。这些就是"Demo 项目"和"真正产品"之间的差距。

## 动手操作

### 1. 列表过渡动画 —— `<TransitionGroup>`

Vue 内置了 `<TransitionGroup>` 组件，专门用于为 `v-for` 列表的增删添加动画。打开 `src/App.vue`，修改模板中的卡片列表部分：

```vue
<template>
  <div class="app">
    <h1>🎵 我的音乐收藏</h1>

    <AddForm @add="addPiece" />

    <FilterBar
      :periods="periods"
      :active="selectedPeriod"
      @update:active="selectPeriod"
    />

    <!-- 用 TransitionGroup 包裹列表，添加进出动画 -->
    <TransitionGroup name="card" tag="div" class="card-grid">
      <MusicCard
        v-for="piece in filteredPieces"
        :key="piece.id"
        :id="piece.id"
        :name="piece.name"
        :composer="piece.composer"
        :image="piece.image"
        :period="piece.period"
        :liked="piece.liked"
        @toggle-like="toggleLike"
        @delete="deletePiece"
      />
    </TransitionGroup>
  </div>
</template>
```

**注意**：`<TransitionGroup>` 把原来的 `<div class="card-grid">` 替换掉了——`tag="div"` 告诉 Vue 把它渲染成一个 `<div>`，`class="card-grid"` 照常传给它。

然后在 `<style>` 中添加过渡动画样式（加在已有样式后面）：

```css
/* TransitionGroup 动画 */
.card-enter-active,
.card-leave-active {
  transition: all 0.5s ease;
}

/* 进入：从透明 + 向下偏移开始 */
.card-enter-from {
  opacity: 0;
  transform: translateY(30px);
}

/* 离开：变为透明 + 缩小 */
.card-leave-to {
  opacity: 0;
  transform: scale(0.8);
}

/* 离开时让其他卡片平滑移动填补空隙 */
.card-leave-active {
  position: absolute;
}

/* 让卡片在移动时也有过渡 */
.card-move {
  transition: transform 0.5s ease;
}
```

### 逐行理解

**`name="card"`** —— 这是过渡效果的名称。Vue 会根据这个名称自动应用对应的 CSS class：
- `card-enter-from`：元素进入时的初始状态
- `card-enter-active`：元素进入过程中的过渡设置
- `card-enter-to`：元素进入完成后的状态（这里没用到）
- `card-leave-from`：元素离开时的初始状态（这里没用到）
- `card-leave-active`：元素离开过程中的过渡设置
- `card-leave-to`：元素离开完成时的状态

**`tag="div"`** —— `<TransitionGroup>` 默认不会生成 DOM 元素，`tag` 指定它渲染成什么标签。这里是 `div`，和我们之前的 `.card-grid` 容器一致。

**`.card-leave-active { position: absolute; }`** —— 这个技巧让离开的元素脱离文档流，这样后面的卡片才能平滑地向上移动填补空隙。没有这行的话，离开的元素还在占据空间，其他卡片会等动画结束后突然跳到新位置。

**`.card-move`** —— 当其他卡片因为列表变化而移动位置时，这个 class 控制它们的移动过渡效果。

### 2. 空状态提示

当筛选结果为空时（比如选了"现代主义"但还没有这个时期的曲目），当前列表是空的——用户可能以为应用坏了。加个提示：

在 `<TransitionGroup>` 后面（模板中）添加：

```vue
<!-- 空状态提示 -->
<div v-if="filteredPieces.length === 0 && pieces.length === 0" class="empty-state">
  <p class="empty-icon">🎶</p>
  <p class="empty-title">收藏库是空的</p>
  <p class="empty-desc">用上方的表单添加你的第一首音乐收藏吧！</p>
</div>

<div v-else-if="filteredPieces.length === 0" class="empty-state">
  <p class="empty-icon">🔍</p>
  <p class="empty-title">没有找到「{{ selectedPeriod }}」时期的曲目</p>
  <p class="empty-desc">试试选择其他时期，或者添加一首这个时期的曲目</p>
</div>
```

在 `<style>` 中添加空状态样式：

```css
.empty-state {
  text-align: center;
  padding: 60px 20px;
  color: #999;
}

.empty-icon {
  font-size: 48px;
  margin-bottom: 16px;
}

.empty-title {
  font-size: 18px;
  font-weight: 600;
  margin-bottom: 8px;
  color: #666;
}

.empty-desc {
  font-size: 14px;
}
```

**注意区分两种空状态：**
1. `pieces.length === 0`（全部数据为空）→ 提示"收藏库是空的，去添加吧"
2. `filteredPieces.length === 0` 但 `pieces.length > 0`（筛选结果为空）→ 提示"这个时期没有曲目，换个时期或添加一首"

区分这两种情况能让用户更清楚地知道发生了什么。

### 3. 响应式细节优化

在 `<style>` 中添加一个简单的媒体查询，优化小屏幕下的卡片展示：

```css
/* 小屏幕适配 */
@media (max-width: 480px) {
  .music-card {
    flex-direction: column;
    text-align: center;
  }

  .card-image {
    width: 120px;
    height: 120px;
  }

  .card-actions {
    width: 100%;
    justify-content: center;
  }
}
```

这个媒体查询的意思是：当屏幕宽度小于 480px 时（大多数手机竖屏状态），卡片从横向排列改为纵向排列，封面图稍大一些，按钮居中。

### 4. 验证效果

保存所有文件，回到浏览器：

1. **动画**：添加一首新曲目——卡片应该从下方淡入滑上来。删除一首曲目——卡片应该缩小淡出。筛选切换——卡片平滑过渡。
2. **空状态**：把全部曲目删光——应该看到"收藏库是空的"提示（和添加表单一起显示）。
3. **筛选空状态**：先确保有曲目，然后筛选到"现代主义"（如果你还没添加现代主义的曲目）——应该看到"没有找到"提示。
4. **响应式**：把浏览器窗口缩窄到手机宽度——卡片应该变成纵向排列。

## 预期结果

- 添加/删除卡片时有平滑的过渡动画
- 全部数据为空时显示"收藏库是空的"
- 筛选结果为空时显示"没有找到 XX 时期的曲目"
- 手机宽度下卡片纵向排列

## 常见错误

- **错误**：`<TransitionGroup>` 的子元素忘了加 `:key`。**后果**：动画不生效，Vue 控制台报警告。**解决**：TransitionGroup 的子元素必须有 `:key`——我们已经在 `<MusicCard>` 上写了 `:key="piece.id"`，所以这里没问题。但如果你后续改了结构，别忘了这点。
- **错误**：`tag` 和内部的 CSS class 冲突。比如你把 `class="card-grid"` 同时放在 `<TransitionGroup>` 和它内部的 `<div>` 上。**后果**：布局可能多出一层嵌套。**解决**：TransitionGroup 只有一个 `tag`——把容器的 class 直接放在 TransitionGroup 上，它会传给生成的 DOM 元素。
- **错误**：空状态用了 `<MusicCard>` 组件来展示（而不是文本提示）。**后果**：代码复杂了，而且添加和删除操作也和普通卡片混在一起。**解决**：空状态就是一段普通 HTML 文本——越简单越好。
- **错误**：媒体查询的断点选择不对（比如只设了 768px，没考虑更小的 320px 手机）。**后果**：在极窄屏幕上布局仍然不够好。**解决**：测试时把浏览器窗口拖到尽可能窄（320px 左右），确保布局不会溢出。
