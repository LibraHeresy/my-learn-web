# 第 8 步：LocalStorage 持久化 —— Watch 自动保存

## 你要做什么

用 `watch` 监听数据变化，自动把 `pieces` 保存到 `localStorage`，让刷新页面后数据不丢失。

## 为什么这一步重要

v1 中你需要在每次操作后**手动**调用保存函数——忘了调用数据就丢了。`watch` 是 Vue 提供的自动化方案：你指定"监视什么"+"变化时做什么"，Vue 帮你盯着。这是"响应式"思想的延伸——不只是视图响应数据，副作用也可以响应数据。这个"watch-save"模式在你的实际项目中会反复用到。

## 动手操作

### 1. 理解逻辑流程

在写代码之前，先在脑子里把流程过一遍：

**页面首次加载时：**
1. 读取 `localStorage` 中的数据
2. 如果有：用这些数据初始化 `pieces`
3. 如果没有：用默认的 6 条示例数据初始化

**数据变化时（添加、删除、收藏）：**
1. `pieces` 内容发生变化
2. `watch` 检测到变化
3. 自动把 `pieces` 保存到 `localStorage`

**页面刷新时：**
1. 回到"首次加载"的流程——`localStorage` 中有之前保存的数据，所以用这些数据初始化
2. 用户看到的是刷新前最后一次保存的状态

### 逐行理解——重点

**`import { watch }`** —— 从 Vue 中导入 `watch`。注意：要用 `watch` 而不是 `watchEffect`。两者区别：
- `watch(数据源, 回调)` —— 明确指定监视哪个数据，变化时执行回调
- `watchEffect(回调)` —— 自动追踪回调中用到的所有响应式数据
- 对于"保存到 localStorage"这个场景，`watch` 更清晰——你明确知道你在监视 `pieces`

**`loadFromStorage()` 函数** —— 封装了读取逻辑：
1. `localStorage.getItem('music-collection-v2')` ——  读取存储的数据
2. `JSON.parse(saved)` —— localStorage 只能存字符串，所以读取后需要 `JSON.parse` 把字符串还原为 JavaScript 对象/数组
3. `try...catch` —— 防御性编程。如果 localStorage 中的数据被手动修改、损坏，`JSON.parse` 会抛异常。加了 `try...catch` 后，异常被捕获，自动使用默认数据——而不是让整个应用崩溃。
4. 验证 `Array.isArray(parsed) && parsed.length > 0` —— 确保读出来的确实是数组且有内容。如果 localStorage 里存了一个空数组 `[]`，`JSON.parse` 不会报错，但列表会是空的——加了长度检查就避免了这个问题。

**存储键名 `'music-collection-v2'`** —— 用了带版本号的键名。这是一个好习惯：以后如果数据结构变了，换成 `'music-collection-v3'` 就不会和旧数据冲突。

**`watch(pieces, callback, { deep: true })`** —— 三个参数：
1. 第一个参数 `pieces`：要监视的响应式数据
2. 第二个参数 `(newPieces) => { ... }`：数据变化时执行的回调。`newPieces` 是变化后的新值
3. 第三个参数 `{ deep: true }`：**深度监听**。这是最容易忘记的参数。没有它，`watch` 只检查 `pieces` 这个引用有没有变（即是否被替换成了新数组），不检查数组**内部**元素的变化。加上 `deep: true` 后，数组内任何元素的增删改都能被检测到。

**`JSON.stringify(newPieces)`** —— localStorage 只能存字符串，所以保存前需要用 `JSON.stringify` 把数组转换为 JSON 字符串。

### 4. 对比 v1 的持久化方案

| | v1 手工版 | v2 Vue 版 |
|---|---|---|
| 保存触发 | 每次操作后手动调用 | `watch` 自动监听 |
| 读取时机 | `window.onload` 时手动读取 | `ref(loadFromStorage())` 初始化时自动读取 |
| 忘记保存的后果 | 数据静默丢失，用户以为 bug | 不会丢失——保存是自动的 |
| 代码量 | 多个保存函数调用点分散在各处 | 一个 `watch` 集中管理 |

这就是框架的价值：把"每次都记得做"变成"设置一次自动执行"。

## 预期结果

- 添加、删除、收藏操作后刷新页面，数据保持一致
- 开发者工具的 Application 面板中能看到 localStorage 中的数据
- 清除 localStorage 后刷新页面，恢复默认的 6 条示例数据

## 常见错误

- **错误**：忘了 `{ deep: true }`。**后果**：`watch` 只监视 `pieces` 的引用变化（即 `pieces.value = newArray` 这种整体替换），不监视数组内部元素的增删改。当你 `push` 新曲目或 `splice` 删除曲目时，watch 回调不会触发，数据不会保存到 localStorage。**解决**：数组和对象的 watch 几乎总是需要 `deep: true`。
- **错误**：忘了 `JSON.stringify`（直接 `localStorage.setItem('key', newPieces)`）。**后果**：localStorage 会把数组转成字符串 `"[object Object],[object Object]"`，下次 `JSON.parse` 时报错或得到垃圾数据。**解决**：存入前永远 `JSON.stringify`，取出后永远 `JSON.parse`。
- **错误**：localStorage 键名和 v1 中的键名相同。**后果**：如果浏览器之前存过 v1 的数据，v2 会读取到旧格式的数据，而 v1 的数据结构可能和 v2 不同（比如缺少 `id` 字段），导致渲染出错。**解决**：用不同的键名（如 v1 用 `'music-collection'`，v2 用 `'music-collection-v2'`），或者确保数据结构兼容。
- **错误**：`loadFromStorage` 中没加 `try...catch`。**后果**：如果用户手动修改了 localStorage 中的数据导致 JSON 不合法，`JSON.parse` 抛异常，整个应用崩溃白屏。**解决**：始终用 `try...catch` 包裹 `JSON.parse`，失败时降级到默认数据。
