# 第 10 步：代码回顾 —— v1 vs v2 对比

## 你要做什么

把 v1（纯手工版）和 v2（Vue 重构版）并排对比，逐项分析代码结构、数据管理、交互实现的差异，彻底理解"框架到底帮我们做了什么"。

## 为什么这一步重要

写完代码不等于学会了。真正的学习发生在**对比和反思**中——你能说清楚"为什么 v2 更好"，才说明你消化了 Vue 的核心思想。这一步也是为 v3（工程化部署）做铺垫——你需要在心里有一张清晰的"我做了什么"的地图。

## 动手：逐项对比

拿出你在 v1 中写的 `index.html` 或 `app.js`（如果没有就回忆代码结构），和 v2 的代码做以下对比：

### 1. 整体结构对比

| 维度 | v1 手工版 | v2 Vue 重构版 |
|------|----------|-------------|
| 文件数量 | 1 个 HTML 文件（HTML/CSS/JS 混在一起） | 4 个 `.vue` 文件 + 入口文件，各司其职 |
| 代码行数 | ~200-300 行集中在一个文件 | ~300 行分散在多个文件中，每个文件更短 |
| 找代码 | 在 300 行中搜索 `class="card"` | 打开 `MusicCard.vue` —— 一目了然 |
| 复用 | 复制 HTML 字符串来生成多张卡片 | `v-for` 一句话搞定，组件可在任何 Vue 项目复用 |
| 新增功能 | 需要在 HTML、CSS、JS 三个地方分别加代码 | 创建新 `.vue` 文件，导入到 App.vue 即可 |

**关键思考**：v1 的代码结构是"浏览器优先"——你关心的是"页面上有哪些元素，怎么排列"。v2 的结构是"数据优先"——你关心的是"有哪些数据，这些数据驱动了什么视图"。这不是换了个写法，而是**换了思考方式**。

### 2. 核心功能实现对比

**渲染列表**

| | v1 | v2 |
|---|---|---|
| 初始渲染 | `forEach` + `createElement` + `appendChild` 循环拼接 DOM | `ref([])` + `v-for` 声明式渲染 |
| 添加新项 | 再次 `createElement`、设置属性、`appendChild` | `pieces.value.push(newPiece)`，Vue 自动更新 |
| 删除项 | 找到 DOM 元素，`element.remove()` | `splice` 从数组中移除，Vue 自动更新 DOM |
| 代码量 | 每次操作 5-10 行 | 每次操作 1-2 行 |

**数据筛选**

| | v1 | v2 |
|---|---|---|
| 实现方式 | 遍历所有 DOM 卡片 → 比较 → 改 `display` | `computed`：`pieces.value.filter(...)` |
| 筛选按钮 | 手动创建按钮，手动绑定点击事件 | `v-for` + `@click` 自动渲染和绑定 |
| 新增时期 | 手动在 HTML 中加新按钮 | `periods` computed 自动从数据中提取——零改动 |
| 恢复全部 | 遍历所有卡片，改回 `display: ''` | `selectedPeriod = '全部'`，computed 自动返回全部 |

**收藏切换**

| | v1 | v2 |
|---|---|---|
| 状态管理 | 存在 DOM 元素的 class 或 data 属性中 | 存在数据的 `liked` 字段中 |
| 切换逻辑 | 读 DOM 状态 → 反着设置 → 改 class | `piece.liked = !piece.liked` |
| 持久化 | 需要额外遍历 DOM 收集状态再保存 | `watch` 自动检测 `pieces` 变化并保存 |

**思考题**：如果我想加一个"按作曲家排序"的功能，在 v1 和 v2 中分别要改哪些代码？
- v1：排序 DOM（复杂、易出错、性能差）
- v2：`computed` 中加 `.sort()`（一行代码、自动更新）

### 3. 数据流对比

v1 的数据流：**没有"数据流"这个概念！** 数据散落在 DOM 元素的属性、textContent、class 中。你想知道"当前有哪些曲目"？你需要遍历 DOM 来"读取"。这是"以 DOM 为中心"。

v2 的数据流：**单向数据流，始终可追踪。**

```
pieces (ref) ──→ filteredPieces (computed) ──→ v-for 渲染
    ↑                    ↑
    │                    │
 修改数据            自动重新计算
(通过方法)           (响应式)
    │                    │
    └── watch ──→ localStorage 自动保存
```

任何时刻，你只需要看 `pieces.value` 就知道"当前有哪些数据"。你不需要去 DOM 里找。视图永远是从数据派生出来的——**数据是真相的唯一来源（Single Source of Truth）**。

### 4. 可维护性对比

| 场景 | v1 的问题 | v2 的解决 |
|------|----------|---------|
| 改卡片样式 | 在一个大 CSS 块中找 `.card` 相关规则 | 打开 `MusicCard.vue`，scoped 样式只影响这个组件 |
| 加新功能 | 担心改错其他功能（都在一个文件里） | 新建 `.vue` 文件，不影响已有组件 |
| 别人接手 | 需要先读完 300 行才能定位问题 | 文件名就是功能名：`AddForm.vue` 就是表单，`FilterBar.vue` 就是筛选 |
| 调试 bug | `console.log` 到处插，检查 DOM 状态 | Vue DevTools 直接看组件树、props、data 的值 |

### 5. 什么没变？

不是所有东西都变了。以下内容在 v1 和 v2 中是一样的：
- **CSS 样式**：核心样式逻辑（flex 布局、颜色、间距）基本一致，只是被分散到了各个 `scoped` style 块
- **localStorage 机制**：都是用 `getItem`/`setItem` + `JSON.parse`/`stringify`，只是 v2 用 `watch` 自动化了
- **交互逻辑**：收藏就是切换布尔值，删除就是从列表移除——业务逻辑不变，只是实现方式从"操作 DOM"变成"操作数据"
- **用户体验**：用户看到的东西（卡片样式、按钮交互、筛选效果）v1 和 v2 可以做到一模一样——框架改变的是**开发体验**，不是**用户看到的东西**

## 预期结果

完成这一步后，你应该能用自己的话回答：
1. "命令式"和"声明式"的区别，并举例
2. computed 和普通函数的区别
3. 为什么 Vue 中要避免直接操作 DOM
4. 如果你要加一个新功能（比如搜索框），在 v2 中你会怎么做

## 常见错误

- **错误**：认为 v2 只是"把 v1 的代码翻译成了 Vue 语法"。**后果**：你可能在用 Vue 的语法写命令式代码——比如在 Vue 中仍然用 `document.querySelector` 来操作 DOM。**解决**：核心不是语法，是思维方式。当你遇到问题时，先问自己"数据是什么？数据变了视图怎么变？"而不是"我要怎么改 DOM？"
- **错误**：不看对比直接跳到 v3。**后果**：没有深刻理解 Vue 的价值，v3 的工程化流程就只是"跑命令"，不知道为什么值得。**解决**：花 10 分钟认真做上述对比，在脑子里把数据流图画一遍。
