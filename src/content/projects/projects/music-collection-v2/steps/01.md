# 第 1 步：为什么要迁移到 Vue？

## 你要做什么

理解从原生 JavaScript 迁移到 Vue 框架的动机——不是"因为流行"，而是因为它解决了你写 v1 时遇到的实际痛点。

## 为什么这一步重要

如果你不理解"为什么"，后面学 Props、Computed、Watch 时就只是在背语法，而不是在解决真实问题。带着痛点学，每个概念都有明确的"它解决了什么"。

## 动手之前：回顾 v1 的痛点

打开你在《音乐收藏库 · 纯手工版》中写的代码，回忆一下这些场景：

**场景 1：渲染列表。** 添加一个曲目后，你需要手动写 `document.createElement('div')`、`appendChild`、设置 `textContent`、添加 class……每次添加都要把这些步骤重做一遍。如果哪天你忘了调 `appendChild`，页面上就看不到新卡片，但浏览器不报错——BUG 无声无息。

**场景 2：筛选数据。** 用户点"巴洛克"按钮，你需要：遍历所有卡片 DOM → 读取每张卡片的时期属性 → 比较 → 设置 `style.display = 'none'`。点"全部"时又要全部恢复。这个逻辑散落在好几个函数里，改一个容易漏另一个。

**场景 3：数据持久化。** 每次操作完（添加、删除、收藏），你都要记得手动调用一次 `localStorage.setItem()`。忘了调用？——刷新后数据就丢了，用户会以为你写的功能坏了。

**场景 4：代码混乱。** 当你的 `app.js` 超过 200 行后，找一段逻辑越来越慢。HTML 结构藏在 JS 的字符串里，修改一个 card 的样式要去翻 `createElement` 的代码。

## Vue 怎么解决这些问题

| 痛点 | 原生 JS 方式 | Vue 方式 | 解决原理 |
|------|-------------|---------|---------|
| 渲染列表 | `createElement` + `appendChild` 一步步手写 | `v-for="item in list"` 一句话 | **声明式渲染**：你描述"我要一个列表"，Vue 负责生成 DOM |
| 数据更新 | `element.textContent = newValue` 逐个修改 | `ref` 变量一变，页面自动变 | **响应式系统**：Vue 追踪数据依赖，数据变了自动更新 DOM |
| 筛选过滤 | 遍历 DOM、改 `display` | `computed` 计算属性 | **自动推导**：原始数据不变，筛选结果是自动算出来的 |
| 持久化 | 到处手动调 `localStorage` | `watch` 监听数据，自动保存 | **自动副作用**：数据一变就触发保存，永远不会漏 |
| 代码组织 | 一个文件几千行，HTML/JS/CSS 混在一起 | 组件化：每个 `.vue` 文件独立，各管各的 | **关注点分离**：改卡片样式只需打开 `MusicCard.vue` |

## 核心转变：命令式 → 声明式

这是整个 Vue 学习的核心：

- **命令式（v1）**：你告诉浏览器**怎么一步步做**。"创建一个 div → 加个 class → 设置文字 → 插到某个元素后面"
- **声明式（v2）**：你描述**最终应该是什么样**。"这有一组数据，按这个模板渲染，数据变了自己更新"

就像点菜：命令式是你进厨房告诉厨师每一步怎么做；声明式是你对着菜单说"来一份宫保鸡丁"——你不需要知道厨房怎么运作。

## 前提条件

在开始之前，确保你已经完成了：

1. 《走出浏览器》——会打开终端，理解什么是命令行
2. 《安装 Node.js》——Node.js 已安装，`node -v` 和 `npm -v` 都能正常输出版本号
3. 《Vite 创建项目》——知道 `npm create vite` 是干什么的
4. 《单文件组件》——了解 `.vue` 文件由 `<template>`、`<script>`、`<style>` 三部分组成
5. 完成了《音乐收藏库 · 纯手工版》（v1）——本步骤需要拿 v1 的代码做对比

**验证你的环境**：打开终端（PowerShell），依次运行：

```bash
node -v        # 应该输出 v18.x 或 v20.x
npm -v         # 应该输出 9.x 或 10.x
```

如果都正常输出，说明环境准备就绪。

## 预期结果

读完这一步，你应该能用自己的话说出：

1. v1 的三个具体痛点（渲染、筛选、持久化）
2. Vue 的三个核心价值（声明式渲染、响应式、组件化）
3. "命令式"和"声明式"的区别，并举例说明

## 常见错误

- **错误**：认为 Vue 只是"写得少"，不理解响应式本质。**后果**：后面遇到 bug 时不知道 Vue 在干什么，只会乱改。
- **错误**：没完成 v1 就直接开始 v2。**后果**：没有对比参照，无法理解 Vue 替代了什么。
- **错误**：跳过前提条件中的基础课程。**后果**：不知道 `.vue` 文件是什么，看到 template/script/style 三块内容一脸茫然。
