# 第 4 步：列表渲染 —— v-for

## 你要做什么

在 App.vue 中创建一个**响应式数据数组**，用 `v-for` 指令一次性渲染多张卡片，告别 v1 中手动 `createElement` 的循环。

## 为什么这一步重要

`v-for` 是 Vue 中使用频率最高的指令之一，几乎每个实际项目都会用到。这一步你还将第一次接触 `ref`——Vue 响应式系统的核心。理解 `ref` 和 `v-for` 的关系，是理解"数据驱动视图"的关键。

## 动手操作

### 逐行理解

**`import { ref } from 'vue'`** —— `ref` 是 Vue 提供的一个函数，它把普通数据变成"响应式数据"。响应式数据的意思：当数据变化时，所有用到这个数据的页面位置都会自动更新。你不需要手动调任何 DOM API。

**`const pieces = ref([...])`** —— 把数组用 `ref()` 包起来。注意：
- 在 `<script>` 中访问/修改数据时，需要用 `pieces.value`（比如 `pieces.value.push(newItem)`）
- 但在 `<template>` 中，Vue 会**自动解包**，所以你直接写 `pieces` 就行，不用加 `.value`

这是 Vue 新手最容易搞混的地方：**script 中用 `.value`，template 中不用。**

**`id` 字段** —— 每条数据有唯一的 `id`。这在后面做删除、收藏操作时至关重要。永远用 `id` 来找数据，不要用数组索引——因为数组删除元素后索引会变。

### 2. 用 v-for 渲染列表

把 `<template>` 中之前硬编码的单张卡片删掉，替换成 `v-for` 循环：

```vue
<template>
  <div class="app">
    <h1>🎵 我的音乐收藏</h1>

    <!-- 音乐卡片列表 -->
    <div class="card-grid">
      <MusicCard
        v-for="piece in pieces"
        :key="piece.id"
        :id="piece.id"
        :name="piece.name"
        :composer="piece.composer"
        :image="piece.image"
        :period="piece.period"
        :liked="piece.liked"
      />
    </div>
  </div>
</template>
```

**逐行理解：**

`v-for="piece in pieces"` —— 循环 `pieces` 数组，每次迭代把当前元素赋值给 `piece` 变量。等价于 JavaScript 的 `for (const piece of pieces)`。

`:key="piece.id"` —— **非常重要！** `key` 是 Vue 用来追踪每个列表项的唯一标识。当数据变化时，Vue 根据 `key` 判断哪些 DOM 需要更新、哪些可以复用。没有 `key` 或 `key` 不唯一会导致：
- 列表更新时出现奇怪的显示错位
- 动画和过渡效果异常
- 组件状态错乱（比如你点了第一张的收藏，结果显示第二张被收藏了）

**黄金规则：`:key` 的值必须是唯一的、稳定的（不随渲染顺序变化）。** 用 `piece.id` 是最佳选择。**永远不要用数组索引（`:key="index"`）**，理由同上。

### 3. 添加列表布局样式

在 `<style>` 中添加卡片网格布局（接在上一步的样式后面）：

```css
.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(360px, 1fr));
  gap: 20px;
}
```

这个 CSS Grid 布局的意思是：
- `repeat(auto-fill, ...)` —— 在一行中尽量多地放置卡片
- `minmax(360px, 1fr)` —— 每张卡片至少 360px 宽，如果空间多余就均分
- `gap: 20px` —— 卡片之间间距 20px

效果：大屏幕上卡片自动排成多列，手机屏幕上自动变单列——这就是**响应式布局**，不需要写任何媒体查询。

### 4. 验证效果

保存 `App.vue`，查看浏览器。你应该看到 6 张音乐卡片以网格布局整齐排列，每张卡片显示各自的曲名、作曲家和时期。

**试试这个实验（理解响应式）**：按 `F12` 打开控制台，切换到 "Console" 面板。由于你在浏览器中无法直接访问 Vue 组件内部变量，我们先记下这个观察：把浏览器窗口从宽拖到窄——卡片会自动从 3 列变成 2 列再变成 1 列。这就是 CSS Grid 的响应式行为。

- 浏览器中显示 6 张音乐卡片，网格布局，大屏多列、小屏单列
- 每张卡片的内容来自 `pieces` 数组中的对应数据
- 收藏按钮显示正确（维瓦尔第和肖邦显示红心，其余显示空心）

## 常见错误

- **错误**：`:key` 用数组索引（`:key="index"`）。**后果**：删除第一张卡片后，原来的第二张变成了第一张，但它继承了之前第一张的 DOM 状态，可能导致收藏状态显示错乱。**解决**：始终用数据中的唯一 ID 作为 key。
- **错误**：在 `<script>` 中修改数据时忘记 `.value`（写成 `pieces = [...]` 而不是 `pieces.value = [...]`）。**后果**：数据确实被改了，但 Vue 的响应式系统不知道——页面不会更新。**解决**：记住规则——**script 中用 `.value`，template 中不用**。
- **错误**：`v-for` 写在非循环的父元素上。**后果**：如果你把 `v-for` 写在 `<div class="card-grid">` 上，整个 grid 容器会被重复多次，布局就碎了。**解决**：`v-for` 应该写在**要被重复渲染的元素**上，这里是 `<MusicCard>`。
- **错误**：数据数组不是响应式的（没用 `ref` 包裹，直接 `const pieces = [...]`）。**后果**：初始能渲染，但后续往数组里添加或删除数据时，页面不会更新。**解决**：始终用 `ref()` 包裹需要响应式变化的数据。
