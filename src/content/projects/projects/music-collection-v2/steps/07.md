# 第 7 步：删除和收藏切换 —— 子组件通知父组件修改数据

## 你要做什么

实现两个关键交互：点击删除按钮移除一张卡片（带确认弹窗），点击收藏按钮切换喜欢状态。这两个功能都遵循同一个模式——子组件 emit 事件，父组件修改数据。

## 为什么这一步重要

删除和收藏是几乎每个应用都有的交互模式。它们演示了 Vue 中**子组件如何安全地修改父组件的数据**——子组件不直接改数据，而是"通知"父组件。这个模式贯穿所有 Vue 应用，你后面写的每一个交互功能基本都遵守这个规则。

## 动手操作

### 1. 修改 MusicCard.vue —— 确认删除

打开 `src/components/MusicCard.vue`，确认 `<script setup>` 中已经有了 emit 声明（第 3 步写的）。如果没有，加上：

```vue
<script setup>
defineProps({
  id: { type: Number, required: true },
  name: { type: String, required: true },
  composer: { type: String, required: true },
  image: { type: String, required: true },
  period: { type: String, required: true },
  liked: { type: Boolean, default: false }
})

const emit = defineEmits(['toggle-like', 'delete'])
</script>
```

确认模板中的按钮绑定了事件（第 3 步已写）。如果没有 `@click`，加上：

```vue
<button
  class="btn-like"
  :class="{ active: liked }"
  @click="emit('toggle-like', id)"
>
  {{ liked ? '❤️' : '🤍' }}
</button>
<button
  class="btn-delete"
  @click="emit('delete', id)"
>
  🗑️
</button>
```

**MusicCard 的工作到此结束。** 它只需要"发出事件带上 id"，具体怎么处理是父组件的事。如果 MusicCard 自己写删除逻辑（比如修改 `pieces` 数组），就会破坏"数据放在顶层"的原则。

### 2. 在 App.vue 中实现删除和收藏逻辑

打开 `src/App.vue`，在 `<script setup>` 中添加两个处理函数：

```vue
<script setup>
import { ref, computed } from 'vue'
import MusicCard from './components/MusicCard.vue'
import FilterBar from './components/FilterBar.vue'
import AddForm from './components/AddForm.vue'

// ... pieces、selectedPeriod、periods、filteredPieces、selectPeriod、addPiece 保持不变

// 切换收藏状态
function toggleLike(id) {
  const piece = pieces.value.find(p => p.id === id)
  if (piece) {
    piece.liked = !piece.liked
  }
}

// 删除曲目
function deletePiece(id) {
  // 找到要删除的曲目（为了在确认框中显示曲名）
  const piece = pieces.value.find(p => p.id === id)
  if (!piece) return

  // 确认弹窗
  const confirmed = confirm(`确定要删除「${piece.name}」吗？此操作不可撤销。`)
  if (!confirmed) return

  // 从数组中移除
  const index = pieces.value.findIndex(p => p.id === id)
  if (index !== -1) {
    pieces.value.splice(index, 1)
  }
}
</script>
```

### 逐行理解

**`pieces.value.find(p => p.id === id)`** —— 用 `id` 查找数据。注意这里用的是 `Array.find()`，而不是 `pieces.value[id]`。为什么？因为数组索引和 `id` 不是一回事——删除了一首曲目后，后面的曲目索引会变，但它们的 `id` 永远不会变。**用 `id` 作为数据的唯一标识，是前端开发的基本纪律。**

**`piece.liked = !piece.liked`** —— 切换布尔值。这里不需要 `piece.liked.value`——因为 `pieces` 本身是 ref，但数组内部的元素不是 ref。Vue 的响应式系统能检测到对象属性的变化（通过 Proxy），所以直接赋值就能触发更新。

**`confirm(...)`** —— 浏览器内置的确认对话框，返回 `true`（用户点"确定"）或 `false`（用户点"取消"）。这是一个简单的 UX 保护——防止误删。实际项目中可能会用自定义的弹窗组件，但原理一样。

**`pieces.value.splice(index, 1)`** —— 从数组中移除一个元素。`splice(index, 1)` 表示从 `index` 位置开始删除 1 个元素。不要用 `delete pieces.value[index]`——`delete` 只会把那个位置变成 `undefined`（变成空洞），数组长度不变，Vue 的列表渲染会出问题。

### 3. 在模板中绑定事件

找到 `<template>` 中的 `<MusicCard>`，添加事件监听：

```vue
<MusicCard
  v-for="piece in filteredPieces"
  :key="piece.id"
  :id="piece.id"
  :name="piece.name"
  :composer="piece.composer"
  :image="piece.image"
  :period="piece.period"
  :liked="piece.liked"
  @toggle-like="toggleLike"
  @delete="deletePiece"
/>
```

**注意**：`@toggle-like="toggleLike"` 这行在之前第 3、4 步可能漏写了。如果你之前写的 `<MusicCard>` 上没有 `@toggle-like` 和 `@delete`，现在补上。

### 完整数据流回顾

以收藏操作为例，追踪一次完整的数据流：

1. 用户点击收藏按钮 → MusicCard 中 `@click` 触发
2. `emit('toggle-like', id)` → 向父组件发出事件，带上曲目 id
3. App.vue 中 `@toggle-like="toggleLike"` 捕获事件 → 调用 `toggleLike(id)`
4. `toggleLike` 找到对应的 piece → `piece.liked = !piece.liked`
5. `pieces.value` 的内容变了
6. Vue 响应式系统检测到变化 → 自动更新 DOM
7. 卡片上的爱心从空心变实心（或反过来）
8. 样式也跟着变（`:class="{ liked: liked }"` 触发）

整个过程中，**你一行 DOM 操作都没写**。这就是声明式编程——你描述了"liked 为 true 时显示红心"，Vue 负责在数据变化时执行这个描述。

## 常见错误

- **错误**：用索引而不是 id 来找数据（`pieces.value[index]` 而不是 `find(p => p.id === id)`）。**后果**：删除第一张后，索引全部前移。之前收藏了第 3 张，删除第 1 张后，再点原来的第 3 张收藏按钮时，它可能已经不是原来的那张了。**解决**：始终用 `id` 来标识数据，用 `find` / `findIndex` 而不是 `[index]`。
- **错误**：在 MusicCard 子组件中直接修改 props（如 `props.liked = !props.liked`）。**后果**：Vue 会报警告 "Avoid mutating a prop directly"。更严重的是，修改不会同步回父组件的数据，导致数据和视图不一致。**解决**：子组件只能 emit 事件，让父组件来改数据。这是 Vue 中不可违反的规则。
- **错误**：用 `delete pieces.value[index]` 而不是 `splice`。**后果**：数组出现 `undefined` 空洞，`v-for` 渲染出错，Vue 响应式系统可能检测不到变化。**解决**：始终用 `splice`、`filter`、`push` 等数组方法来修改数组。
- **错误**：`@toggle-like` 在父组件中的处理函数名拼写不一致（`@toggle-like="toggleLike"` 但函数名叫 `toggle_Like`）。**后果**：点击按钮后控制台报 `toggleLike is not a function`。**解决**：事件处理函数名要和模板中写的完全一致。
