# 第 5 步：筛选功能 —— Computed 与 FilterBar 组件

## 你要做什么

创建 FilterBar 组件展示时期筛选按钮，用 `computed` 计算属性自动生成筛选选项并过滤列表数据。

## 为什么这一步重要

`computed` 是 Vue 区别于原生 JS 最强大的特性之一。它让你声明"这个值是怎么算出来的"，然后 Vue 自动追踪依赖、自动缓存结果、自动更新。v1 中你需要手动遍历 DOM 并改 `display` 属性的几十行代码，在 v2 中只需要几行 `computed`。这一步还能让你理解"数据始终只有一份，筛选结果是算出来的"这个核心设计思想。

## 动手操作

### 1. 创建 FilterBar.vue

在 `src/components/` 文件夹中新建 `FilterBar.vue`：

```vue
<script setup>
defineProps({
  periods: {
    type: Array,
    required: true
  },
  active: {
    type: String,
    required: true
  }
})

const emit = defineEmits(['update:active'])
</script>

<template>
  <div class="filter-bar">
    <button
      v-for="period in periods"
      :key="period"
      :class="{ active: active === period }"
      @click="emit('update:active', period)"
    >
      {{ period }}
    </button>
  </div>
</template>

<style scoped>
.filter-bar {
  display: flex;
  flex-wrap: wrap;
  gap: 10px;
  margin-bottom: 24px;
  justify-content: center;
}

.filter-bar button {
  padding: 8px 20px;
  border: 2px solid #e0e0e0;
  border-radius: 20px;
  background: #fff;
  color: #666;
  font-size: 14px;
  cursor: pointer;
  transition: all 0.2s;
}

.filter-bar button:hover {
  border-color: #4a90d9;
  color: #4a90d9;
}

.filter-bar button.active {
  background: #4a90d9;
  border-color: #4a90d9;
  color: #fff;
}
</style>
```

### 逐行理解

**defineProps({ periods: { type: Array }, active: { type: String } })** —— FilterBar 只需要两个数据：
- `periods`：可选的时期列表，如 `['全部', '巴洛克', '古典主义', '浪漫主义']`
- `active`：当前选中的时期，如 `'巴洛克'`

**emit('update:active', period)** —— 用户点击某个按钮时，告诉父组件"用户选了这个时期"。注意事件名叫 `update:active`——这是 Vue 的一个约定，配合 `v-model` 使用时可以简写。我们选择手动监听而不是 `v-model`，是为了让你更清楚地看到数据流向。

**为什么 FilterBar 只负责"显示按钮"和"通知父组件"？**
这是组件设计的关键原则：**组件不应该自己做决定**。FilterBar 不知道也不关心"选了巴洛克之后列表应该怎么变"——那是在 App.vue 中用 computed 决定的。FilterBar 只做了它名字里写的事：展示筛选栏（Filter Bar）。

### 2. 在 App.vue 中添加筛选逻辑

打开 `src/App.vue`，修改 `<script setup>`：

```vue
<script setup>
import { ref, computed } from 'vue'
import MusicCard from './components/MusicCard.vue'
import FilterBar from './components/FilterBar.vue'

// pieces 数据保持不变（上一节的内容）

// 当前选中的时期
const selectedPeriod = ref('全部')

// 自动从数据中提取所有不重复的时期
const periods = computed(() => {
  const allPeriods = pieces.value.map(p => p.period)
  const uniquePeriods = [...new Set(allPeriods)]
  return ['全部', ...uniquePeriods]
})

// 根据选中的时期过滤数据
const filteredPieces = computed(() => {
  if (selectedPeriod.value === '全部') {
    return pieces.value
  }
  return pieces.value.filter(p => p.period === selectedPeriod.value)
})

// 切换时期
function selectPeriod(period) {
  selectedPeriod.value = period
}
</script>
```

### 逐行理解

**const selectedPeriod = ref('全部')** —— 当前选中的时期，默认显示全部。用户点击 FilterBar 按钮时，这个值会变化。

**computed(() => {...})** —— `computed` 接收一个函数，函数返回"计算结果"。这个计算结果的特殊性在于：
1. **自动追踪依赖**：`periods` 的 computed 中用了 `pieces.value`，所以只要 `pieces` 数组变化（添加了新时期的曲目），`periods` 自动重新计算。你不需要手动维护时期列表。
2. **缓存**：只要依赖没变，`computed` 就返回上次缓存的结果，不会重复计算。这和普通函数不同——普通函数每次调用都重新执行。
3. **只读**：computed 的值是**派生**出来的，你不能直接修改它。想改变筛选结果？改 `selectedPeriod` 或 `pieces`——这才是"数据源"。computed 永远是"根据源数据算出来的"。

**[...new Set(allPeriods)]** —— 用 `Set` 去重数组。`Set` 是 JS 内置的数据结构，自动排除重复元素。`[...set]` 把 Set 转回数组。

**filteredPieces** —— 这就是用来渲染列表的数据。注意：**模板中 v-for 应该遍历 filteredPieces 而不是 pieces**。这是下一步要在模板中改的地方。

### 3. 更新模板

修改 `<template>`，在卡片列表上方添加 FilterBar 组件，并把 `v-for` 的数据源换成 `filteredPieces`：

```vue
<template>
  <div class="app">
    <h1>🎵 我的音乐收藏</h1>

    <!-- 筛选栏 -->
    <FilterBar
      :periods="periods"
      :active="selectedPeriod"
      @update:active="selectPeriod"
    />

    <!-- 音乐卡片列表 -->
    <div class="card-grid">
      <MusicCard
        v-for="piece in filteredPieces"
        :key="piece.id"
        :id="piece.id"
        :name="piece.name"
        :composer="piece.composer"
        :image="piece.image"
        :period="piece.period"
        :liked="piece.liked"
      />
    </div>
  </div>
</template>
```

**注意**：`@update:active="selectPeriod"` —— 监听 FilterBar 发出的事件。当用户点击"巴洛克"按钮时：
1. FilterBar 调用 `emit('update:active', '巴洛克')`
2. App.vue 的 `selectPeriod('巴洛克')` 被调用
3. `selectedPeriod.value` 变成 `'巴洛克'`
4. `filteredPieces` 自动重新计算，只保留巴洛克时期的曲目
5. 页面上的卡片自动更新——你一行 DOM 操作都没写

这就是"数据驱动"的完整链路。

### 4. 验证效果

保存所有文件，回到浏览器。你应该看到：
- 标题下方出现一排筛选按钮：全部、巴洛克、古典主义、浪漫主义
- "全部"按钮高亮（蓝色背景）
- 点击"巴洛克"——只剩巴赫和维瓦尔第的 2 张卡片
- 点击"浪漫主义"——只剩肖邦和施特劳斯的 2 张卡片
- 点击"全部"——恢复 6 张卡片

**有趣的验证**：时期按钮的数量和名称是 `periods` computed 自动生成的。如果你以后添加了一首"现代主义"的曲目，筛选栏会自动多出一个"现代主义"按钮——不需要你手动去加。

## 预期结果

- 筛选按钮正确显示四种选项（全部、巴洛克、古典主义、浪漫主义）
- 点击不同按钮，卡片列表实时过滤
- 高亮按钮对应当前选中的时期

## 常见错误

- **错误**：`v-for="piece in pieces"` 而不是 `v-for="piece in filteredPieces"`。**后果**：筛选按钮不管怎么点，列表都不变——因为模板始终渲染的是未筛选的原始数据。**解决**：列表渲染必须用 computed 的结果，这样才能随筛选条件变化。
- **错误**：在 `<script>` 中访问 computed 值时忘了 `.value`（写成 `selectedPeriod === '全部'` 而不是 `selectedPeriod.value === '全部'`）。**后果**：比较永远不成立，筛选永远返回全部数据。**解决**：script 中所有 ref 和 computed 都要加 `.value`。
- **错误**：computed 函数中做了副作用操作（比如在 computed 里调 `localStorage.setItem`、发网络请求、修改其他 ref）。**后果**：computed 会在依赖变化时重新执行，导致副作用被触发不可预测的次数。**解决**：computed 应该**只计算、只返回结果**——它是"纯"的。副作用请用 `watch`（第 8 步会讲）。
- **错误**：FilterBar 中 `emit('update:active', period)` 拼写成 `emit('update:active', period)` 但父组件监听的是 `@update-active`（用短横线而不是冒号）。**后果**：事件发不出去，点击按钮无反应。**解决**：事件名统一——Vue 推荐在模板中用 kebab-case（`@update:active` 中的 `update:active` 已经是这个格式，括号里保持不变即可）。
