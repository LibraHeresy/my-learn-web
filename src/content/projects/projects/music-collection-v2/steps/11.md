# 第 11 步：验收清单与下一步

## 你要做什么

逐项检查你的 v2 项目是否完整可用，确认你没有漏掉任何功能。然后了解接下来可以往哪个方向走。

## 为什么这一步重要

"差不多做完了"和"确认做完了"是两回事。正式的项目交付一定有检查清单（checklist）——逐项打钩确认，不给 bug 留死角。这一步也帮你建立"自我验收"的习惯：每次做完一个功能，自己先测一遍，而不是等别人发现 bug。

## 功能验收清单

逐项操作，每条都通过了再打钩：

### 基础功能

- 项目启动：在项目目录下运行 `npm run dev`，浏览器能正常打开 `http://localhost:5173/`
- 默认数据：页面加载后能看到 6 张音乐卡片，网格布局排列
- 卡片信息：每张卡片显示封面图、曲名、作曲家、时期标签

### 筛选功能

- 点击"巴洛克"按钮——只剩巴赫和维瓦尔第的 2 张卡片
- 点击"古典主义"按钮——只剩莫扎特和贝多芬的 2 张卡片
- 点击"全部"按钮——恢复 6 张卡片
- 筛选按钮高亮与当前选中时期一致（蓝色背景）
- 筛选到空结果时显示"没有找到"提示（不是空白页）

### 添加功能

- 填写曲名、作曲家、图片 URL、时期，点击"添加曲目"——新卡片出现在列表中
- 提交后表单字段自动清空
- 不填曲名就提交——弹出"请输入曲名"提示
- 不填作曲家就提交——弹出"请输入作曲家"提示
- 添加一个新时期的曲目（如"现代主义"）——筛选栏自动出现"现代主义"按钮

### 收藏功能

- 点击空心爱心——变红心，卡片背景变淡粉色
- 再次点击红心——变回空心，背景恢复白色
- 在"巴洛克"筛选下点收藏——切换回"全部"，确认收藏状态保留
- 刷新页面——收藏状态保持

### 删除功能

- 点击删除按钮——弹出确认框，显示曲名
- 点"确定"——卡片从列表中消失
- 点"取消"——卡片保留
- 删除后刷新页面——被删的卡片没有"复活"
- 在筛选视图下删除一张卡片——列表正确更新，不出现空位

### 持久化

- 添加、修改、删除后刷新页面——数据保持一致
- 打开开发者工具 → Application → Local Storage → 能看到 `music-collection-v2` 键
- 手动清除 localStorage 后刷新——恢复默认的 6 条数据，而不是白屏

### 体验细节

- 添加/删除卡片时有过渡动画（滑入/淡出）
- 删光所有数据后——显示"收藏库是空的"提示
- 手机宽度下（把浏览器窗口缩窄到 400px 以下）——卡片纵向排列，不变形

### 代码质量自查（不需要全懂，但要知道方向）

- 每个组件文件 < 150 行（如果某个文件超过 150 行，考虑拆分）
- 没有在子组件中直接修改 props（如 `props.liked = xxx`）
- 没有使用 `document.querySelector` 或 `document.getElementById`
- 所有 `v-for` 都有唯一的 `:key`
- 所有 `computed` 只做计算，没有副作用（没有 `localStorage.setItem`、`fetch` 等）

## 如果卡住了

按以下顺序排查：

1. **页面白屏，控制台有报错**：先看红色报错信息，通常是拼写错误、导入路径错误、语法错误。从第一行报错开始修复，后面的错误可能是前面引起的连锁反应。
2. **点击按钮没反应**：检查 emit 事件名是否一致（子组件 `emit('toggle-like', id)`，父组件 `@toggle-like="toggleLike"`）。注意 Vue 会自动转换大小写（`toggleLike` ↔ `toggle-like`），但最好统一用 kebab-case（短横线命名法）。
3. **数据刷新后丢失**：检查 watch 是否加了 `{ deep: true }`；检查 localStorage 的 key 是否正确。
4. **筛选不生效**：检查 `v-for` 遍历的是 `filteredPieces` 还是 `pieces`；检查 `computed` 中访问 ref 是否加了 `.value`。
5. **动画不生效**：检查 TransitionGroup 子元素是否有 `:key`；检查 CSS class 的 `name` 前缀是否匹配（`name="card"` → CSS 用 `.card-enter-from`）。

## 下一步：选择你的路线

v2 项目到这里就完成了。你有两个方向可以选择：

### 方向 A：继续学习工程化（推荐）
进入 **music-collection-v3**，学会：
- 用 Git 管理代码版本
- 把代码推送到 GitHub
- 构建生产版本（`npm run build`）
- 部署到 GitHub Pages，获得一个公开网址
- 用 GitHub Actions 实现自动部署

### 方向 B：巩固和理解
- 把 v1 和 v2 并排打开（或者其他同学），口头讲解一遍"我在 v2 中改了哪些地方、为什么改了"
- 试着加一个小功能：搜索框（输入文字实时过滤曲名）。这只需要新增一个 `searchQuery` ref 和修改 `filteredPieces` 的 computed 逻辑
- 把 v2 的代码结构画成一张图（组件树 + 数据流向），放在项目文件夹里

### 方向 C：补充基础知识
如果在 v2 过程中发现某个概念始终不太理解，回到对应的基础课程重新学一遍（不要觉得丢脸——每个概念都是踩过坑之后才能真正理解的）。
- Props 不熟 → 《单文件组件》的 Props 部分
- Computed 不熟 → 《Computed 与 Watch》课程
- v-model 不熟 → 《表单与 v-model》课程
- 事件不熟 → 《组件通信》课程
