# 步骤 7：筛选功能——按风格分类查看

---

## 这一步在做什么

让页面顶部的筛选按钮（全部、巴洛克、古典、浪漫、现代）发挥作用：点击某个风格按钮后，只显示该风格的卡片，其他卡片隐藏。

---

## 为什么这一步很重要

"筛选/过滤"是几乎所有列表类应用的基础功能——购物网站的按品类筛选、邮箱的按标签筛选、任务管理的按状态筛选。核心逻辑是相通的：**有一个原始数据列表，根据一个条件决定每项是显示还是隐藏。**

这一步还让你练习"按钮状态管理"——点击一个新按钮后，之前的按钮取消高亮，新按钮高亮。这种"互斥选中"的交互模式非常常见。

---

## 具体操作

### 1. 打开 `script.js`

在 VS Code 中打开 `script.js`。

### 2. 获取筛选按钮元素

在文件顶部的"获取表单相关元素"代码附近（或任意位置，但建议放在一起方便管理），添加筛选按钮的引用：

```javascript
// ====== 获取筛选按钮 ======
const filterButtons = document.querySelectorAll(".filter-btn");
```

### 3. 写筛选函数

在 `renderCards` 函数之后（或任意合适的位置），添加筛选函数：

```javascript
// ====== 筛选与按钮状态管理 ======
function setupFilters() {
  // 给每个筛选按钮绑定点击事件
  filterButtons.forEach(function(button) {
    button.addEventListener("click", function() {
      // 步骤1：获取当前按钮的筛选值
      const filterValue = button.dataset.filter;
      // dataset.filter 对应 HTML 中的 data-filter 属性

      // 步骤2：更新按钮的激活状态
      // 先移除所有按钮的 active 类
      filterButtons.forEach(function(btn) {
        btn.classList.remove("active");
      });
      // 再给当前点击的按钮添加 active 类
      button.classList.add("active");

      // 步骤3：根据筛选值过滤数据
      let filteredData;
      if (filterValue === "all") {
        // "全部"——不过滤，显示所有数据
        filteredData = musicData;
      } else {
        // 按风格过滤：只保留 period 和 filterValue 一致的数据
        filteredData = musicData.filter(function(item) {
          return item.period === filterValue;
        });
      }

      // 步骤4：用过滤后的数据重新渲染页面
      renderCards(filteredData);
    });
  });
}
```

**逐行解释：**

| 代码 | 作用 |
|------|------|
| `button.dataset.filter` | 读取 HTML 中 `data-filter` 属性的值。例如点击"古典"按钮时，`filterValue` 是 `"古典"` |
| `classList.remove("active")` | 移除 CSS 类 |
| `classList.add("active")` | 添加 CSS 类 |
| `musicData.filter(function(item) { ... })` | 数组的 `filter` 方法——遍历数组，返回使回调函数返回 `true` 的元素组成的新数组。**原数组不变** |
| `renderCards(filteredData)` | 用过滤后的数据渲染。注意这里传的是筛选过的数据——全量数据 `musicData` 依然保存在数组中，筛选只是决定了"显示哪些" |

### 4. 在页面加载时初始化筛选

在 `script.js` 末尾，`renderCards(musicData)` 这行之后，添加：

```javascript
// ====== 初始化筛选功能 ======
setupFilters();
```

### 5. 修复筛选后的删除和添加问题

当前方案存在一个问题：筛选后再删除或添加时，会以筛选后的数据为基准渲染。我们需要确保**删除和添加操作始终操作全量数据**。

#### 修复删除——获取当前筛选状态

修改 `deleteMusic` 函数。找到它，在删除数据之后、重新渲染之前，加上对当前筛选状态的判断：

```javascript
function deleteMusic(id) {
  const confirmed = confirm("确定要删除这首曲目吗？此操作不可撤销。");
  if (!confirmed) return;

  const index = musicData.findIndex(function(item) {
    return item.id === id;
  });
  if (index !== -1) {
    musicData.splice(index, 1);
  }

  // ====== 修改：根据当前筛选状态渲染 ======
  renderFilteredCards();

  console.log(`🗑 已删除 ID=${id} 的曲目，当前共 ${musicData.length} 首`);
}
```

#### 修复添加——获取当前筛选状态

同样修改 `addForm.addEventListener` 中的渲染部分：

```javascript
addForm.addEventListener("submit", function(event) {
  event.preventDefault();

  // ...（中间代码保持不变）...

  musicData.push(newItem);

  // ====== 修改：根据当前筛选状态渲染 ======
  renderFilteredCards();

  addForm.reset();
  console.log(`✅ 已添加：《${title}》—— ${composer}`);
});
```

#### 写辅助函数：根据当前激活的筛选按钮渲染

在 `renderCards` 函数下面添加：

```javascript
// ====== 辅助：根据当前激活的筛选按钮来渲染 ======
function renderFilteredCards() {
  // 找到当前激活的筛选按钮
  const activeBtn = document.querySelector(".filter-btn.active");
  const filterValue = activeBtn ? activeBtn.dataset.filter : "all";

  if (filterValue === "all") {
    renderCards(musicData);
  } else {
    const filteredData = musicData.filter(function(item) {
      return item.period === filterValue;
    });
    renderCards(filteredData);
  }
}
```

### 6. 完整的交互流程

现在整个流程是：
1. 用户点击筛选按钮 → `setupFilters` 中的事件处理 → 更新按钮状态 + 按条件渲染
2. 用户添加新曲目 → 数据 `push` 到 `musicData` → `renderFilteredCards()` 根据当前筛选按钮渲染
3. 用户删除曲目 → 数据从 `musicData` 中 `splice` → `renderFilteredCards()` 根据当前筛选按钮渲染

这样就保证了：无论筛选状态如何，添加和删除操作都作用于**全量数据**，渲染结果也正确反映了当前筛选。

## 设计讨论：`filter` 返回新数组 vs. 在原数组上操作

```javascript
// filter 返回一个新数组——不修改原数组
const classicMusic = musicData.filter(item => item.period === "古典");
// musicData 仍然是完整的 6 条数据
// classicMusic 是筛选后的 2 条数据

// splice 直接修改原数组
musicData.splice(2, 1);
// musicData 现在是 5 条数据了
```

理解哪些方法修改原数组、哪些返回新数组，对于避免 Bug 非常重要：

| 方法 | 是否修改原数组 | 返回值 |
|------|--------------|--------|
| `push()` | 修改 | 新数组长度 |
| `splice()` | 修改 | 被删除的元素组成的数组 |
| `filter()` | 不修改 | 筛选后的新数组 |
| `map()` | 不修改 | 映射后的新数组 |
| `findIndex()` | 不修改 | 找到的索引或 -1 |
| `forEach()` | 不修改 | `undefined` |

## 这一步的常见错误

### 错误 1：点击筛选按钮后，按钮样式没有变化
**原因**：忘记更新 `active` 类。
**解决**：确认在事件处理函数中有 `classList.remove` 和 `classList.add` 的代码。注意要先移除所有按钮的 `active`，再给当前按钮添加。

### 错误 2：筛选后，那些不应该显示的卡片还在
**原因**：没有调用 `renderCards(filteredData)`，或者调用了但传的仍然是 `musicData`。
**解决**：确认筛选逻辑结束后调用了 `renderCards(filteredData)`，且参数是过滤后的数组。

### 错误 3：切换到其他筛选后，上一轮的筛选结果没有消失
**原因**：`renderCards` 内部会先执行 `grid.innerHTML = ""` 清空容器。如果这个清空逻辑没执行（比如 `grid` 变量是 `null`），旧卡片就会残留。
**解决**：检查 `document.getElementById("cardGrid")` 是否正确获取到了容器元素。

### 错误 4：筛选后添加曲目，卡片没有出现在当前筛选中
**原因**：添加时调用的是 `renderCards(musicData)` 而不是 `renderFilteredCards()`。
**解决**：确认添加和删除操作都改用 `renderFilteredCards()` 来渲染。

### 错误 5：`filterButtons.forEach` 报错"不是函数"
**原因**：用 `querySelector`（单数，只返回一个元素）而不是 `querySelectorAll`（复数，返回 NodeList）。
**解决**：`querySelectorAll` 返回的是 NodeList（可以 `forEach`）。`querySelector` 返回单个元素（不能 `forEach`）。确认用的是 `querySelectorAll`。
