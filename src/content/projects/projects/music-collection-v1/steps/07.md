# 步骤 6：删除功能——移除不需要的收藏

---

## 这一步在做什么

让每张卡片上的"删除"按钮可以真正工作。点击删除按钮 → 从数据数组中移除对应的数据 → 从页面上移除对应的卡片。

---

## 为什么这一步很重要

添加和删除是"数据管理"的两个基本操作。有了删除功能，你的应用才是一个真正能被使用的工具——用户可以管理自己的收藏，而不只是往里面堆东西。

这一步还会引入一个重要的设计决策：**删除后是全量重新渲染，还是只移除被删的那一个 DOM 元素？** 两种做法各有优劣，这一步我们会对比并选择最适合当前项目的方式。

---

## 具体操作

### 1. 打开 `script.js`

在 VS Code 中打开 `script.js`。

### 2. 给删除按钮绑定事件

我们在 `createCard` 函数中已经写好了删除按钮的 HTML。现在需要在卡片创建之后，给这个按钮绑定点击事件。

找到 `createCard` 函数。在 `return card;` 之前，添加事件绑定代码：

```javascript
function createCard(item) {
  const card = document.createElement("div");
  card.className = "music-card";
  card.dataset.id = item.id;

  card.innerHTML = `
    <img class="card-cover" src="${item.cover}" alt="${item.title}">
    <div class="card-info">
      <h3>${item.title}</h3>
      <p class="composer">${item.composer}</p>
      <span class="tag">${item.period}</span>
      <button class="delete-btn">🗑 删除</button>
    </div>
  `;

  // ====== 新增：给删除按钮绑定事件 ======
  const deleteBtn = card.querySelector(".delete-btn");
  deleteBtn.addEventListener("click", function() {
    deleteMusic(item.id);
  });

  return card;
}
```

**解释：**

| 代码 | 作用 |
|------|------|
| `card.querySelector(".delete-btn")` | 在当前卡片内部查找删除按钮（而不是在整个页面中查找） |
| `deleteMusic(item.id)` | 调用我们马上要写的删除函数，传入这条数据的 ID |

### 3. 写删除函数

在 `createCard` 函数之后、`renderCards` 函数之前，添加 `deleteMusic` 函数：

```javascript
// ====== 删除曲目的函数 ======
function deleteMusic(id) {
  // 步骤1：向用户确认（防止误删）
  const confirmed = confirm("确定要删除这首曲目吗？此操作不可撤销。");

  if (!confirmed) {
    return;  // 用户点了"取消"，什么都不做
  }

  // 步骤2：从数据数组中移除
  // 方法：找到 id 匹配的数据项的索引，然后 splice
  const index = musicData.findIndex(function(item) {
    return item.id === id;
  });

  if (index !== -1) {          // -1 表示没找到（理论上不会发生）
    musicData.splice(index, 1);  // splice(起始位置, 删除个数)
  }

  // 步骤3：重新渲染页面
  renderCards(musicData);

  // 步骤4：在控制台输出日志
  console.log(`🗑 已删除 ID=${id} 的曲目，当前共 ${musicData.length} 首`);
}
```

**逐行解释：**

| 代码 | 作用 |
|------|------|
| `confirm("...")` | 浏览器内置的确认对话框。返回 `true`（用户点确定）或 `false`（用户点取消） |
| `musicData.findIndex(...)` | 在数组中查找满足条件的元素的**索引**（位置编号，从 0 开始）。找不到返回 `-1` |
| `function(item) { return item.id === id; }` | `findIndex` 的回调函数——对数组中的每个元素执行这个判断，第一个返回 `true` 的就是我们要找的 |
| `musicData.splice(index, 1)` | 从数组中删除元素。`index` 是起始位置，`1` 是删除个数。`splice` 会直接修改原数组 |
| `renderCards(musicData)` | 重新渲染——和一键添加后同样的策略。先清空网格，再根据新数组创建全部卡片 |

## 设计讨论：为什么用"全量重新渲染"而不是"只删除一个 DOM"？

在这个步骤中，删除数据后我们调用了 `renderCards(musicData)`——这会把所有卡片删掉再重新创建。有同学可能会问：能不能只删除被点击的那一个卡片元素？

**两种方案对比：**

| | 方案 A：全量重新渲染（我们用的） | 方案 B：只删除单个 DOM |
|---|---|---|
| 代码复杂度 | 简单——调用已有的 `renderCards` 就行 | 较复杂——需要找到对应的卡片元素并 `remove()` |
| 数据一致性 | 100% 一致——页面就是数据的精确反映 | 可能不一致——如果数组改对了但 DOM 删错了，就会出现偏差 |
| 性能 | 数据量大时稍慢（几百条以上会感觉到） | 更好，因为只操作一个元素 |
| 适用场景 | 数据量小的项目、原型阶段 | 数据量大的应用 |

对于这个项目（收藏一般不会超过几十条），"全量重新渲染"是更好的选择——代码简单、不容易出错。

> 这个决策思维叫做**权衡（trade-off）**。实际工作中，没有哪个方案是"绝对正确"的——你需要根据场景选择代码复杂度、性能、维护性之间的平衡。

## 这一步的常见错误

### 错误 1：点击删除按钮没有反应
**原因 1**：`deleteBtn.addEventListener` 放在了错误的位置——比如放在 `return card` 之后。
**解决**：JavaScript 是顺序执行的。`return` 之后的代码不会执行。确认事件绑定在 `return card;` 之前。

**原因 2**：`card.querySelector(".delete-btn")` 返回了 `null`。
**解决**：检查 `innerHTML` 中的按钮是否有 `class="delete-btn"`。另外注意 `querySelector` 的选择器语法——class 选择器以 `.` 开头：`.delete-btn`。

### 错误 2：删除后卡片消失了，但刷新页面又出现了
**原因**：目前数据只存在内存中（`musicData` 数组）。刷新页面后，`musicData` 恢复为初始的 6 条预设数据。这是预期行为——我们会在后面的步骤中添加 localStorage 来持久化数据。

### 错误 3：删除按钮被点击后，旁边的卡片也被删掉了
**原因**：`deleteBtn.addEventListener` 中的 `deleteMusic` 调用时传入了错误的 ID。
**解决**：确认传入的 ID 来自 `item.id`（闭包变量），而不是某次循环后变化的变量。在 `createCard` 函数内部，`item` 是每次调用时传入的参数——它是独立的作用域，不会被后面的调用覆盖。

### 错误 4：`splice` 和 `slice` 搞混了
**现象**：写了 `musicData.slice(index, 1)`，但数组没有变化。
**原因**：`slice` 返回一个新数组，不修改原数组。`splice` 直接修改原数组。
**解决**：删除元素用 `splice`（有 p），复制片段用 `slice`。

> 记忆技巧：`splice` 中的 **p** = **permanent**（永久的）——它会永久修改原数组。
