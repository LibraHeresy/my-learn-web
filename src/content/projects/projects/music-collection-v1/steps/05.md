# 步骤 4：JavaScript 数据与渲染——让卡片"活"起来

---

## 这一步在做什么

用 JavaScript 创建一个数据数组（包含预设的几首曲目信息），然后写一个函数把这些数据"翻译"成页面上的卡片。这是整个项目最关键的一步——迈过这道坎，你就理解了"数据驱动页面"的基本范式。

---

## 为什么这一步很重要

这是前端开发中最核心的思维转变：

**之前你的做法（静态页面）：** 在 HTML 中手写每个 `<div>`、每个 `<h3>`、每个 `<p>`。内容是写死在 HTML 里的。

**现在你要做的（动态渲染）：** 数据存在 JavaScript 的数组里，然后用循环 + DOM 操作把数据变成 HTML 元素。内容是"活"的——改数据就改页面。

在真正的 Web 应用中，数据从来不是手写在 HTML 里的。它们来自数据库、来自 API、来自用户输入。你在这一步学会的是：**如何把"数据结构"翻译成"页面结构"**。

---

### 3. 写渲染函数

在数据数组下面，写一个函数：接收一首曲目的数据，返回一个完整的卡片 HTML 元素：

```javascript
// ====== 创建单张卡片的函数 ======
// 参数：item —— 一个包含曲目信息的对象
// 返回值：一个完整的 .music-card DOM 元素
function createCard(item) {
  // 步骤1：创建卡片容器 <div class="music-card">
  const card = document.createElement("div");
  card.className = "music-card";
  // 把 id 存到 DOM 元素上，后面删除时可以知道删的是哪个
  card.dataset.id = item.id;

  // 步骤2：用 innerHTML 填充卡片内容
  // 使用模板字符串（反引号 ``）可以方便地插入变量和多行 HTML
  card.innerHTML = `
    <img
      class="card-cover"
      src="${item.cover}"
      alt="${item.title}"
      onerror="this.src='data:image/svg+xml,<svg xmlns=\\'http://www.w3.org/2000/svg\\' width=\\'400\\' height=\\'300\\'><rect fill=\\'%23E8D5C4\\' width=\\'400\\' height=\\'300\\'/><text x=\\'200\\' y=\\'160\\' text-anchor=\\'middle\\' fill=\\'%23987A5E\\' font-size=\\'48\\'>🎵</text></svg>'"
    >
    <div class="card-info">
      <h3>${item.title}</h3>
      <p class="composer">${item.composer}</p>
      <span class="tag">${item.period}</span>
      <button class="delete-btn">🗑 删除</button>
    </div>
  `;

  return card;
}
```

**逐行解释：**

| 代码 | 作用 |
|------|------|
| `document.createElement("div")` | 创建一个新的 HTML 元素（此时只存在内存中，还没放到页面上） |
| `card.className = "music-card"` | 给元素添加 class，让它能应用我们在 CSS 中写的样式 |
| `card.dataset.id = item.id` | `dataset` 是 DOM 元素上存放自定义数据的地方。`dataset.id` 对应 HTML 中的 `data-id` 属性。后面删除时可以通过 `card.dataset.id` 知道这是哪条数据 |
| `` card.innerHTML = `...` `` | 用模板字符串填充卡片内部的 HTML。`${}` 是变量插入语法 |
| `onerror="..."` | 图片加载失败时的备用方案——显示一个音乐符号 SVG |

### 4. 写"渲染全部卡片"的函数

```javascript
// ====== 渲染所有卡片到页面 ======
function renderCards(dataArray) {
  // 步骤1：获取卡片容器
  const grid = document.getElementById("cardGrid");

  // 步骤2：清空容器（防止重复渲染）
  grid.innerHTML = "";

  // 步骤3：遍历数据数组，为每条数据创建卡片并添加到容器
  dataArray.forEach(function(item) {
    const card = createCard(item);       // 调用上面写的 createCard
    grid.appendChild(card);              // 把卡片添加到网格容器中
  });
}
```

**逐行解释：**

| 代码 | 作用 |
|------|------|
| `grid.innerHTML = ""` | 清空容器。如果不先清空就再次渲染，卡片会重复堆叠 |
| `dataArray.forEach(...)` | 遍历数组中的每一项。`forEach` 接收一个函数，数组中的每个元素都会调用一次这个函数 |
| `grid.appendChild(card)` | 把创建好的卡片元素添加到页面上的网格容器中。`appendChild` 会把它加为容器的最后一个子元素 |

### 5. 页面加载时自动渲染

在文件末尾添加一行，让页面一加载就显示预设的数据：

```javascript
// ====== 页面加载时渲染初始数据 ======
renderCards(musicData);
```

### 6. 保存并查看

按 `Ctrl+S` 保存 `script.js`。在浏览器中刷新页面。

## 你应该看到什么

卡片网格不再是一片空白！现在你应该看到：
- 6 张音乐收藏卡片，排列成响应式网格（宽屏 3 列，中等屏 2 列，窄屏 1 列）
- 每张卡片包含封面图片、曲名、作曲家名字、风格标签、"删除"按钮
- 鼠标悬停在卡片上时卡片会微微上浮
- 鼠标悬停在删除按钮上时，按钮变成红色

虽然"删除"按钮现在还不起作用（点击不会有反应），筛选按钮也还没接通逻辑——这些我们会在后面的步骤中实现。

## 这一步的常见错误

### 错误 1：页面仍然是空白的，没有卡片
**原因 1**：忘记调用 `renderCards(musicData)`。
**解决**：确认 `script.js` 最后有这一行。

**原因 2**：浏览器控制台有报错（按 F12 查看）。
**解决**：最常见的报错是 `Cannot read property 'appendChild' of null`——这意味着 `document.getElementById("cardGrid")` 返回了 `null`。检查 `index.html` 中是否有 `id="cardGrid"` 的元素。

**原因 3**：`<script src="script.js">` 放在了 `<head>` 中，导致 JS 执行时 HTML 元素还没加载。
**解决**：确认 `<script>` 标签在 `</body>` 之前。

### 错误 2：图片没有显示
**原因**：`picsum.photos` 在某些网络环境下可能无法访问。
**解决**：换成其他图片链接试试，或者直接用课程中的占位图片。你也可以先不管图片——卡片的其他内容（曲名、作曲家、标签）应该还是能看到的。

### 错误 3：卡片样式不对（看起来不像卡片）
**原因 1**：CSS 中 `class="music-card"` 的样式没有生效。确认 `style.css` 被正确关联（在 `<head>` 中有 `<link>` 标签）。
**原因 2**：CSS 文件中的 `.music-card` 和 JS 中创建的 `card.className = "music-card"` 拼写不一致。

### 错误 4：模板字符串中的变量显示为 `${xxx}` 而不是实际值
**原因**：使用了普通引号 `'...'` 或 `"..."` 而不是反引号 `` `...` ``。
**解决**：模板字符串必须用反引号（键盘上 `Tab` 键上面那个键，在英文输入法下按）。普通引号不会解析 `${}` 语法。

### 错误 5：`onerror` 中的 SVG 不显示
**原因**：引号嵌套问题——SVG 中有单引号，和 `onerror` 的单引号冲突了。
**解决**：在 `onerror` 属性中使用 **HTML 实体** `&apos;` 代替内部单引号，或者把 `onerror` 属性中的引号改为双引号。一般来说，建议不要在 `innerHTML` 中写 `onerror`，而是用 JS 监听图片的 `error` 事件——但为了保持步骤简单，我们先这样写。如果遇到问题，可以先删掉 `onerror` 部分。
