# 语义化标签 — 给页面一个清晰的结构

:::analogy
语义化标签就像给不同的房间挂门牌——厨房、卧室、书房，而不是全叫"房间1"。`<header>`、`<main>`、`<footer>` 让浏览器和搜索引擎一眼看懂你的页面结构，而不需要猜。
:::


:::prerequisite
**本节你需要知道这些词：**

- **div 与 span**：`<div>` 是块级容器（独占一行），`<span>` 是内联容器（不换行）——第六节"div 与 span"中学过。
- **class 与 id**：`class` 给元素贴分类标签（可重复），`id` 给元素唯一编号（不重复）——第六节中学过。
- **列表**：`<ul>`（无序列表）、`<ol>`（有序列表）——第四节"列表"中学过。
- **图片与链接**：`<img>` 插入图片，`<a>` 创建链接——第五节"图片与链接"中学过。
:::

:::explain{title="问题：用 div 搭的页面，浏览器看得懂吗？"}
上一节你学会了用 `<div>` 分组。但 `<div>` 有一个根本问题：它没有"含义"。

看这段代码：

```html
<div class="header">
  <h1>网站标题</h1>
  <div class="nav">首页 | 关于 | 联系</div>
</div>
<div class="main">
  <div class="post">
    <h2>文章标题</h2>
    <p>文章内容...</p>
  </div>
</div>
<div class="footer">
  <p>版权信息</p>
</div>
```

你（人类）看到 `class="header"` 知道这是页头。但浏览器、搜索引擎、屏幕阅读器看到的是：三个 `<div>`，不知道谁是谁。对于百度来说，你的导航链接和文章正文"地位一样"——不知道该重点索引什么。对于盲人用户来说，屏幕阅读器逐一读出 div 里的内容——不知道从哪里开始是"主要内容"。

这就是"div 汤"（div soup）——全是 div，没有语义。你需要的是**有名字的标签**。
:::

:::explain{title="语义化标签 — 每个标签都有自己的名字"}
HTML5 引入了一组语义化标签，替换掉那些只有 `class` 名字的 `<div>`：

```html
<body>
  <!-- header：页头区域 —— 放网站 Logo、标题、导航 -->
  <header>
    <h1>网站标题</h1>
    <!-- nav：导航菜单 —— 专门用来放跳转链接组 -->
    <nav>
      <a href="/">首页</a>
      <a href="/about">关于</a>
      <a href="/contact">联系</a>
    </nav>
  </header>

  <!-- main：页面核心内容 —— 每个页面只能有一个 main -->
  <main>
    <!-- section：一个内容区块，通常带标题 -->
    <section>
      <h2>最新文章</h2>
      <!-- article：一篇独立、可分发的内容（如博客文章、评论） -->
      <article>
        <h3>文章一</h3>
        <p>内容摘要...</p>
      </article>
      <article>
        <h3>文章二</h3>
        <p>内容摘要...</p>
      </article>
    </section>

    <section>
      <h2>关于本站</h2>
      <p>一段介绍文字。</p>
    </section>
  </main>

  <!-- footer：页脚区域 —— 放版权、联系信息、底部导航 -->
  <footer>
    <p>&copy; 2026 我的网站</p>
  </footer>
</body>
```

看名字就知道：`<header>` 是头，`<nav>` 是导航，`<main>` 是主体，`<section>` 是区块，`<article>` 是文章，`<footer>` 是脚。不需要 `class` 名字来提示，标签本身就在说话。
:::

:::explain{title="section vs article — 怎么区分？"}
这是语义化标签中最容易混淆的一对：

- `<section>` — 页面上的一个**内容区块**，通常带标题。是页面布局的一部分，不能脱离页面独立存在。例如："今日推荐""最新评论""关于我们"。
- `<article>` — 一篇**独立完整**的内容，可以单独分发。例如：一篇博客文章、一条新闻、一条用户评论——就算把这篇文章从页面中切出来放到别的地方，它依然是一篇完整的"文章"。

判断标准：如果某块内容可以单独分享给别人看而不丢失上下文，那就是 `<article>`；如果它只是页面布局中的一个区域，离开页面就失去意义，那就是 `<section>`。
:::

:::explain{title="语义化的三重价值"}
这三个"看不见的好处"才是语义化标签的真正意义：

1. **SEO（搜索引擎优化）**：百度/Google 看到 `<main>` 就知道核心内容在哪，看到 `<nav>` 就知道这是导航链接不是正文，看到 `<article>` 就知道这是一篇文章可以索引。用 `<div>` 的页面，搜索引擎猜不到。

2. **无障碍访问（Accessibility）**：盲人用户用屏幕阅读器浏览网页。阅读器读到 `<nav>` 会提示"导航区域"，读到 `<main>` 会提示"主要内容开始"，用户可以跳过导航直接听正文。纯 `<div>` 页面，阅读器只能从头读到尾。

3. **代码可读性**：六个月后你回来看自己的代码，`<header>` 和 `<footer>` 一眼认出，`<div class="header">` 和 `<div class="footer">` 需要读 class 名字才能分辨。你的队友也一样。
:::

:::explain{title="常见错误：每页多个 main"}
`<main>` 在一个 HTML 页面中**只能出现一次**。它是页面的核心内容区域——就像一个舞台只能有一个"主舞台"。如果你需要多个区块，用 `<section>` 放在 `<main>` 里面。另外，`<main>` 不能放在 `<article>`、`<aside>`、`<header>`、`<footer>` 或 `<nav>` 里面——它可以放在 `body` 内的普通容器（如 `<div>`）中。
:::

:::example{title="看例子"}
下面的代码用语义化标签构建了一个网站页面，注意和用 `<div>` 的版本对比：

```html
<!-- header：页头 —— 放网站标题和导航 -->
<header>
  <h1>古典音乐鉴赏</h1>
  <!-- nav：导航菜单 —— 放跳转链接 -->
  <nav>
    <a href="#">首页</a> |
    <a href="#">设计师</a> |
    <a href="#">项目</a>
  </nav>
</header>

<!-- main：页面核心内容 —— 每页只有一个 -->
<main>
  <!-- section：内容区块，带标题 -->
  <section>
    <h2>今日推荐</h2>
    <p>今日推荐作品：《降E大调夜曲》</p>
  </section>

  <section>
    <h2>本周精选</h2>
    <!-- article：独立文章，可以单独分享 -->
    <article>
      <h3>张三：巴洛克的最后一位大师</h3>
      <p>文章正文...</p>
    </article>
    <article>
      <h3>如何听懂赋格？</h3>
      <p>文章正文...</p>
    </article>
  </section>
</main>

<!-- footer：页脚 —— 放版权和联系信息 -->
<footer>
  <p>&copy; 2026 代码阶段</p>
</footer>
```

虽然默认样式和 `<div>` 几乎一样，但这些标签自带"身份信息"——搜索引擎、屏幕阅读器、未来的你都能一眼看懂页面结构。
:::

:::recap
这一节你学会了用"有名字的标签"搭建页面结构——`<header>` 是页头，`<nav>` 是导航栏，`<main>` 是主体内容（每页只能有一个），`<section>` 是内容区块（带标题的页面分区），`<article>` 是独立文章（可以单独分发），`<footer>` 是页脚。语义化标签对 SEO、无障碍访问和代码可读性都有直接好处。对比纯 `<div>` 的"div 汤"，语义化标签让你的页面结构一目了然。现在你搭出来的网页不再是"一堆 div"，而是一个分工明确、井井有条的页面了。
:::
