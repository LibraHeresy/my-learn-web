# HTML 文档结构 — 了解网页的标准格式

:::analogy
每个网页都有一个标准结构，就像每封信都有抬头、正文和落款——`DOCTYPE` 是"这是一封信"的声明，`head` 是信封信息，`body` 是信纸内容。你不写这些不是不行，但收信的人（浏览器）可能会误解。
:::


:::prerequisite
**本节你需要知道这些词：**

- **标签（tag）**：用尖括号包裹的标记，如 `<h1>`、`<p>`，成对出现——上一节"认识 HTML"中学过。
- **开始标签与结束标签**：`<h1>` 开始，`</h1>` 结束，中间放内容。
:::

:::explain{title="问题：一个页面只有 `<h1>` 和 `<p>` 够吗？"}
上一节你直接在编辑器里写了 `<h1>` 和 `<p>`，预览区就显示了。那为什么还要学"文档结构"？

设想你拿到一封信，上面直接写"你好，我很好。再见。"——没有称呼、没有署名、没有日期。你大概能看懂，但你会困惑：这是谁写给谁的？什么时候写的？

HTML 页面也一样。你不写 `<!DOCTYPE html>`、`<html>`、`<head>`、`<body>`，浏览器**可能**还是能显示——但会遇到隐藏问题：中文乱码、手机上看布局错乱、搜索引擎搜不到你的页面。结构不是"能不能用"的问题，而是"正不正常"的问题。
:::

:::explain{title="HTML 文档的标准骨架"}
就像写信有固定格式，HTML 页面也有自己的骨架：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>我的页面标题</title>
</head>
<body>
  <h1>你好，世界！</h1>
  <p>这是页面上可见的内容。</p>
</body>
</html>
```

这就是一份"标准设计图"——每一部分都有固定的位置和意义。
:::

:::explain{title="逐行读懂这个结构"}
`<!DOCTYPE html>` — 声明"这是 HTML5 文档"。就像文件封面写着"版本 2.0"，浏览器看到这行就知道用什么规则来解析页面。不写的话，浏览器会进入"怪异模式"——用旧规则渲染，可能导致布局错乱。

`<html lang="zh-CN">` — 整个文档的根元素。`lang` 属性告诉浏览器和搜索引擎页面是什么语言。屏幕阅读器会根据它切换发音，搜索引擎会根据它判断目标用户。

`<head>` — 页面"元信息"区，不显示在页面上，但决定了页面如何被理解：
- `<meta charset="UTF-8">` — **必须写！**声明字符编码。不写的话，中文可能显示为乱码（??????）。
- `<meta name="viewport" ...>` — 告诉手机浏览器正确缩放，没有这行，手机上的网页会缩成米粒大小。
- `<title>` — 浏览器标签页上显示的文字，也是搜索引擎结果显示的标题。

`<body>` — 页面"正文"，你写过的所有可见内容（`<h1>`、`<p>` 等）都放在这里面。浏览器只渲染 `<body>` 里的内容。
:::

:::explain{title="head 中的其他重要元素"}
`<head>` 区还可以包含更多"幕后配置"：

```html
<head>
  <!-- 链接 CSS 样式文件 -->
  <link rel="stylesheet" href="style.css">
  <!-- 网站的图标（favicon） -->
  <link rel="icon" href="favicon.ico">
  <!-- SEO 描述：搜索引擎显示的摘要文字 -->
  <meta name="description" content="一个学习编程的网站">
</head>
```

虽然 `<head>` 里的内容不直接显示在页面上，但它像产品说明书上的规格标注一样——决定了页面如何被理解和渲染。
:::

:::explain{title="常见错误：缺少结构的页面会怎样？"}
试着想象一个"没骨架"的页面：

```html
<!-- 没有 DOCTYPE、html、head、body —— 直接写内容 -->
<h1>标题</h1>
<p>一段文字。</p>
<p>另一段，里面有一个特殊字符：中文。</p>
```

浏览器可能会显示——但：
1. **没有 meta charset**：中文可能变乱码（指定了 UTF-8 才安全）
2. **没有 viewport**：手机上字小到看不清
3. **没有 title**：标签页显示的是文件名或网址，丑陋且不专业
4. **没有 lang**：屏幕阅读器用英语读中文页面，障碍用户无法正常访问

**现实工作中的代价：** 搜索引擎看不到 `<title>` 和 `<meta description>`，你的页面在搜索结果里排名靠后，用户根本找不到你。
:::

:::explain{title="HTML 注释：给自己留便条"}
写代码时经常想给自己留个记号——这段是干什么的、为什么这样写——但又不想让它显示在页面上。HTML 提供了**注释（Comment）**：

```html
<!-- 这是注释，不会显示在页面上 -->
<p>这行会正常显示</p>
```

注释以 `<!--` 开头，以 `-->` 结尾，中间的内容会被浏览器完全忽略。**快捷键：** 选中代码按 `Ctrl + /`（Mac: `Cmd + /`），编辑器自动添加或移除注释。

**注释能做什么：**
- 标记代码区块，方便以后维护（"这一段是导航栏"）
- 暂时隐藏某些内容（调试时很有用）
- 给合作的队友留下说明

```html
<!-- 导航栏区域 -->
<nav>
  <a href="/">首页</a>
  <!-- 暂时隐藏"关于我们"，下个月上线
  <a href="/about">关于我们</a>
  -->
</nav>
```
:::

:::example{title="看例子"}
现在你编辑器中的代码是放在 `<body>` 里的。但这个教学平台已经帮你写好了 `<head>` 和 `<body>` 的框架——这就是为什么你只需要写内容部分的代码。

当你未来自己创建一个 `.html` 文件时，记得先写完整结构：

```html
<!-- DOCTYPE：告诉浏览器"这是 HTML5 页面" -->
<!DOCTYPE html>
<!-- html 标签：整个页面的根容器，lang 声明语言 -->
<html lang="zh-CN">
<!-- head：幕后配置——字符编码、标题、视口设置 -->
<head>
  <!-- charset：防止中文乱码 -->
  <meta charset="UTF-8">
  <!-- viewport：手机端正确缩放 -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <!-- title：标签页上显示的文字 -->
  <title>我的音乐博客</title>
</head>
<!-- body：所有可见内容都在这里 -->
<body>
  <!-- 你的内容写在这里 -->
</body>
</html>
```
:::

:::recap
这一节你学会了网页的"标准格式"——`<!DOCTYPE html>` 开头声明文档类型，`<head>` 放幕后信息（编码、标题、视口），`<body>` 放所有看得见的内容。你还学会了用 `<!-- -->` 写注释给自己留便条，按 `Ctrl + /` 就能快速切换。结构不好的页面可能有中文乱码、手机上错位、搜索引擎找不到等隐藏问题——现在你打开任何一个网页按 F12，都能看懂它的骨架结构了。
:::
