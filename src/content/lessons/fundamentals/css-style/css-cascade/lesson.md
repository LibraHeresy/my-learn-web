# 层叠与优先级 — 当多个规则"打架"时谁说了算？

:::analogy
当多条 CSS 规则同时指向一个元素时，浏览器按一套优先级规则决定谁胜出——就像公司里，直属上级的指令优先于隔壁部门的通知；CEO 的指令（ID 选择器）又优先于部门经理（类选择器）。越具体的规则越有话语权。
:::

:::prerequisite
**本节你需要知道这些词：**

- **CSS 选择器的三种基本类型**：元素（`h1`）、类（`.card`）、ID（`#title`）——上一节刚学过
- **CSS 规则的基本结构**：`选择器 { 属性: 值; }`
- **浏览器 DevTools**：F12 打开，在 Elements 面板可以看到每个元素的样式
:::

:::explain{title="本节目标"}
学完本节，你将能够：
- 解释为什么同一个元素可能被多条规则影响
- 按权重计算规则判断哪条规则最终胜出
- 理解 `!important` 的作用，以及为什么平时不该用它
- 用 DevTools 的样式面板诊断"样式不生效"的问题
:::

:::explain{title="一、当两条规则指向同一个元素，会发生什么？"}
这是每个 CSS 学习者早晚会遇到的情况。看这个例子：

```html
<p class="highlight" id="special">这段文字到底是什么颜色？</p>
```

三条 CSS 规则都指向这段文字，但写了三个不同的颜色：

```css
p               { color: gray; }      /* 规则A：所有段落灰色 */
.highlight      { color: blue; }      /* 规则B：带 highlight 类的蓝色 */
#special        { color: red; }       /* 规则C：id 为 special 的红色 */
```

**这段文字最终是红色。** 为什么？不是谁后写谁赢，也不是谁先写谁赢——是**权重最高的赢**。`#special` 是 ID 选择器，权重 100，远远高于 `.highlight`（权重 10）和 `p`（权重 1）。

**CSS 的"C"就是"Cascading"（层叠），指的是当多条规则冲突时，浏览器按优先级"叠"出最终效果。**
:::

:::explain{title="二、权重的计算规则——三列数字比大小"}
权重可以看作三列数字：(ID数, 类数, 元素数)。从左到右比，先比第一列，同分再看第二列，以此类推：

```css
/* 格式：(ID数, 类数, 元素数) */

p                          /* (0, 0, 1) = 权重 1         ——最低 */
.card p                    /* (0, 1, 1) = 权重 11        ——覆盖上面 */
.card p.highlight          /* (0, 2, 1) = 权重 21        ——覆盖上面 */
#main .card p              /* (1, 1, 1) = 权重 111       ——覆盖上面 */
#main #content p           /* (2, 0, 1) = 权重 201       ——覆盖上面 */
```

**关键规则：**
- ID 是"百位"：每个 ID 选择器加 100
- 类/伪类/属性是"十位"：每个 `.class`、`:hover`、`[attr]` 加 10
- 元素/伪元素是"个位"：每个 `h1`、`div`、`::before` 加 1
- 通配符 `*` 权重为 0（不参与竞争）
- 权重相同时，后写的覆盖先写的

**常见疑惑：** `11 > 1`，所以 `.card p` 覆盖 `p`。`21 > 11`，所以 `.card p.highlight` 覆盖 `.card p`。`101 > 21`，所以 `#main p` 覆盖 `.card p.highlight`。把数字写出来比大小，永远不会搞错。
:::

:::explain{title="三、!important —— 紧急按钮，请勿日常使用"}
`!important` 写在属性值后面，会让这条声明**无视权重直接胜出**：

```css
p {
  color: blue !important;   /* 即使其他规则权重再高，这条也会胜出 */
}

#main .card p.highlight {
  color: red;               /* 权重 121，但被上面的 !important 覆盖了 */
}
```

**为什么不能用？** `!important` 像在安静的办公室里放鞭炮——它能吸引所有注意力，但破坏了正常的秩序。一旦用了第一次，很快就需要用更多 `!important` 去覆盖之前的 `!important`，最后代码变得无法维护。

**只有两种情况下应该用 `!important`：**
1. 覆盖你无法修改的第三方样式（如 UI 组件库）
2. 工具类（如 `.hidden { display: none !important; }`）——"无论如何都要隐藏"
:::

:::explain{title="四、层叠的全流程——浏览器到底怎么决定？"}
当一个元素被多条规则影响时，浏览器的决策流程是：

**第一步：来源与 `!important`（最高优先级）**
1. 用户代理（浏览器默认样式）：最低
2. 用户样式（用户在浏览器设置里设的）：中等
3. 作者样式（你写的 CSS）：较高
4. 作者样式中的 `!important`：最高

**第二步：选择器权重**
在同一个来源层级里，权重高的规则覆盖权重低的。

**第三步：书写顺序**
权重相同，来源相同，后写的覆盖先写的。

这就是完整的"Cascading"（层叠）过程——层层筛选，最终只有一个值胜出。
:::

:::example{title="看例子"}
下面的代码故意写了冲突的规则。打开 CSS 选项卡，看到四条规则都指向了 `<p>` 元素：

```css
/* 规则1：权重 (0,0,1) = 1 */
p { color: gray; }

/* 规则2：权重 (0,1,1) = 11 —— 覆盖规则1 */
.card p { color: #3D2B1F; }

/* 规则3：权重 (0,2,1) = 21 —— 覆盖规则2 */
.card p.highlight { color: #8B2E2E; }

/* 规则4：权重 (1,0,0) = 100 —— 覆盖上面所有 */
#special { color: #C9A96E; }
```

在预览区看第三条卡片（带 `highlight` 类和 `special` id 的段落）——文字是金色（`#C9A96E`），因为 `#special` 的权重 100 最高。其他卡片的 `.highlight` 段落是暗红色（规则3），普通段落是深棕色（规则2）。
:::

:::example{title="常见错误——看看你踩过几个坑？"}
**错误 1：以为"后写的"总是赢**
```css
.highlight { color: blue; }   /* 这句先写 */
p { color: red; }             /* 这句后写，但权重只有 1，打不过上面的权重 10 */
```
只有权重相同时，"后写的"才覆盖"先写的"。权重不同时，权重高的赢，不管谁先写谁后写。

**错误 2：用 !important 调试**
```css
p {
  color: red !important;  /* ❌ 调试时的坏习惯 */
}
```
如果一条样式不生效，正确的做法是用 DevTools 找到哪条规则覆盖了它，然后调整选择器的权重——而不是粗暴地加 `!important`。

**错误 3：不理解"行内样式"的权重**
```html
<p style="color: green;" class="highlight" id="special">文字</p>
```
行内样式（写在 `style=""` 属性里的）权重相当于 (1,0,0,0)——比任何选择器都高。只有 `!important` 能覆盖行内样式。这就是为什么实际项目中几乎不用行内样式——它太难被覆盖了。

**错误 4：选择器写得过于具体**
```css
/* ❌ 权重太高，后面很难覆盖 */
body div.container section#main ul.list li.item a.link span.text {
  color: red;  /* 权重：1+1+(1+10)+(1+100)+1+(1+10)+1+(1+10)+1+1+(1+10)+1 = 很高 */
}
/* ✅ 保持选择器尽可能简单 */
.main .text { color: red; }
```
选择器不需要把 DOM 树的每一层都写出来。过长的选择器带来三个问题：权重过高难以覆盖、性能稍差、代码难读。
:::

:::explain{title="五、实际工作中你会怎么用？"}
在真实项目中，层叠和优先级的理解直接影响你的 CSS 架构决策：

- **全局样式**（reset、base）用元素选择器和低权重选择器，方便后续覆盖
- **组件样式**用单个类选择器（如 `.card`），权重为 10，恰好够用
- **组件变体**用双类选择器（如 `.card.featured`），权重为 20，覆盖基础样式
- **页面级特殊样式**才用 ID 选择器（如 `#hero`），权重 100，作为"最终裁决"
- **避免 `!important`**——如果你的 CSS 中出现了 5 个以上的 `!important`，说明架构需要重构

**一个实用的调试习惯：** 在 DevTools 的 Styles 面板里，被划掉的样式就是被更高权重覆盖的。旁边通常会显示覆盖它的选择器——这是理解层叠最快的方式。
:::

:::recap
回顾本节你学会的内容：
- **层叠的决策流程**：来源与 `!important` → 选择器权重 → 书写顺序
- **权重计算**：(ID数, 类数, 元素数)，从左到右比大小
- **ID > 类 > 元素**：100 > 10 > 1，权重相同时后写覆盖先写
- **`!important` 是紧急按钮**：无视权重直接胜出，但会破坏代码的可维护性
- **被划掉的样式**：DevTools 里带删除线的样式就是被更高权重覆盖的
- **原则**：选择器尽量简单，权重尽量低，代码才便于维护和修改

下一节你将学习过渡——让样式变化不再是瞬间跳变，而是像天亮一样平滑渐变。
:::
