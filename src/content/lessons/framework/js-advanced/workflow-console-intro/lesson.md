# 读懂浏览器的"错音提示" — 开发者控制台入门

:::music-analogy
每个音乐家都有一位"调音师"朋友——音不准时，调音器会告诉你偏差了多少。浏览器的**开发者工具控制台（Console）**就是你的调音器——代码出错时，它会精确告诉你哪一行、出了什么错。学会读错误信息，你就再也不怕"报错"了。
:::

:::explain{title="错误不是失败，是路标"}
写代码一定会遇到错误。即便是工作了 20 年的工程师，也天天看报错信息。区别在于：他们不慌张，而是**先看控制台**。
当你的 JS 不工作时，第一个动作不是盯着代码瞎猜——**先打开浏览器控制台**：
- Windows：按 `F12`，点击 "Console"（控制台）标签
- Mac：按 `Cmd + Option + J`
- 或者右键页面 → "检查" → "Console"
红色文字就是错误信息。**红色不可怕，可怕的是不读红字。** 就像一个音不准时你的耳朵会告诉你——控制台就是代码的"听力训练"。
:::

:::explain{title="读懂红字错误信息"}
每条错误通常包含三部分信息：
**1. 错误类型** — 告诉你"出了什么问题"：
- `ReferenceError: xxx is not defined` — 变量没声明就用了
- `TypeError: xxx is not a function` — 把不是函数的东西当函数调用了
- `SyntaxError: Unexpected token` — 语法错误，漏了括号或引号
**2. 文件名 + 行号** — 告诉你"在哪里出的错"：
- 例如 `at 3:15` 表示第 3 行第 15 个字符
**3. 错误消息** — 英文描述的具体原因
现在编辑器里的代码有 5 个故意埋下的错误。打开控制台，一个一个找出并修复它们！
:::

:::task{title="动手试试 ✨"}
::::step{purpose="学会打开控制台是所有前端调试的第一步。红色错误信息不是惩罚，而是路标——就像调音器告诉你哪根弦不准，它精确地指出错误类型和位置。" expected="控制台出现红色错误信息，包含错误类型（ReferenceError/TypeError）、文件名和行号。"}
打开浏览器控制台（F12），查看红色错误信息——第一条错误告诉你第几行出了什么错？
::::

::::step{purpose="ReferenceError 是最常见的错误类型——变量未定义。学会从错误信息中的行号定位代码，而不是盲目猜测，能大幅缩短调试时间。" expected="修复后再次运行，第一条红色错误消失，第二条错误出现——就像调音时修好一根弦后，下一根弦的问题才被听到。"}
根据第一条错误提示（document 拼写为 docuement），找到对应代码行并修复
::::

::::step{purpose="错误之间会互相掩盖——一个错误导致后续代码不执行。这就像交响乐中一个声部漏了，后面的乐手没法跟进去。逐个修复错音，直到所有声部和谐共鸣。" expected="控制台变干净（无红色错误），点击收藏按钮后卡片状态正常切换，消息文字正确显示。"}
继续修复剩余 4 个错误：querySelector 大小写 → 变量名不一致 → textContent 拼写错误 → innerHTML 大小写
::::

:::

:::hint{title="需要一点线索？"}
5 个错误的类型分别是：
1. `document` 拼写错误 — ReferenceError
2. `querySelector` 大小写错误 — TypeError
3. 变量名不一致（声明和使用的名字不同）
4. DOM 方法名拼写错误
5. DOM 属性名拼写错误
控制台会精确告诉你每一个错误的位置。耐心读完红字！
:::

:::listen-to
巴赫《赋格的艺术》— 赋格中每一个声部的进入和退出都有精确的时间点，就像控制台报出的每一行错误——精确、清晰、可追溯。当你逐个解决错误时，就像分析赋格声部一样，一次专注一个问题。
:::
