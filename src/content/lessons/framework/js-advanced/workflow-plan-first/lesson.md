# 先规划再动手 — 用注释画出你的"乐谱草稿"

:::music-analogy
指挥家在排练前一定会先通读总谱，标出曲式结构、调性变化和难点段落。写代码也一样——**先用注释画出"草图"，再填入真正的代码**。这就像排练前做案头工作：标注呈示部、展开部、再现部。先看清大局，再动手处理细节。
:::

:::explain{title="注释是你的\"排练笔记\""}
你已经学过 HTML、CSS、JS 的三种注释写法（`<!-- -->`、`/* */`、`//`）。现在我们要用注释做更重要的事——**规划代码结构**。
当你面对一个空白页面时，不要急着写代码。先写注释：
```html
<!-- 页面分为三个区域：
  1. 顶部标题区
  2. 中间卡片列表（3张卡片）
  3. 底部统计区
-->
```
这就像在乐谱上标注：呈示部、展开部、再现部。
:::

:::explain{title="好的注释写什么？"}
**写"意图"，不写"操作"**
❌ 不好的注释（描述你做了什么）：
`// 把 3 赋给 x`
`let x = 3;`
✅ 好的注释（解释为什么）：
`// 页面默认显示 3 张卡片（移动端一屏刚好够）`
`let cardCount = 3;`
✅ 规划型注释（先画结构，再填空）：
```html
<!-- 顶部区：标题 + 副标题 -->
<header>
  <h1>我的音乐收藏</h1>
  <p>记录那些打动我的旋律</p>
</header>
<!-- 主内容：3 列卡片网格 -->
<main>
  <!-- 每张卡片：封面图、曲名、作曲家、时期标签 -->
</main>
```
:::

:::task{title="动手试试 ✨"}
::::step{purpose="读懂别人（或自己以前）写的规划注释是团队协作的基础。就像拿到一份排练笔记，先理解指挥的标注，才知道每个段落该怎么处理。这一步训练你\"读注释→写代码\"的转换能力。" expected="页面出现标题、3张音乐卡片和底部统计信息——每个区域对应一组注释，结构清晰可见。"}
阅读三组 HTML 注释，理解页面结构（顶部标题区、中间卡片列表区、底部统计区），在每组注释下方填入对应的 HTML 标签
::::

::::step{purpose="CSS 注释帮你区分不同区域的样式，修改时能快速定位。就像在总谱上用不同颜色标注各声部的力度变化——视觉分区减少查找时间。" expected="标题居中并呈暗红色，卡片有米白背景和圆角边框，底部统计文字居中灰色显示。"}
在 CSS 中同样用注释分区规划，然后逐一写出顶部标题、卡片区域、底部统计区的样式
::::

::::step{purpose="在代码之前用注释列好步骤，就像排练前在乐谱上标记\"这里渐强\"\"那里放缓\"。养成这个习惯后，写复杂逻辑时思路不会断。" expected="点击顶部标题后，文字从\"我的音乐收藏\"随机变为\"每一段旋律都值得被收藏\"等口号之一。"}
在 JS 中先用注释规划逻辑步骤（获取元素 → 点击事件 → 随机替换），再填入代码：点击标题时随机切换一句口号
::::

::::step{purpose="querySelectorAll 返回 NodeList，其 .length 属性可以动态统计页面元素数量。这是数据统计的基础——后续框架中用响应式数据自动统计，底层原理相同。" expected="底部显示\"共 3 首收藏\"（数量随着卡片的增减自动变化）。"}
（挑战）用 querySelectorAll 获取所有卡片，计算数量并显示在底部统计区
::::

:::

:::recap
你学会了在写代码之前先用注释规划结构——HTML 注释划分页面区域，CSS 注释分好样式区块，JS 注释列出逻辑步骤。先画草图再填代码，让复杂任务变得可控。
:::
