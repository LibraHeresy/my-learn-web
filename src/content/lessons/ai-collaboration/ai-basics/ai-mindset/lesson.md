# 编程思维的进化

:::analogy
编程的进化就像交通工具的进化——从走路（手写汇编）到开车（高级语言）再到导航软件（Prompt）。你没变，但你对"目的地"的思考比重变大了，对"怎么踩油门"的思考比重变小了。
:::

:::prerequisite
你已经写过实际的 HTML、CSS、JS 代码，知道"从零敲代码"是什么体验。
:::

## 一、你的问题

你以前写代码是：想清楚逻辑 → 一行行敲出来 → 调试。现在有了 AI，你可以说一句话就得到代码。但问题是：你现在该做什么？如果 AI 替你写了代码，你的价值在哪里？你该把精力投在什么地方？

## 二、解决方案：把"怎么做"外包，把"做什么"和"为什么"抓在手里

编程经历过三次抽象飞跃。每一次，都是把"怎么做"自动化，把"做什么"和"为什么"留给人。

**第一层：机器码 / 汇编（1940s-1950s）**
你怎么做：`MOV AX, [0100h]`——告诉 CPU 把哪个寄存器的值搬到哪个内存地址。写一个 Hello World 要十几条指令。
你的精力花在哪：100% 在"怎么做"。

**第二层：高级语言（1960s-2010s）**
你怎么做：`console.log("Hello")`——编译器翻译成几百条机器指令。
你的精力花在哪：70% 在"做什么"（设计逻辑），30% 在"怎么做"（写具体语法）。

**第三层：Prompt 工程（2020s）**
你怎么做："写一个 Vue 3 组件，显示用户列表，包含加载状态和空状态提示。"
你的精力花在哪：95% 在"做什么"和"为什么"（需求理解、边界定义、质量判断），5% 在"怎么做"（审查和修正生成代码）。

:::explain{title="关键洞察：你的价值不是写代码，是做决定"}
每一层抽象都让写代码这件事变得更容易，但让"判断什么代码是对的"这件事变得更难——因为代码量大了，出错的概率大了，需要你判断的场景多了。AI 时代的前端开发者，不是不需要学 HTML/CSS/JS 了，而是更需要学——你得用这些知识去判断 AI 生成的东西对不对。
:::

**你的新工作流：**
```
之前：理解需求 → 设计结构 → 敲代码 → 调试 → 测试 → 上线
现在：理解需求 → 设计结构 → 向 AI 描述任务 → 审查 AI 输出 → 修改整合 → 测试（AI 辅助）→ 上线
```

敲代码的时间从 60% 降到了 10%。但是，"理解需求""设计结构""审查输出""判断对错"——这些比敲代码更难的事情——从 40% 变成了 90%。**AI 把体力活自动化了，脑力活全留给了你。**

## 三、常见错误

**错误 1：跳过审查直接复制。**
> AI 生成了一段 Vue 组件，看起来能跑 → 直接粘贴 → 三周后发现 props 类型校验根本没做。
你跳过了审查，等于跳过了你最重要的价值环节。

**错误 2：AI 写的代码看不懂也直接用。**
> "这段 `reduce` 嵌套 `filter` 的代码我不知道什么意思，但好像能用。"
这叫闭着眼睛开车。任何你不理解的 AI 代码，要么问 AI 解释清楚，要么不用。

**错误 3：让 AI 替你做设计决策。**
> "帮我设计这个页面的组件结构。"
AI 的设计是统计平均——"大多数项目这么做"。但你的项目有具体约束，AI 不知道。架构决策永远是你的事。

:::example{title="实战：体会角色转变"}
拿出你之前手写过的任何一个前端组件（比如第 5 章的卡片组件）。

**第一步：** 计时，你手动把它的 HTML 和 CSS 重写一遍，看要多久。写下你是如何思考的。

**第二步：** 用 AI 生成一个同类组件（"写一个卡片组件，包含图片、标题、描述、按钮"），看 AI 要多久。

**第三步：** 审查 AI 生成的组件。找出至少 3 处你需要修改的地方（语义化标签、无障碍属性、CSS 变量、响应式处理）。计时，你审查和修改花了多久。

你大概率会发现：AI 生成只需要 5 秒，但你的审查和修改需要 5 分钟。而这 5 分钟，就是你作为开发者不可替代的价值——AI 生产，你品控。
:::

## 四、实际工作中的场景

- **入职新公司：** Leader 让你给现有项目加一个搜索功能。AI 能帮你写搜索框组件和过滤逻辑，但"搜索结果按什么排序""搜索历史存在哪里""输入 300ms 后才触发还是立刻触发"——这些决策 AI 做不了，因为它们取决于你们项目的具体业务约束和用户体验标准。
- **技术方案评审：** 同事提出用 Vuex 管理状态，你觉得 Pinia 更合适。AI 可以帮你列出 Pinia 和 Vuex 的对比表，但最终选哪个——这取决于你们团队的技术栈历史、上手成本、长期维护的考量。AI 不在乎你们的项目明天是好是坏，你在乎。
- **性能优化：** 页面加载慢。AI 能帮你分析代码里哪些地方可能有性能瓶颈，但"某个优化值不值得做"——这取决于你们用户的设备分布、网络环境、以及产品发展的优先级。

:::task{title="从执行者到决策者"}
::::step{id="1"}
找一个你之前手写过的组件（或从第八章 Vue 练习里找一个），用 AI 重新生成一个功能相似的组件。
::::
::::step{id="2"}
对比你手写的版本和 AI 生成的版本。列出 AI 版本中至少 3 处需要你去修改的地方。
::::
::::step{id="3"}
写一段话："在这个组件中，哪些决策是 AI 做的（如 CSS 颜色值、DOM 结构）？哪些决策是我做的（如组件接口设计、props 命名、状态管理方式）？为什么我做的那部分比 AI 做的那部分更重要？"
::::
::::step{id="4"}
把你写的话分享给一个同学或同事，看他们是否认同你的分析。
::::
:::

:::recap
编程经历了三层抽象：汇编让你脱离机器码，高级语言让你脱离汇编，Prompt 让你脱离语法细节。AI 时代你的价值不在"能写多少代码"，而在"能判断什么代码是对的"。AI 负责生产，你负责品控。审查、决策、判断——这些才是你不可替代的核心能力。
:::
