# AI 能做什么、不能做什么

:::analogy
AI 像一个读过一亿本书但从没出过门的图书管理员。它什么都知道一点，但哪个答案对——你说了算。

:::

:::prerequisite
你需要用过至少一次 ChatGPT、Claude 或 Kimi 等 AI 对话工具。如果还没有，现在打开一个，随便问一个问题再回来。

:::

:::explain{title="一、你的问题"}
你打开 AI 工具，输入一句话，它秒回一大段。有时候精准得像读心术，有时候胡说八道。你不知道什么时候该信它，什么时候该怀疑。你需要的不是"用得越多越有感觉"，而是一套判断标准。
:::

:::explain{title="二、解决方案：AI 能力的三个圈"}
把 AI 的能力想象成三个同心圆：

**内圈——绝对擅长（可放心用）：**
- 生成样板代码。如"写一个 Vue 3 计数器组件"——这种任务在互联网上有几十万个样本，AI 输出质量极高。
- 解释已有代码。把看不懂的代码贴给它："这段代码在做什么？"——它从模式中提取意图的能力很强。
- 格式转换。如"把这段 jQuery 改成 Vue 3 写法"——源和目标都是已知模式。

**中圈——需要你验证（可用但不可盲信）：**
- 写正则表达式。AI 写的正则在正常输入下通过，但边界字符可能漏掉或误匹配。
- 写 CSS 动画。AI 能写出完整的关键帧，但 `ease-in-out` 还是 `cubic-bezier(0.4, 0, 0.2, 1)` 更合适，只有你的眼睛知道。
- 写 API 调用代码。正常流程没问题，但网络超时、并发冲突、竞态条件——这些异常路径经常被省略。

**外圈——不擅长（不要依赖它决策）：**
- 你的业务规则。AI 不知道你们公司订单满 200 减 30 但新人首单不参与满减。
- 你的架构决策。这个功能放哪个模块？AI 的建议是基于一万个无关项目的统计平均，不是你的具体情况。
- 安全关键代码。加密、认证、支付——任何 bug 都是灾难，AI 的统计式输出承担不了这个风险。

**这条规律可以帮你做任何判断**

越是"有标准答案且公开样本多"的任务，AI 越可靠。越是"需要你的具体情况才能判断"的任务，AI 越不可靠。每次不确定时，问自己：这件事在互联网上有几千个一模一样的需求吗？有，AI 行。没有，你来。
:::

:::example{title="常见错误——看看你踩过几个坑？"}
**错误 1：把 AI 的输出当成最终答案。**
> "帮我写一个用户认证系统" → 直接用 → 上线后发现 token 过期逻辑有漏洞。
正确做法：AI 的输出永远是初稿，你必须审查、测试、修改。

**错误 2：AI 答错了就认为 AI 不行。**
> "帮我写一个排序算法" → AI 生成了一个有 bug 的实现 → 放弃 AI。
正确做法：把 bug 喂回去，让 AI 修正。或者，换一个更具体的 Prompt 重新来。

**错误 3：用 AI 做它不擅长的事。**
> "帮我制定我们项目的技术选型方案" → AI 不了解你的团队、历史、约束，它的建议跟随机抽签差不多。
正确做法：技术选型是你和团队的事。AI 最多帮你列出各方案的优缺点。

**实战：三个测试，建立你的判断坐标系**

打开 AI 工具，依次做这三个测试。每个测试都用纸笔记下你的观察。

**测试 1（内圈）：** "用 HTML + CSS 写一个价格卡片，原价 199 元，现价 99 元，折扣标签用红色背景白字。"
观察：代码质量如何？有没有遗漏细节？
结论：样板代码任务——AI 表现如何？

**测试 2（中圈）：** 把你之前写过的一段代码贴给 AI："解释这段代码的逻辑，有没有可以优化的地方？"
观察：AI 的理解准确吗？优化建议合理吗？有没有它没注意到的细节？
结论：需要验证的任务——你发现了哪些 AI 的盲区？

**测试 3（外圈）：** "我有个在线商城，用户下单后要根据收货地址自动计算运费。帮我设计运费计算规则。"
观察：AI 的回答是具体的还是模糊的？它有没有追问你的业务细节？列出的规则有没有重大遗漏？
结论：需要你具体情况的任务——AI 的回答有多大比例是"正确的废话"？

三个测试做完，你就有了切身体感，而不是听别人说"AI 很强"或"AI 很蠢"。
:::

:::explain{title="四、实际工作中你会怎么用？"}
- **日常开发：** 同事让你写一个表单组件。你用 AI 生成 HTML 结构和基础 CSS，然后自己调整字段顺序、错误提示文案、无障碍属性。AI 写 70% 的代码量，你做 100% 的重要决策。
- **Code Review：** PR 里有一段复杂的正则表达式。你贴给 AI："解释这个正则在匹配什么，有没有可能误匹配？"AI 帮你理解代码，但合不合入——你来判断。
- **接手老项目：** 前任留下的代码没有注释。你把一个 200 行的函数贴给 AI："逐段解释这个函数做了什么。"AI 帮你快速读懂，但重构方案——你来设计。

:::

:::task{title="建立你的 AI 判断力坐标系"}
::::step{id="1"}
打开 AI 工具，做测试 1（价格卡片）。把 AI 生成的代码复制下来，标注出哪些地方你觉得合理、哪些地方需要改进。
::::
::::step{id="2"}
做测试 2（解释你的代码）。对比 AI 的解释和你自己的理解，找出至少一处 AI 没说对或没说全的地方。
::::
::::step{id="3"}
做测试 3（运费规则设计）。读 AI 的回答，用红笔划掉所有"听起来对但没有实际用处"的内容，看剩多少真正有价值的部分。
::::
::::step{id="4"}
总结：在你的日常工作中，哪些任务属于内圈（可放心用 AI）、哪些属于中圈（需验证）、哪些属于外圈（不要依赖 AI）？列一个清单。
::::
:::


:::recap
AI 的能力分三圈：内圈（样板代码、解释代码、格式转换）可放心用；中圈（正则、CSS、API 调用）需要你验证；外圈（业务规则、架构决策、安全代码）不要依赖 AI。判断标准只有一条：这件事在互联网上有几千个一模一样的需求吗？有，AI 行。没有，你来。

:::
