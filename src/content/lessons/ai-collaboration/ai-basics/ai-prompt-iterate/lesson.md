# Prompt 迭代与对话

:::music-analogy
「好的演奏不是第一遍就完美——是指挥说'这里弱一点、那里慢一点'，乐团长反复练习，直到找到最好的那个版本。」
:::

:::explain{title="一、第一个 Prompt 几乎永远是错的"}
新手最常见的错误：写一个 Prompt，看到 AI 的回复不满意，就认为"AI 不行"。
这就像你找一个新同事干活，第一次交代需求没说清楚，他做的和你想的不一样。你不会直接开了他——你会补充信息、纠正理解、重新沟通。
AI 协作的核心不是"写出完美的第一个 Prompt"，而是**"写 Prompt → 看输出 → 找差距 → 修正 Prompt → 再看输出"**的循环。
一个真实案例：
> **第 1 个 Prompt：** "写一个导航栏。"
> **AI 输出：** 一个水平排列的链接列表，样式普通。
> **你的判断：** 不是我要的。我需要响应式的——手机上变成汉堡菜单。还有，当前页面要高亮。
>
> **第 2 个 Prompt：** "改进：需要响应式，移动端用汉堡菜单，当前页面链接高亮。"
> **AI 输出：** 加上了媒体查询和 active class，但汉堡菜单的 JS 逻辑写得有点啰嗦。
> **你的判断：** 功能对了，但代码太冗长。让它用 Vue 的响应式重写。
>
> **第 3 个 Prompt：** "代码冗余。用 Vue 3 Composition API 重写，用 ref 管理菜单开关状态。"
> **AI 输出：** 简洁的 Vue 3 导航组件，响应式、高亮、汉堡菜单都有了。
**三次迭代，一次比一次接近目标。** 你的价值不在第一次 Prompt（AI 不知道你想做什么），在你的第二次、第三次 Prompt（你看到了差距，知道怎么纠正）。
:::

:::explain{title="二、\"对话\"不是\"命令\""}
很多人把 AI 当成命令行：输入指令，等待输出。这是错误的心理模型。
正确模型：**把 AI 当成一个在 Slack 上和你聊天的同事。** 你们在对话，不是在发号施令。
对话意味着：
- **你可以追问：** "这里为什么要用 useEffect？用 computed 不行吗？"
- **你可以质疑：** "你说的这个方案，在数据量大时会有什么性能问题吗？"
- **你可以要求解释：** "这段正则表达式在干什么？逐部分解释一下。"
- **你可以说不：** "这个方案太复杂了，我想要更简单的实现。"
- **你可以让它改：** "把上面的代码改成用 async/await 而不是 .then()。"
每一次对话都是一次**方向修正**。AI 的输出是一场即兴演奏——你的每一次回应都在改变它的方向。你把控全局，AI 负责执行。
:::

:::explain{title="三、出错了怎么办"}
AI 一定会出错。不是"可能"出错，是"一定"。
当 AI 给你一段不能用的代码时，你有两个选择：
**选择 A：自己修。** 你看懂了问题在哪，手动改过来。这最快——如果你能看懂的话。
**选择 B：把错误喂回去。** 把报错信息贴给 AI："你上面的代码报了这个错：`TypeError: Cannot read properties of undefined`。帮我修复，并解释原因。"
选择 B 是更好的学习方式。因为：(1) 你在教 AI 知道它哪里错了；(2) AI 的解释让你理解了错误的本质；(3) 下次你看到类似的报错，就知道怎么回事了。
**关键心态：AI 出错不是坏事，是学习机会。** 每一个 bug 都是你理解系统的一次入口。如果你每次都自己修好了但不知道为什么坏，你就没有学到东西。如果你每次都让 AI 解释为什么出错，你的调试能力会以惊人的速度提升。
:::

:::recap
第一个 Prompt 几乎永远不完美——AI 协作的核心是不断迭代：写 Prompt、看输出、找差距、修正 Prompt，循环直到满意。把 AI 当成对话的同事而不是命令行，你可以追问、质疑、要求解释，每一次对话都是一次方向修正。
:::
