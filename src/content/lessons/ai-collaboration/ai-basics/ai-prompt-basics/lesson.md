# 写好 Prompt 的核心原则

:::analogy
好的 Prompt 就像好的外卖备注——"加辣、少盐、不要香菜、面硬一点"比"来碗面"的成功率高十倍。AI 也一样：你说得越清楚，它越不容易猜错。

:::

:::prerequisite
你已经用过 AI 工具，有过"我说 A 它给我 B"的体验。如果你还没有这种体验，现在去试试："帮我写个按钮组件"——你看 AI 给你的按钮和你想要的差多远。

:::

:::explain{title="一、你的问题"}
你给 AI 写了一段需求，它生成的代码跟你想要的差了十万八千里。你觉得 AI 不好用，但问题可能不在 AI——在你的需求描述。AI 就像一个很能干但对你项目一无所知的新同事：你不说清楚，它一定猜错。
:::

:::explain{title="二、解决方案：四个原则，让你的 Prompt 从猜谜变成精准投递"}
### 原则 1：具体，再具体

**坏的 Prompt：**
```
帮我写个按钮。
```

AI 被迫猜——什么颜色、什么大小、什么文字、什么功能。猜错的概率极高。它可能给你一个 Bootstrap 风格的蓝色按钮，而你要的是一个圆角 8px 的浅蓝 icon 按钮。

**好的 Prompt：**
```
写一个 Vue 3 <template> 中的按钮组件：
- 圆角 8px
- 默认背景色 #E8F0FE，hover 时变为 #D2E3FC
- 文字颜色 #1A73E8
- 通过 props 控制内容（emoji + 文字）
- 两个尺寸：small（padding: 6px 12px）和 medium（padding: 10px 20px）
- 通过 size prop 切换
```

**结果对比：** 坏 Prompt 的代码你可能需要改 80%。好 Prompt 的代码你可能只需要改 20%。多花 30 秒写清楚，省掉 5 分钟改代码。**你的时间花在说清楚需求上，比花在改 AI 的烂代码上划算得多。**

### 原则 2：先给上下文，再说需求

AI 不知道你的项目用 Vue 还是 React、用 Tailwind 还是原生 CSS、有没有命名规范。你不知道的默认值，AI 也不知道——它只能猜。

**没有上下文的 Prompt：**
```
写一个数据获取的 hook。
```

**有上下文的 Prompt：**
```
我用 Vue 3 Composition API，项目命名规范是 camelCase，函数以 use 开头。
写一个 useFetch 组合式函数：
- 接收 URL 参数，返回 { data, loading, error } 三个 ref
- 包含请求取消逻辑（组件卸载时自动取消未完成的请求）
- TypeScript 类型：data 泛型
```

:::

:::hint{title="上下文对你是免费信息"}
你本来就清楚你的技术栈和规范，把它写进 Prompt 只需要多花 10 秒钟。但这对 AI 来说是决定性的——它不用在 Vue/React/Tailwind 之间随机选一个了。
:::


### 原则 3：拆成小步骤，不要一口气

**坏的 Prompt：**
```
帮我做一个完整的 Todo 应用：添加、删除、标记完成、过滤、搜索、localStorage 持久化、响应式设计、暗色模式。
```

结果：大部分功能勉强能用，但每个都有小 bug，整体结构混乱，不可维护。

**好的方式——拆成多次对话：**
```
第 1 步："写一个 Todo 应用的 Vue 3 模板结构，先只实现列表展示，数据用 ref 硬编码。"
→ 你审查 → 确认结构没问题

第 2 步："在上面的基础上，加一个输入框和添加按钮，用 v-model 绑定输入值。"
→ 你审查 → 确认添加功能正常

第 3 步："给每个 todo 项加删除按钮和点击标记完成（切换样式）。"
→ 你审查 → 确认交互逻辑正确
```

**为什么拆步骤比一口气好？**

1. 每步输出代码量小，你审查得过来。一口气 300 行你根本看不仔细。
2. 每步验证通过再做下一步，bug 不会累积。5 个小 bug 各修 1 分钟，比 1 个由 5 个小 bug 纠缠出的大 bug 好修一百倍。
3. AI 的上下文是有限的——后面的生成会受前面的影响。拆开后每个对话独立，不会"前面的错误污染后面的代码"。

### 原则 4：给 1-2 个示例，胜过一千字描述

你想让 AI 生成特定风格的代码，但用语言描述"风格"很抽象。最简单的方式：直接给它看一个例子。

```
我需要为以下 API 路径生成 TypeScript 类型定义。格式参考这个示例：

示例：
/api/users/:id → GET /api/users/{userId}

请按照相同的模式处理下面的路径：
- /api/orders/:orderId
- /api/orders/:orderId/items/:itemId
- /api/products/:productId/reviews
```

AI 看了示例，立刻理解了"把 :param 转成 {paramName} 的驼峰形式"这个规则，然后准确地应用到剩下的三个路径。一个例子胜过你写一大段规则描述。

**四个原则的综合应用**

你需要一个商品卡片组件。对比两种写法：

**只用原则 1（半吊子）：**
```
写一个商品卡片，有图片、名称、价格。
```
AI 生成：一个 div 套 div 的结构，图片没有 alt，价格没有格式化。

**四个原则全用：**
```
【上下文】Vue 3 + 原生 CSS，项目使用 BEM 命名规范，ES module。

【示例】之前项目的卡片结构参考：
<article class="card">
  <img class="card__image" :src="product.image" :alt="product.name" />
  <div class="card__body">
    <h3 class="card__title">{{ product.name }}</h3>
    <span class="card__price">{{ formatPrice(product.price) }}</span>
  </div>
</article>

【需求】写一个 ProductCard 组件：
1. Props: product 对象 { id, name, price, image, originalPrice }
2. 显示原价（划线）、现价（红色加粗）、折扣标签（'立减XX元'）
3. 图片加载失败时显示占位图（灰色背景 + 相机 emoji）
4. CSS 变量：--card-radius: 12px, --card-shadow: 0 2px 8px rgba(0,0,0,0.1)

【步骤】先只生成模板和 props 定义。样式我会在下一轮对话告诉你。
```

用一个例子、具体参数、明确的范围，AI 的输出质量能有质的飞跃。
:::example{title="常见错误——看看你踩过几个坑？"}
**错误 1：Prompt 太短，期望太高。**
> "写个登录页" → 5 秒后抱怨 AI 生成的登录页没有记住密码功能、没有手机号登录、没有验证码。
你说 4 个字，期望 AI 猜到你心里 100 个需求。这不现实。

**错误 2：把四个原则当成一次性的固定模板。**
> 每次都用同样的格式："【上下文】Vue 3...【需求】写一个..."
四个原则是思维框架，不是填空题。关键是养成"说清楚"的习惯，而不是背一个模板。

**错误 3：只给技术需求，不给设计需求。**
> "写一个表格组件" → AI 生成了一个功能正确但丑到爆的表格。
AI 不知道你觉得什么好看。颜色、间距、字体大小——这些也要说，哪怕就一句话："整体风格简洁，用浅灰边框，hover 行高亮。"
:::

:::explain{title="四、实际工作中你会怎么用？"}
- **写周报：** Leader 让你"把本周的工作整理一下"。你用 AI："我是一名前端开发。将以下工作记录整理成三段式周报：本周完成、遇到的问题、下周计划。语言简洁、用短句。工作记录：[粘贴你的记录]。"
- **写正则表达式：** "我需要一个正则以验证中国大陆手机号。匹配规则：1 开头，第二位 3-9，共 11 位数字。给我正则表达式和 5 个测试用例。"
- **生成重复代码：** 项目里需要 8 个类似的 API 请求函数。你把第一个写好的作为示例，让 AI 生成剩余 7 个——格式一致，只改路径和参数名。

:::

:::task{title="练习四个原则"}
::::step{id="1"}
打开你的 AI 工具，用"写一个导航栏"作为第一个 Prompt，看 AI 生成什么。截图保存。
::::
::::step{id="2"}
用四个原则重写这个 Prompt：说明技术栈（你在用什么框架）、给上下文（项目风格）、拆步骤（先只做桌面端）、给示例（你喜欢的导航栏风格）。把新 Prompt 发给 AI，对比两次输出。
::::
::::step{id="3"}
找一个你实际需要写的组件（可以是工作中、作业中、或自己的项目中），用四个原则写 Prompt，让 AI 生成。然后审查输出，标注出：哪些地方 AI 理解对了、哪些地方还需要你再改。
::::
::::step{id="4"}
总结：对比步骤 1 和步骤 2 的结果，你多花的那些字数（上下文、示例、具体参数）帮你省掉了多少改代码的时间？
::::
:::


:::recap
写好 Prompt 的四个原则：具体（不要"写个按钮"，要"圆角 8px、背景 #E8F0FE"）、给上下文（"我用 Vue 3，命名规范 camelCase"）、拆步骤（一口气是灾难，逐步验证是正道）、给示例（一个例子胜过一千字描述）。多花 30 秒写清楚 Prompt，省掉 5 分钟改代码。这个投资回报率你自己算。

:::
