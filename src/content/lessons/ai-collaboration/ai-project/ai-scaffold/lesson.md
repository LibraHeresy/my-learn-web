# 用 AI 搭项目脚手架

:::analogy
AI 搭脚手架就像搬进精装公寓——墙刷好了、水电通了、家具位置摆好了。你不用从砌砖开始，但搬进去后哪里要走电线、哪里要钉钉子——都是你的判断。
:::

:::prerequisite
你已经用 `npm create vite@latest` 手动创建过 Vue 3 项目，知道默认的项目目录结构长什么样。
:::

## 一、你的问题

你手动创建过 Vue 项目——`npm create vite@latest`、选模板、`npm install`、清掉默认的 HelloWorld 组件、手动建 components 和 composables 文件夹。这些步骤不难，但每次开始新项目都要重复一遍，大概 20-30 分钟。而且一旦你开始用 AI，AI 可能会建议你装不存在的包、用过时的 API、或者用 Vue 2 的语法写 Vue 3 的项目。你需要的是"5 分钟搭好干净的项目骨架 + AI 的建议我能辨别真假"。

## 二、解决方案：脚手架生成 + 幻觉防御

### 第一步：让 AI 生成项目结构

```
我在本机 Windows/Mac 上创建项目。用 Vite + Vue 3 初始化一个新项目，项目名为 [你的项目名]。
请一步步告诉我：
1. 创建项目的命令（我已有 Node.js 18+）
2. 创建后需要删除哪些默认文件（HelloWorld.vue、默认样式等）
3. 需要创建的文件夹结构（components、composables、assets、styles）
4. 初始安装哪些开发依赖（不需要 vue-router、pinia 等我没要求的）
5. 创建以下基础文件：
   - src/styles/reset.css（基础 CSS Reset）
   - src/styles/variables.css（CSS 变量：颜色、间距、字体）
   - src/App.vue（清理后的版本，只有基本结构）
   - src/main.js（保持默认，只改 import 路径）
```

AI 会给出详细步骤。你做一步、验证一步、再做下一步。不要一次性敲完所有命令——万一第一步就报错了，后面的都是浪费时间。

### 第二步：识别 AI 的幻觉

AI 在脚手架阶段有三个经典幻觉，你必须能识别：

**幻觉 1：不存在的 npm 包。**
AI 可能让你装 `vue-tomato-timer`、`vue-use-debounce` 这种听起来合理但实际不存在的包。**应对：** AI 让你 `npm install` 任何包之前，去 npmjs.com 搜一下——这个包存在吗？最后更新时间是什么时候？周下载量是多少？如果一个包周下载量只有 50，不要用。

**幻觉 2：过时的 API 或框架版本。**
AI 可能写 Vue 2 的 `new Vue({ ... })` 而不是 Vue 3 的 `createApp(...)`。可能用 `@vue/cli` 而不是 Vite。**应对：** 识别不了就运行——如果 Vite 报错，说明代码不是 Vue 3 的写法。把报错贴回去："这段代码在 Vue 3 + Vite 环境下报错，请改成 Vue 3 Composition API 的写法。"

**幻觉 3：过度的目录结构。**
AI 可能建议你创建 `src/components/common/`、`src/components/layout/`、`src/components/features/`、`src/components/pages/`——10 个子目录但你的项目只有 5 个组件。**应对：** 目录结构应该跟随组件数量增长而增长，而不是一开始就搞一大堆空文件夹。项目初期 3 个文件夹足够（components、composables、styles）。

:::hint{title="幻觉不是 AI 的 bug，是你的审查项目"}
每次 AI 让你装包、写代码、建目录时，想象有一个黄色警告灯在闪。你在用它之前要学会克制，不然就会被它带偏。你学过的前八章知识，此刻就是你的防骗盾牌。
:::

### 第三步：验证脚手架的可运行性

脚手架搭好后，不要立刻开始写业务代码。先做三件事，确认基础是稳固的：

1. `npm run dev` → 浏览器打开 → 能看到页面吗？
2. 打开浏览器控制台（F12 → Console）→ 有没有红色报错？
3. 改一下 App.vue 里的文字 → 浏览器自动刷新 → 你改的文字出现了吗？

三件事都通过，脚手架才算搭好了。如果有任何一步失败，把错误信息贴给 AI，修好再继续。**不要在坏的脚手架上面盖房子。**

:::example{title="完整的脚手架初始化对话"}
```
你：我需要在本地创建一个 Vue 3 + Vite 项目，项目名为 my-pomodoro。
操作系统 Windows 11，Node.js 18+。
只使用 Vue 3 + 原生 CSS，不需要 vue-router、pinia、TypeScript。
请一步步告诉我要执行什么命令。

AI：第一步，打开终端，进入你的工作目录，执行：
npm create vite@latest my-pomodoro -- --template vue
cd my-pomodoro
npm install

第二步，删除默认文件：
- 删除 src/components/HelloWorld.vue
- 删除 src/assets/vue.svg
- 清空 src/style.css 的内容（或删除）

第三步，创建文件夹：
- src/components/
- src/composables/
- src/styles/

...等等。

你（执行完第一步后）：npm install 之后控制台警告：
"3 high severity vulnerabilities"
这是什么意思？需要处理吗？

AI：通常是 devDependencies 中的问题，不影响生产代码。运行 npm audit 可以看详情。
对于学习项目，这种警告可以暂时忽略。如果要修复，运行 npm audit fix。
```

这种对话节奏——你来我往，遇到问题立刻问——比"一次性收到一大堆指令然后默默执行"安全得多。
:::

## 三、常见错误

**错误 1：一口气执行所有步骤，中间不验证。**
> AI 给了 5 步 → 你一次性全部执行 → 第 3 步报错了但你错过了，第 4、5 步全部无效 → 你找不到哪里出了问题。
每一步执行完，确认结果正确，再做下一步。脚手架搭建不是赛车——是盖地基，慢比快重要。

**错误 2：AI 说装什么包就装什么，不查一下 npm。**
> `npm install vue-awesome-component` → 装完发现这个包 3 年没更新，文档是 Vue 2 的。
先查 npmjs.com，再决定装不装。这个习惯会帮你避免 50% 的第三方依赖坑。

**错误 3：脚手架搭完直接开始写代码，不验证环境。**
> 搭完了 → 开始写第一个组件 → 写了一小时 → `npm run dev` → 报错，但错误太多分不清是脚手架问题还是你代码的问题。
搭完脚手架立刻验证（npm run dev 能跑、控制台没报错、热更新正常）。验证通过后，之后的所有错误都只可能是你自己的代码引起的——排查范围从"整个项目"缩小到"你刚写的那段代码"。

## 四、实际工作中的场景

- **新项目启动：** 团队决定开一个新项目。你把技术选型（Vue 3 + Vite + Pinia + ESLint + Prettier）告诉 AI，让它列出初始化步骤和配置文件内容。你实际操作，AI 帮你处理各种初始化报错（Node 版本不匹配、依赖冲突、配置语法过时）。
- **统一团队项目模板：** 团队 5 个人，每个人创建项目时文件夹结构都不一样。你让 AI 根据团队规范生成一个脚手架脚本（bash 或 Node 脚本），一键创建标准化的项目骨架。大家跑同一条命令，创建出来的项目结构完全一致。
- **从老项目迁移：** 你们要从 Vue CLI（Webpack）迁移到 Vite。你把 `vue.config.js` 的内容贴给 AI："帮我把 Webpack 的配置翻译成 Vite 的 `vite.config.js`，保持功能等价。"AI 出初版 → 你测试 → 微调。
