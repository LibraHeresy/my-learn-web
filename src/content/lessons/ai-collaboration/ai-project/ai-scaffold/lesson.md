# 用 AI 搭项目脚手架

:::music-analogy
「乐团已经就座，乐器已经调好——现在只需要你的第一个手势。」
:::

:::explain{title="一、从零到有，五分钟"}
在第七章你学会了用 Vite 创建项目——`npm create vite@latest`，选择模板，安装依赖，配置。每一步都手动操作。
现在试试让 AI 指导你：
> 我需要在本地创建一个 Vue 3 + Vite 项目。请一步步告诉我：
> 1. 用什么命令创建项目
> 2. 初始目录结构是什么
> 3. 需要安装哪些额外依赖
> 4. 如何清理默认的模板代码
> 5. 创建项目的基本文件夹结构（components、composables、assets 等）
AI 会给你详细的步骤。但你需要注意：**AI 的建议不一定适用于你当前的 Node.js 版本、操作系统、网络环境。** 如果某个命令报错了，把错误喂回去，让 AI 帮你调整。
脚手架搭好之后，你有了一个干净的项目骨架。接下来，让 AI 帮你创建第一个组件。
:::

:::explain{title="二、警惕 AI 的幻觉"}
AI 在"搭项目"这件事上有一个特有的问题：**幻觉出不存在的库或过时的 API。**
它可能告诉你装一个叫 `vue-tomato-timer` 的包——这个包并不存在，但名字"听起来合理"，于是 AI 编了一个。
它可能用 Vue 2 的语法写 Vue 3 的项目。因为它的训练数据里 Vue 2 的内容比 Vue 3 多。
它可能建议你用 `@vue/cli` 而不是 Vite。因为 `@vue/cli` 以前是主流，它的训练数据里还有大量相关内容。
**应对策略：**
1. AI 让你 `npm install` 任何包之前，先去 npmjs.com 查一下这个包是否存在、最近更新是什么时候
2. AI 写的代码在你项目里报错时，把报错贴回去——"你上面的代码在 Vue 3 里不 work，请用 Vue 3 的写法重写"
3. 遇到不确定的 API 时，让 AI 写出参考来源——"这个 API 在 Vue 3 官方文档的哪个部分？"
**脚手架阶段的核心技能不是"会用 AI"，是"能识别 AI 的幻觉"。** 这个能力只能靠你自己的知识积累——你学过的前八章此时在保护你。
:::
