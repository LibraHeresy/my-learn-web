# 用 AI 写样式和布局

:::analogy
AI 能生成一堆样式代码，但只有你的眼睛才知道这个间距太多、那个颜色太跳。审美和判断力——这是 AI 替代不了的东西。
:::

:::explain{title="一、AI 写 CSS 的特点"}
AI 在 CSS 上有两个极端表现：
**好的一面：** 属性值记得很全。你想要渐变、阴影、动画——AI 能准确地写出 `linear-gradient(135deg, #667eea 0%, #764ba2 100%)`。这些标准写法在它的训练数据里有几百万次重复。
**坏的一面：** 没有设计品味。AI 把颜色调成什么取决于"统计上最常见的蓝色"，而不是"这个蓝色在这个页面上好不好看"。AI 不知道"留白"的美感，不知道`line-height: 1.6`比`1.2`在长文章里的阅读体验好在哪里。
**核心差异：** CSS 有两部分——"怎么写"（语法）和"该写成什么样"（设计判断）。AI 擅长前者，完全不会后者。后者是你的事。
:::

:::explain{title="二、审查 AI 生成的 CSS"}
当你拿到一段 AI 生成的 CSS 时，检查这四个问题：
**1. 冗余。** AI 倾向于重复声明。同一个 `margin: 0; padding: 0;` 在 8 个选择器里出现。你应该抽成公共样式或使用 CSS 变量。
**2. 响应式缺失。** AI 默认生成桌面端样式。如果你没说"移动端适配"，它不会自动加媒体查询。而真实项目中移动端流量往往过半。
**3. 硬编码数值。** `width: 320px; height: 240px;`——这些魔法数字在你的页面上可能正好，但在另一个地方是灾难。审查时问自己：这个值应该用相对单位吗（`%`、`rem`、`vw`）？
**4. 多余的 !important。** AI 在"解决优先级冲突"时经常滥用 `!important`，而不是去理清选择器优先级。任何一个 `!important` 都是将来的定时炸弹。
**审查 CSS 比审查 HTML 更需要你的品味和判断力。** 因为 HTML 有"对错"（语义化），CSS 更多是"好坏"（优雅、可维护、响应式）。
:::

:::explain{title="三、练习"}
用 AI 完成以下三个 CSS 任务，每个都仔细审查并改进：
**任务 1：** 给 AI 一张页面截图或一段描述："设计一个浅色模式的卡片组件——白色背景、圆角 12px、轻微阴影、hover 时上浮 4px 并加深阴影。"
→ AI 生成 CSS 后，你检查：阴影参数自然吗？过渡时间舒服吗？有没有用 CSS 变量？
**任务 2：** "用 Flexbox 实现一个三列网格，每列之间的间距为 24px，响应式：平板两列、手机一列。"
→ 审查：断点设置合理吗？间距的实现方式是用 gap 还是 margin？
**任务 3：** 把你自己之前写的一段 CSS 贴给 AI："这段 CSS 有没有可以优化的地方？有没有冗余？"
→ 对比：AI 的建议和你的实际感受一致吗？哪些建议你认同、哪些不认同？
:::

:::recap
AI 写 CSS 属性值记得很全，但完全没有设计品味。审查 AI 生成的 CSS 时要检查四件事：冗余代码、响应式缺失、硬编码数值、多余的 !important。CSS 语法对不对由规范决定，但好不好看由你来判断。
:::
