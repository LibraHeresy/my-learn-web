# 用 AI 写逻辑

::music-analogy
「AI 能即兴一段 solo，但只有你才知道这段 solo 该在哪个和弦进行里出现。」
::

::explain{title="一、AI 写 JS 的优势与陷阱"}
JavaScript 逻辑是最容易出"看起来对、实际有 bug"的地方。
**AI 擅长：** 标准算法的实现（排序、去重、日期格式化）、正则表达式、API 请求模板、标准的设计模式实现。
**AI 容易出错的地方：**
- **异步时序。** AI 生成的 async/await 代码在正常网络下运行良好，但网络慢、请求失败、竞态条件——这些边界情况经常被忽略。
- **类型混乱。** `"5" + 3` 和 `"5" - 3` 的结果不一样——AI 生成的 JS 可能在某些路径上产生意外的类型转换。
- **状态副作用。** AI 可能直接修改传入的参数（mutate），而不是返回一个新对象。这就造成了隐蔽的 bug。
- **缺少错误处理。** AI 默认假设一切顺利。`try/catch`、API 错误处理、空值检查——经常被省略。
**核心原则：AI 生成的 JS 代码你必须能看懂。** 不是"大概看懂"，是"每一行都知道它在干什么"。如果有一段你看不懂的 AI 代码跑了你的生产环境，你就是在闭着眼睛开飞机。
::

::explain{title="二、审查 JS 的四步法"}
拿到 AI 生成的 JS 代码后，按这个顺序检查：
**第 1 步：读逻辑。** 代码做的是你让它做的事吗？逐行读。如果有一行你说不出它为什么在那里——删掉，或者问 AI 它是干嘛的。
**第 2 步：找边界。** 输入是空数组怎么办？参数是 `null` 怎么办？网络请求失败了怎么办？用户狂点按钮怎么办？**AI 生成的代码在正常路径上正确率高，但在异常路径上正确率急剧下降。**
**第 3 步：看副作用。** 函数有没有修改它不该修改的东西？有没有依赖于全局变量？有没有隐含的时序假设？
**第 4 步：跑测试。** 不是写正式的单测——就是在浏览器控制台里手动调几次，给不同的输入，看输出是不是你预期的。**这是最有效的质量保证。**
::

::explain{title="三、练习"}
让 AI 完成以下三个 JS 任务，每个都用四步法审查：
**任务 1：** "写一个表单验证函数：邮箱不能为空且必须包含@，密码至少 8 位且包含数字和字母，用户名 2-20 个字符。返回一个包含所有错误的数组。"
→ 审查：空值呢？特殊字符呢？错误信息清晰吗？
**任务 2：** "写一个 `debounce` 函数，接收一个函数和延迟时间（毫秒），返回防抖后的新函数。"
→ 审查：this 绑定正确吗？参数传递完整吗？第一次调用是否立即执行（leading edge）？
**任务 3：** "写一个 `fetchWithRetry` 函数：请求一个 URL，失败时自动重试，最多 3 次，每次间隔递增。"
→ 审查：哪些 HTTP 状态码才应该重试（404 不应该重试，503 应该）？超时处理了吗？
::
