# 走出浏览器：从练习页到本地项目

:::analogy
从在网页上写练习到在本地建项目，就像从在草稿纸上练字到用笔记本电脑写文章——同一门技能，只是换个更专业的环境。
:::

:::explain{title="这一章你会学什么"}
这一章是“登台篇”的入口。你会开始接触：
- 本地项目文件夹
- VS Code
- 终端命令
- Node.js 与 npm
- Vite、Git、部署

学完这一章，你不再只是“在练习页里改代码”，而是能在自己的电脑上创建、运行、管理和发布一个前端项目。
:::

:::explain{title="学前你应该已经会什么"}
进入这一章之前，你最好已经具备这些基础：
- 会写基础的 HTML、CSS、JavaScript
- 知道结构、样式、交互分别对应什么
- 至少做过几次浏览器内的小练习

如果你还不熟悉这些，不是不能继续，而是你会在工程化环境里同时面对“新工具 + 旧知识不稳”两种压力。
:::

:::explain{title="环境地图：你接下来会看到什么"}
到目前为止，你的代码大多运行在浏览器练习环境里。接下来会多出 4 个新角色：

- **文件夹**：项目真正住的地方
- **VS Code**：你主要写代码的编辑器
- **终端**：输入命令、启动工具、看报错的地方
- **Node.js / npm**：运行前端工具链的基础环境

工程语境里，你以后会经常听到这些标准说法：  
**本地开发环境**、**项目根目录**、**开发服务器**、**依赖安装**。  
这些听起来专业，但本质上都是在回答两个问题：  
“代码放哪？”“怎么让它跑起来？”
:::

:::explain{title="为什么这一步会让很多人突然紧张"}
很多转行者不是卡在知识点本身，而是卡在**环境切换**：
- 以前只看页面，现在要看文件夹
- 以前只点按钮，现在要敲命令
- 以前改完马上生效，现在还要先启动项目

如果你感到不适，这很正常。你不是突然变笨了，而是在适应新的工作台。  
就像第一次从在家做饭转到餐厅后厨：不是不会做菜，而是要多处理一些新的流程和分工。
:::

:::task{title="这一章开始前，请先完成这 3 件事"}
1. 接受一个事实：你不是在学习另一门语言，而是在学习“如何在本地组织和运行项目”
2. 把“看不懂终端”理解成暂时的陌生感，而不是能力不足
3. 记住后面的所有工具课，目标都只有一个：让你能独立把项目跑起来、改起来、发出去
:::

:::hint{title="卡住时先这样想"}
先别问“我是不是不适合工程化”。  
先问：
- 我现在卡在文件结构，还是卡在命令本身？
- 我是不知道在哪运行，还是不知道报错在说什么？
- 我是知识不会，还是环境还不熟？

把卡点分清楚，焦虑会立刻下降一半。
:::

:::recap
工程化不是另一套神秘知识，而是把你已经会的前端基础放进更专业的工作环境里。接下来这章要帮你完成的，不是“突然变高手”，而是从浏览器练习顺利过渡到本地项目。
:::
