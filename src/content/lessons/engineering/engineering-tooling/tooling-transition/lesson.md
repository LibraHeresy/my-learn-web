# 走出浏览器：从练习页到本地项目

:::analogy
你一直在驾校的练习场里开车——有护栏、有教练、路况单一。现在你要把车开上真实公路。车还是那辆车（HTML/CSS/JS），但环境完全不同了：你要自己看路牌（文件结构）、自己加油（安装依赖）、自己找路（终端命令）。
:::

:::explain{title="问题：浏览器沙箱能干什么？不能干什么？"}
到目前为止，你的所有代码都在浏览器内的练习环境里运行。这种环境故意把事情简化了：

**你能做的事：**
- 写 HTML、CSS、JavaScript
- 改代码后刷新页面，立刻看到效果
- 所有文件自动保存在网页后台

**你做不了的事（而这恰好是真实开发每天都要做的）：**
- 安装第三方库（没有 `npm install`）
- 使用构建工具压缩代码（没有 Vite）
- 版本管理，改坏了回不去的恐惧（没有 Git）
- 把代码发布到网上让别人访问（没有部署）
- 多个文件之间用 `import` 互相引用（沙箱通常是单文件）

浏览器沙箱就像一个带围栏的儿童泳池——安全，但你游不了真正的泳。现在你要进入标准泳池了。
:::

:::explain{title="解决方案：本地开发环境的四个新角色"}
真实的前端项目不是跑在浏览器沙箱里，而是跑在**你自己的电脑**上。你的电脑上会多出四个新成员：

| 成员 | 类比 | 解决什么问题 |
|------|------|-------------|
| **项目文件夹** | 你的工作台 | 代码放哪里？不再是网页上的一个文本框 |
| **VS Code** | 你的主力工具 | 怎么写代码？不再是用网页里的简易编辑器 |
| **终端（命令行）** | 你的语音遥控器 | 怎么启动工具？不再是点击网页上的"运行"按钮 |
| **Node.js / npm** | 你的工具箱电源 | 构建、打包、安装库——这些工具靠什么运行？ |

这四个角色配合在一起，就是"本地开发环境"。后面的每一课会逐一展开一个角色。
:::

:::example{title="看对比：沙箱项目 vs 本地项目"}
一个音乐搜索页面，在两种环境下的区别：

沙箱环境（你现在用的）：
```
// 所有代码挤在一个在线编辑器的文本框里
// 没有文件夹概念
// 没有 import，CDN 引入 Vue：
// <script src="https://unpkg.com/vue@3"></script>
// 点击网页上的"运行"按钮看效果
// 关掉网页，代码存在服务器上（不是你控制的）
```

本地项目（你将要创建的文件结构）：
```
music-collection/                ← 项目文件夹，在你电脑上
├── index.html                   ← 入口页面
├── package.json                 ← 记录项目名、依赖、脚本
├── vite.config.js               ← Vite 构建配置
├── src/
│   ├── main.js                  ← 应用启动入口
│   ├── App.vue                  ← 根组件
│   ├── components/              ← 放可复用的组件
│   │   └── MusicCard.vue
│   └── utils/                   ← 放工具函数
│       └── formatDate.js
└── node_modules/                ← 第三方依赖（自动生成）
```

区别的核心：**你掌控一切**——文件在哪、用哪个版本、怎么构建、部署到哪里，全部由你决定。
:::

:::hint{title="常见误区：新手最易犯的3个心理错误"}
1. **"我就是想写个网页，为什么要学这么多工具？"**
   用浏览器沙箱写一个页面，和用工程化环境开发一个真实项目，就像用美图秀秀修一张自拍 vs 用 Photoshop 出一套商业海报。工具复杂度上升，是因为你要做的事情复杂度上升了。

2. **"我不会命令行，是不是不适合做前端？"**
   你不需要"会命令行"，你只需要记住 6 个命令（pwd、ls、cd、mkdir、echo、code .）。刚开始每次都要查，一个月后肌肉记忆。没有人天生会敲命令。

3. **"这么多新东西同时来，我是不是太笨了？"**
   不是你笨，是环境切换的认知负荷大。以前你只需要关注"代码写得对不对"，现在还要关注"文件在哪、工具装没装、命令敲没敲对"。这是暂时的——就像第一次用智能手机，三天后就不觉得复杂了。
:::

:::explain{title="现实工作连接：为什么没人用浏览器沙箱做真实项目"}
- 在公司，你的代码存在 GitHub 上，同事 `git clone` 就能拿到
- 产品上线前，CI/CD 系统会自动 `npm run build`，生成压缩后的生产文件
- 如果你的电脑坏了，换个电脑 `git clone` + `npm install` + `npm run dev`，5 分钟恢复工作状态
- 面试官看你的 GitHub，不会看你的沙箱截图

浏览器沙箱是一个**学习工具**，不是一个**工作工具**。这一章的目的就是帮你完成这个切换。
:::

:::task{title="建立你的第一个本地项目文件夹"}
::::step{purpose="在电脑上创建项目文件夹，并用 VS Code 打开——这是本地开发的起点。从此你的代码不再活在网页里，而是你电脑上的真实文件。" expected="VS Code 左侧文件资源管理器中能看到 my-music-app 文件夹，内部有一个 readme.md 文件。"}
在桌面上创建项目文件夹

1. 打开文件资源管理器（Windows：`Win + E` | Mac：Finder）
2. 在桌面或文档目录中，右键 → 新建文件夹
3. 文件夹命名为 `my-music-app`（全小写，用连字符连接，这是项目命名的约定）

在 VS Code 中打开这个文件夹：
4. 启动 VS Code
5. 点击 `文件` → `打开文件夹`（或直接把文件夹拖到 VS Code 图标上）
6. 选择刚才创建的 `my-music-app` 文件夹
7. 在左侧文件资源管理器中右键 → 新建文件 → 命名为 `readme.md`
8. 在 `readme.md` 中输入：`# 我的第一个本地项目`
9. 按 `Ctrl+S`（Mac: `Cmd+S`）保存
::::

::::step{purpose="打开 VS Code 内置终端——终端是你和电脑之间的文字对话窗口。以后安装依赖、启动项目、运行构建都在这里进行。" expected="终端面板在 VS Code 底部弹出，显示当前路径为 my-music-app 文件夹。"}
打开内置终端，确认你"站在"项目文件夹里

1. 在 VS Code 中按 `Ctrl+``（Mac: `Cmd+``）——注意是反引号键，在 Esc 键下方
2. 终端面板会在底部弹出
3. 输入 `pwd` 并回车——这会显示你"当前站在哪个文件夹"
4. 确认输出以 `my-music-app` 结尾（如 `C:\Users\你的名字\Desktop\my-music-app`）
5. 输入 `ls`（Mac）或 `dir`（Windows CMD）——列出当前文件夹里的文件
6. 应该能看到刚才创建的 `readme.md`
::::

::::step{purpose="在终端里创建文件和文件夹——感受一下'不用鼠标也能操作电脑'。这个 src 文件夹后续会放你的所有源代码。" expected="终端 ls 输出中能看到 src 文件夹和 index.html 文件。"}
用终端创建 src 文件夹和 index.html

在 VS Code 终端中输入（一行一行来，每行回车）：
```bash
mkdir src
```
这会创建一个名为 `src` 的文件夹（src = source，源代码的缩写，约定俗成）。

```bash
cd src
```
进入 src 文件夹。

```bash
echo "" > index.html
```
（Mac/Linux）创建一个空的 index.html 文件。如果是 Windows CMD，用 `type nul > index.html`。

```bash
cd ..
```
回到上级目录（my-music-app）。

```bash
ls
```
确认能看到 `src` 文件夹。现在用 VS Code 左侧文件树展开 `src`，确认里面有 `index.html`。
::::
:::

:::recap
本地开发环境 = 项目文件夹 + VS Code + 终端 + Node.js。浏览器沙箱是学习工具，本地环境是工作工具。你不需要一次性精通所有工具，接下来的每一课会逐一展开一个角色。现在的你已经迈出了第一步：项目文件夹创建好了，VS Code 打开了，终端也用过一次了。
:::
